# 接收链路下游闭合：sink 语义、命令分派与队列字段初始化

前序分析见[五态帧解析状态机与 0x08016fdc 跳转表归属](state-machine-switch-closure-20261109.md)、[非USB字面量偏移字段图](literal-field-access-20261109.md)与[上报对象构造链](report-object-layout-20261109.md)。五态状态机解到「状态 4 比对 16 位尾值」为止，其后被调用的 sink 函数、比对成功后的命令分派、队列对象的字段初始化与两个残余覆盖空洞都未展开。本章把这四处接到可执行语义上，并重扫空洞与 `0x10f0` 大块。

全部结论来自冻结 BBIN 的只读字节与既有导出；没有新增 Ghidra 调用，没有重新反汇编，没有执行固件，没有联网或访问设备账号。

后续分析见[冻结镜像全量反汇编与导出语料一致性核查](disasm-full-image-20261109.md)：本条遗留的 `0x10f0` 字段窗口与 `027c..02a0` 空洞在冻结镜像的指令流中零命中，说明这两段偏移不以字面位移出现。

## 主要结论

| 项 | 结果 |
| --- | --- |
| sink `0x0800a578` | 74 字节 / 35 条；**单寄存器推送**，不是内存拷贝 |
| 三种模式 | 模式 1 字节流、模式 2 半字流、模式 3 字流；目标地址固定，源指针递增 |
| 参数单位 | 模式 1、2 收**字节数**，模式 3 收**字数** |
| 忙标志 | `ctx+0x1d` 进入写 2、退出写 1；`*ctx+0x08` 置 bit0 |
| 状态 4 之后 | 按 `0x2000230c` 的 bit7 分两路，汇合到同一张五项表 |
| 第二张跳转表 | `0x08017132` 起 5 个字节 `030c141418`，增量 3/12/20/20/24 |
| 表基址规则 | 等于 `bl` 地址加 4（返回地址），不是表前一条指令 |
| 队列对象 | `0x2000240c`，字段在 `+0x8084..+0x80b0`，即 `0x2000a490..0x2000a4bc` |
| 初始化写者 | `0x0801d888` 一处，11 次写入；容量 256 字节，帧头上限 4 |
| 空洞复扫 | `027c..02a0` 获得 12 个基址组见证；无见证字节 43 → **7** |

模型 **113 条断言 0 失败**，独立字节核验 **81 项 0 失败**。见[sink 语义](../analysis-tools/system-deepening/receive-path-field-closure/SINK_SEMANTICS.json)、[下游分派](../analysis-tools/system-deepening/receive-path-field-closure/DOWNSTREAM_DISPATCH.json)、[队列字段](../analysis-tools/system-deepening/receive-path-field-closure/QUEUE_FIELDS.json)、[空洞复扫](../analysis-tools/system-deepening/receive-path-field-closure/HOLE_RESCAN.json)、[0x10f0 块](../analysis-tools/system-deepening/receive-path-field-closure/BLOCK_10F0.json)、[中文结论](../analysis-tools/system-deepening/receive-path-field-closure/FINDINGS_ZH.txt)。

## sink 0x0800a578：三种模式共用固定目标地址

函数体 `[[0800a578, 0800a5c1]]`，74 字节、35 条指令，签名等价于 `u32 sink(ctx, void *src, u32 count)`。入口处置 `ctx+0x1d = 2`，出口处置 1，这是忙标志；目标对象取自 `*ctx`，其 `+0x08` 处置 bit0，本函数不负责清除。

模式字段是 `ctx+0x20`（`ctx[8]`），按 2、3、1 的顺序比较，其余值返回 0。

三种模式最关键的共同点是：**目标地址始终不变，源指针递增**。

| 模式 | 处理函数 | 体量 | count 单位 | 组装方式 | 尾部 |
| --- | --- | --- | --- | --- | --- |
| 1 | `0x0800a480` | 88B / 44 条 | 字节 | `b0<<24 \| b1<<16 \| b2<<8 \| b3`（大端） | `strb` / `strh` / `strh+strb` |
| 2 | `0x0800a4d8` | 44B / 22 条 | 字节 | `h0<<16 \| h1` | 奇数半字 `strh` |
| 3 | 内联 `0x0800a5a0..0x0800a5b0` | 6 条 | 字 | 原样搬运 | 无 |

模式 3 的循环指令序列直接说明目标不变：

```asm
0800a5a4  cmp  r1,r2
0800a5a6  bne  0800a5ac
0800a5a8  ldr  r0,[r3,#0x0]      ; 循环结束后读回
0800a5aa  b    0800a59a
0800a5ac  ldmia r1!,{r0}         ; 源指针递增
0800a5ae  str  r0,[r3,#0x0]      ; 目标寄存器 r3 不变
0800a5b0  b    0800a5a4
```

连续多个字被推到同一个地址，符合单寄存器数据口 / FIFO 的行为，而不是缓冲区拷贝。三种模式的返回值都是最后一次读回的字，调用方取 `uxth` 后与帧尾 16 位值比较。

参数单位不一致是易错点：状态 4 传入 `[0x2000a4a8]`，即帧体字节数；只有模式为 1 或 2 时该值才是正确单位。

## 状态 4 之后：bit7 分派与第二张跳转表

状态 4 先把解析状态清 0，把当前字节或入帧尾高半部，调用 sink，再把返回值 `uxth` 后与 `[0x2000a4b0]` 比较。不等则回 `0x08016e22` 继续收字节，相等才进入命令分派。

```asm
08016ef6  movs r5,#0x7f
08016ef8  ldr  r4,[0x08016fbc]   ; 0x2000230c
08016efa  ldrb r3,[r4,#0x0]
08016efc  ands r5,r3             ; code = byte & 0x7f
08016efe  sxtb r3,r3
08016f00  cmp  r3,#0x0
08016f02  blt  08016f06          ; bit7 置位
08016f04  b    0801710c           ; bit7 清零
```

两条分支：

- **bit7 置位** → `0x08016f06`：`subs r3,r5,#2` 后 `cmp r3,#3`，只有 `code` 在 2..5 时才 `bls 0x08016f10`；其余走 `0x08017102`，打印 `Received response to 0x%02x` 后汇入主循环。
- **bit7 清零** → `0x0801710c`：先把 `0x20002304` 清 0，以 `code|0x80` 发一个应答字节，再按 `code-1` 进入同一张表。

第二张表位于 `0x08017132`，五项字节 `03 0c 14 14 18`，增量 3/12/20/20/24：

| code | 目标 | 行为 |
| --- | --- | --- |
| 1 | `0x08017138` | 栈缓冲写 `0x46`，`func_08012344(0)`，返回码 1 |
| 2 | `0x0801714a` | `func_08012344(0)` 后以长度 `0x80` 发送 `0x0807f804` |
| 3 | `0x0801715a` | 返回码 4 |
| 4 | `0x0801715a` | 与 code 3 共用目标 |
| 5 | `0x08017162` | `FUN_0800fed8`、打印 `Rebooting...`、延时、死循环 |

code 5 是唯一不返回的路径，与 `0x08025518` 处的字符串吻合。两条分支共用同一张表是这段代码的结构特征。

## 表基址等于返回地址

`0x0801712e` 处是 `bl 0x0800814c`，Thumb-2 指令占 4 字节，返回地址即 `0x08017132`。`0x0800814c` 是 `__gnu_thumb1_case_uqi`，9 条指令：

```asm
0800814c  push {r1}
0800814e  mov  r1,lr
08008150  lsrs r1,r1,#0x1
08008152  lsls r1,r1,#0x1        ; r1 = lr & ~1
08008154  ldrb r1,[r1,r0]        ; 字节表
08008156  lsls r1,r1,#0x1
08008158  add  lr,r1
0800815a  pop  {r1}
0800815c  bx   lr
```

表基址按 `lr & ~1` 计算，因此恒等于 `bl` 地址加 4。这与 `0x08016fd8` 处 `bl 0x08008484` 的情形完全同构，两条表都容易误取为表前指令的地址。

## 队列对象与十一个字段

`0x08016e22` 入口处 `ldr r6,[0x08016f94]`，该字面量的值是 `0x2000240c`。状态机内所有字段都写作 `r6` 加小偏移，因此真实地址是 `0x2000240c + 0x8084..0x80b0`，落在 `0x2000a490..0x2000a4bc`。仅从字面量反推会整体错位 8 字节。

对象头：`+0x00` 状态、`+0x04` 回调（初始化为 `0x0800fe95`）、`+0x08` 起 64 字节缓冲、`+0x48` head、`+0x4c` tail、`+0x50` 转义标志、`+0x54` 周期（`0x0801321d`）。

| 偏移 | 绝对地址 | 用途 |
| --- | --- | --- |
| `+0x8080` | `0x2000a48c` | 通道掩码数组基址，32 项按 `0x401` 步长置 1 |
| `+0x8084` | `0x2000a490` | 待选标志，由 `0x08016ffc` 检测 |
| `+0x8088` | `0x2000a494` | 选择事件对象，经 `0x080134be` 轮询 |
| `+0x8094` | `0x2000a4a0` | 帧体基址指针，初始化为 `0x2000230c` |
| `+0x8098` | `0x2000a4a4` | 帧体容量，初始化为 `0x100` |
| `+0x809c` | `0x2000a4a8` | 帧体写索引 / 已收长度 |
| `+0x80a0` | `0x2000a4ac` | 长度对象指针，初始化为 `0x20002308`，使用时解引用 |
| `+0x80a4` | `0x2000a4b0` | 16 位帧尾累加器（半字） |
| `+0x80a8` | `0x2000a4b4` | 帧头字节数，初始化为 `min(参数,4)` |
| `+0x80ac` | `0x2000a4b8` | 帧头字节游标 |
| `+0x80b0` | `0x2000a4bc` | 帧头字累加器 |

初始化写者只有 `0x0801d888`，区间 `0x0801d948..0x0801d9dc`，共 11 处写入，顺序为 `0x8094`、`0x8098`、`0x80a0`、`0x80a8`、`0x8080`、`0x8084`、`0x8088`、`0x809c`、`0x80a4`、`0x80ac`、`0x80b0`。容量常量来自 `movs r1,#0x80` 后 `lsls r1,r1,#1`，即 256；帧头上限来自 `cmp r3,#0x4` 与 `movs r3,#0x4` 的截断。

每帧由状态 0 重清四个偏移：`0x809c`、`0x80a4`、`0x80ac`、`0x80b0`。帧体指针、容量和帧头字节数不在每帧重置，它们在初始化时定下后保持。这决定了缓冲区复用方式：每帧重用同一块 256 字节缓冲，只把游标与累加器归零。

## 空洞复扫：43 字节降为 7 字节

扫描范围扩到全部 5631 份 txt 导出，同时用两种访问形式，并引入两条规则：

- **镜像归属规则**：导出地址必须落在 `0x08008000..0x08028720`。3650 份满足，1345 份属于其他模块，其 `param_2` 是另一个对象。`host-legacy-sample-consumers/pass5/0018a510.txt` 是这一类。
- **基址组规则**：同一个基址表达式必须同时寻址洞内偏移与洞外紧邻的已覆盖偏移。仅要求「同函数触及两个覆盖偏移」不足够——`0x08014298` 触及 `0x143`/`0x1c0`/`0x50e` 却只有一个孤立的 `0x281`。

按这两条规则，`027c..02a0` 获得 12 个基址组见证：

| 接入方向 | 函数 | 基址 |
| --- | --- | --- |
| 左侧，`0x270` 起延伸到 `0x290/0x294/0x298` | `0800bedc`、`0800bfbc`、`0800c4aa`、`0800cd80`、`0800cdfa`、`0800ce00` | 各自的 `iVar` |
| 右侧，`0x294/0x298/0x29c` 接到 `0x2a0` | `0801830c`、`080183c6` 两版、`08025534` 两版、`0801b63c` | `param_1` |

洞内被见证的偏移是 `0x290`、`0x294`、`0x298`、`0x29c`。以 `0801830c` 为例，同一 `param_1` 上连续出现 `char +0x29c`、`int +0x294`、`uint +0x298`、`char +0x2a0`，是连续字段而不是零散访问。

但见证只覆盖 `0x290..0x29c`，洞的前段 `0x27c..0x28f` 共 20 字节仍只有 `0x281` 一个孤立候选，没有任何字段级证据。`3e01..3e08` 共 7 字节，两种形式、全部导出中零候选。

三个口径分别给出：

| 口径 | 字节 |
| --- | --- |
| 完全无见证的洞（仅 `3e01..3e08`） | 7 |
| 洞内无字段证据的前缀（`027c..028f`） | 20 |
| 两者合计 | 27 |

字段见证采用对象绑定判据，块级覆盖率为 `11297/15880 = 71.14%`，字段见证与分支解码都不改变覆盖率。

## 0x10f0 块：44 个偏移，非同质结构

窗口 `0x10f0..0x21bc` 约 4300 字节。既有字段台账在该窗口内记录 44 个不同偏移、385 次访问（读 201、写 78、间接 106），涉及 59 个函数，其中 43 个偏移达到对象绑定判据。

第一个被命名的偏移是 `0x1488`，不是 `0x10f0`。`0x10f0..0x1487` 共 920 字节之间没有任何导出给出字段访问，这段是「未被描述」而不是「确认为空」。

按 `0x100` 分段后方向构成明显不同：`0x1488` 一带以标量配置字为主，读写兼具；`0x1c00` 之后以只读字为主，服务于遥测与命令组装；最高频偏移集中在 `0x2000` 附近，说明尾部是上报侧的聚集区。

字段级命名仍不可行：现有导出能给出「哪个函数读了哪个偏移几次」，但给不出该偏移的物理含义。推进需要解码对应写入者。

## 边界

以下项目不在本章范围内：

1. `0x10f0..0x1487` 共 920 字节无任何字段访问记录，需要新的导出。
2. `0x10f0` 块 44 个偏移的物理含义未定，需要解码写入者。
3. `027c..028f` 前 20 字节与 `3e01..3e08` 全 7 字节仍无见证。
4. 命令分派器 `0x40..0x48` 那组九项分支，以及 `0x080171a0`、`0x08017206`、`0x08017668` 另三处跳转表，只有反编译文本、未逐字节解码。
5. 169 个大函数内部地址仍无函数体，必须重新反汇编，已越只读边界。
6. 引脚功能、字段单位、实机时序需要材料或设备。

覆盖口径不变：`覆盖 = TARGET 地址 ∪ function= 所属函数 ∪ 已导出 RANGE 区间`。块级覆盖 `11297/15880 = 71.14%`，14 个空洞共 4583 字节，其中 12 个有见证。
