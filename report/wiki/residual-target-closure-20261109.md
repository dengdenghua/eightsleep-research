# nonUSB flash 内调用目标的可达性闭合与 trampoline 簇

前序分析见[GPIO 描述表、0x10f0 块字段与调用图](post-layout-closure-20261109.md)。字段访问的字面量偏移形式与空洞绑定判据见[字面量偏移字段图与空洞判定](literal-field-access-20261109.md)。本章给出 flash 内 `bl/blx` 目标的可达性闭合过程、`08015f00..08016f00` trampoline 簇的结构，以及「写入见证必须绑定对象」这条方法边界。

全部结论来自冻结 BBIN 的只读字节与既有 Ghidra 工程的 `-readOnly -noanalysis` 导出；没有执行固件、没有联网、没有访问设备或账号。trampoline 簇里每个 stub 对应哪个 `switch` 分支仍未解析，不在本章范围。

## 主要结论

| 项 | 结果 |
| --- | --- |
| 起始残余 | 99 个 flash 内 `bl/blx` 目标没有任何导出覆盖（96 个来自前一轮函数的出边，3 个来自更早轮次） |
| 收敛序列 | **99 → 18 → 3 → 1 → 1 → 1 → 1**，随后卡在两点振荡；最后一轮改按区间导出 |
| 导出规模 | **125 个目标**（124 单函数 + 1 区间 `08015e00:08017000`），133 份 txt |
| 残余终值 | 按「目标地址 ∪ 所属函数」口径 **2** 个；按「再并上已导出 RANGE 区间」口径 **0** |
| 函数体 | **124 / 124 有函数体**，`function=` 全部等于自身地址，无一个退化 |
| 长尾定位 | 残余全部落在 **`[0x08015f00, 0x08016f00)`**：0x1e..0x20 字节 stub 与 6 字节 `__gnu_thumb1_case_shi` 派发器交替互调 |
| 函数画像 | 最小 1B、最大 863B、中位 59B、平均 97B；57 个叶子、16 个调日志、7 个调 memset |
| 负结果 | 导出面从 2690 扩到 2823 份后，GPIO 描述表仍只有 **27 行被引用 / 309 个调用点** |
| 格式串增量 | 日志调用点 909 → **934**，唯一格式串 156 → **165** |
| 覆盖率 | 不变，仍 **11297 / 15880 = 71.14%**；83B 空洞仍无写入见证 |

字节核验 **27 项 0 失败**（7770 条 INSN 逐字节比对）；模型 **39 条断言 0 失败**。见 [残余台账](../analysis-tools/system-deepening/residual-target-closure/RESIDUAL_LEDGER.json)、[收敛记录](../analysis-tools/system-deepening/residual-target-closure/CONVERGENCE.json)、[模型断言](../analysis-tools/system-deepening/residual-target-closure/MODEL_RESULTS.json)、[逐项核验](../analysis-tools/system-deepening/residual-target-closure/BYTE_VALIDATION.json)、[中文结论](../analysis-tools/system-deepening/residual-target-closure/FINDINGS_ZH.txt)。

## 残余如何收敛

起始集合由调用图中未被任何导出覆盖的 flash 目标组成。迭代算法在每次扫描全部导出后重新计算未覆盖目标，直至集合收敛；目标选择与收敛过程均可复算。

| pass | 目标数 | 内容 |
| --- | --- | --- |
| 1 | 99 | 起始残余集合 |
| 2 | 18 | 由 pass1 新函数的出边暴露 |
| 3 | 3 | 由 pass2 暴露 |
| 4 | 1 | `08015f08` |
| 5 | 1 | `08016e08` |
| 6 | 1 | `08015f28` |
| 7 | 1 | `08016e0e` |
| 8 | 1 | `RANGE 08015e00:08017000` |

从 pass3 起每轮只多暴露 1 个地址，且在两簇之间来回：`08015f08 → 08016e04`、`08016e08 → 08015f22`、`08015f28 → 08016e0a`、`08016e0e → 08015f40`。A 簇的 stub 调 B 簇的派发器，派发器的分支块又回调 A 簇的下一个 stub，逐点追下去只会沿环前进。

这是一个**结构决定的上界**，不是导出遗漏。正确解法是按区间导出该簇：`RANGE 08015e00:08017000` 之后，目标层口径残余 2 个（`08015f46` / `08016e14`，均在区间内），并上区间覆盖后为 0。

## trampoline 簇的结构

区间导出共 496 条已解码指令，含 31 个 distinct `bl` 目标，其中 13 个落在本区间内，最高频被调的是 `08016e22`（6 次）；区间内有 35 个 flash 目标被外部调用。

| 成员 | 地址 | 尺寸 | 形态 |
| --- | --- | --- | --- |
| stub | `08015f08` | `0x20` | 4 参数函数，`REF_TO 08016e04` |
| stub | `08015f28` | `0x1e` | 同型，`REF_TO 08016e0a` |
| 派发器 | `08016e08` | 6B | `__gnu_thumb1_case_shi` 注入 |
| 派发器 | `08016e0e` | 6B | 同型 |

`__gnu_thumb1_case_shi` 是 GCC 为 Thumb-1 大 `switch` 生成的查表例程，6 字节派发器 + `0x1e..0x20` 字节 stub 的组合说明这段不是业务逻辑而是编译器产物。**每个 stub 对应哪个 `switch` 的哪个分支没有解析**：静态上要把每个派发器的跳转表读出来再和调用点绑定，属于另一件事。

## 补齐的 124 个函数

| 指标 | 值 |
| --- | --- |
| 最小函数体 | 1B |
| 最大函数体 | 863B（首个 body 块；6 个函数有多个不连续块） |
| 中位 / 平均 | 59B / 97B |
| 无出边叶子 | 57 |
| 调日志 `08012754` | 16 |
| 调 memset `080086a4` | 7 |
| 落在 trampoline 簇 | 8 |

124 个目标的 `function=` 全部等于自身地址，说明它们都是真正的函数入口。这与前一轮 692 目标里 169 个 `function=none` 形成对照：那 169 个是大函数**内部地址**，Ghidra 在那里没有函数体可导出，补齐它们必须重新反汇编。两件事不能混为一谈。

## 一个负结果与一个增量

GPIO 描述表在 2823 份导出中具有 27 行被引用、309 个调用点。该目标集合的 124 个函数均未通过三个访问器读取描述表，因此不能将其余 65 行缺少引用单独归因于这些函数缺少导出。

**日志格式串增加 9 条**：调用点 909 → 934（+25），唯一格式串 156 → 165（+9），增量来自 16 个具有日志调用的导出函数。

## 方法边界：写入见证必须绑定对象

复查「哪些空洞有写入见证」时，如果对所有导出一律统计 `param_2 + 0xNNN` 的赋值语句，会给空洞 `0x0234..0x0258` 凭空造出 3 条见证：

```c
/* local-persistence-final-pass/pass1/0002d3fc.txt */
*(short *)(param_2 + 0x248) = param_1[2];
*(undefined1 *)(param_2 + 0x252) = 0;
```

该函数的第二参数确实叫 `param_2`，但它是**另一个模块的另一个对象**，其所在地址 `0x0002d3fc` 甚至不在本镜像 VA 范围 `0x08008000..0x08028720` 内。

正确口径是只允许持有该对象的两个分派函数作为见证来源。按此复查：

| 分派 | 落在 4 个无见证空洞的写语句 |
| --- | --- |
| `0801d888` | 0 |
| `08027834` | 0 |

因此 `0234..0258`、`027c..02a0`、`1c08..1c0c`、`3e01..3e08` 这 83B 仍然无见证，「10 个空洞有见证、4 个没有」的结论不变。

## 姊妹分派的清块助手

`08027834` 体内 `FUN_080106a4` 出现 **14 次**，即它用同一个助手清了 14 个块；对应的 `0801d888` 用 `FUN_080086a4`。两个分派清块走不同助手，该助手自身在 Ghidra 里仍无函数体（导出一行 `TARGET xxxx function=none`），所以只能确认「以 `(块, 0, 长度)` 形式被调用 14 次」，不能确认内部实现，也无法判定它与 `080086a4` 是否同一份 memset 的两个入口。

## 边界

1. **169 个内部地址**仍无函数体：补齐需重新反汇编并改工程，越过只读边界。
2. **trampoline 簇的分支归属**未解析。
3. **区间导出不等于函数级分析**：区间只保证指令可得，不保证已识别函数边界。
4. **覆盖率未提升**：11297/15880 = 71.14%，83B 空洞无见证。

本章不做：不执行固件、不做动态验证、不接设备、不访问账号或网络；不修改 Ghidra 工程、不重新反汇编、不新增指令；不把代码可达性提升当作布局覆盖率提升。27 项字节核验与 39 条模型断言全部通过，两组独立计数在 124 目标、125 导出、1296 flash 目标、934 日志点、165 格式串上互相吻合。
