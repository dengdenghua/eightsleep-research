# 证据方法与版本边界

本项目基于已取得材料做静态归纳，不在整理过程中连接账号、提交导出、修改设备或执行固件。为避免把不同证据强度混在一起，每个结论需要带上样本、范围和验证方式。

## 证据分层

| 层级 | 可以支持 | 不能自动支持 |
| --- | --- | --- |
| 指令与调用链 | 指定二进制分支、字节格式、函数间关系 | 当前实机恰好运行该版本或分支 |
| 配置与协议 | 默认服务、路由、队列设置、请求响应字段 | 运行期配置一定相同，接口返回一定由某处计算 |
| 合成模型 | 给定输入及建模假设下的数值、排队与时序行为 | 故障发生率、硬件时延、临床准确率 |
| 既有只读响应 | 某次请求返回的版本和字段结构 | 服务器内部程序与所有设备的状态 |
| 论文与专利 | 公开研究或实施例的内容 | 当前 Pod 的生产部署对应关系 |
| 未恢复实现 | 明确缺口与下一步材料需求 | 证明该算法不存在 |

反编译 C、重建 C、模型 Python 都是分析产物，不能称为原厂完整源代码。本 Wiki 以代码和接口证据为主，公开论文与专利不填补生产实现空白。

## 版本不是单一编号

下载 SWU 的发布修订、Frank 的 build 字符串、DAC clientVersion、Capybara assembly、每个 MCU 的 BBIN 版本以及账号 API 的 firmwareCommit 分别由不同组件报告。它们需要额外映射，不能直接互换。

Pod5 与 Pod6 共用 MT8365 是用户提供的机型条件；已下载官方包实际以 MT8365 为目标。Pod6、K60、主板标签与传感板修订也不是同一个命名空间。代码中的 K60 通道表不提供床上几何坐标或校准参数。完整映射见 [平台与版本](modules/hardware.md)。

官方 APK 的四份 DEX 已提取；JADX 存在部分反编译错误，关键链由 Smali 互证。字节清单、字符串命中和类型名都只是进一步追踪的入口，不能独立证明功能实际执行。

## 冻结快照与正文的适用关系

每份证据快照记录源文件 SHA256、分发副本 SHA256、原相对路径和脱敏次数。脱敏副本与源文件哈希可能不同；这不是二进制篡改或证据完全同字节的声明。脱敏只用于项目中的文档副本，原研究材料保持原样。

冻结快照保留生成时的内容，用于核对来源、字节和推导过程；其任务状态不作为当前验收状态。当前结论与未解决问题以模块页和任务表为准，并注明具体适用范围。例如，A02 气囊正常控制与部分故障状态链具有静态证据，Fault1–4 的实际写入端仍未闭合。

## 隐私与可复现性

项目保留协议、代码和必要的技术结构结论，不捆绑登录状态、账号密钥、个人原始波形或完整健康响应。已有的导出申请仅作历史记录；本项目没有再次发起申请。HTML 不调用远端接口，不使用外部字体、CDN 或遥测。

HTML 和 Wiki 可独立阅读。重新做固件反编译需要原始样本和工具环境；原始样本、提取材料及校验清单见完整材料目录，是否完成语义分析另行标注。可视化的合成案例引用既有模型结果，其输入条件均明确显示，没有在浏览器中运行真实固件或生产算法。

后续有新材料时，应先建立样本哈希与版本关系，再更新模块页、任务状态和证据清单，最后重新生成 HTML。
