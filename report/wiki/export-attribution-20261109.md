# 导出语料的字节相容性与来源边界

`foreign = 1461` 是相对于**一份冻结 g0 镜像、两个测试基址、指定指令编码规则**的零匹配集合。它不是“无用文件数”，也不是“全部来自 USB 构建”。本页登记该集合的补充核查；原分类与解码记录保持原样。

## 原分类的准确含义

原模型只加载 `firmware-sensor-g0.bbin`，分别以 `0x08008000` 和 `0x08010000` 比较导出中的指令行。`exact_alt_base = 34` 与 `partial_alt_base = 139` 表示**同一份 g0 字节换基址后**的相容性，不能直接改称 USB 镜像的归属数量。

五类互斥计数为 212、912、34、139、1461，合计 2758 个含指令行文件。1461 只表示该测试下两个基址均无匹配行；不同构建、其他地址空间、混合导出、编码差异及缺失样本等原因尚需分别核验。

## 候选比对范围与判据

使用冻结目标及八份兄弟 BBIN，共九份候选。每个候选登记完整路径、字节数与 SHA256。按导出中全部指令地址，枚举能容纳至少一条完整指令的非负、4 KiB 对齐基址，逐行比较；不以文件名或前六行短签名筛选。

“支持的候选”须同时满足：至少六条指令、至少 95% 行匹配、至少 16 字节连续匹配，且推定基址处于测试闪存窗口 `0x08000000–0x08100000`。优先保留全行匹配候选，否则保留全部达标候选。“唯一”只表示这九份文件及该策略内唯一，不证明导出工具原来打开的是哪个构件。页对齐与编码形式是测试限制，不是所有固件的硬性规律。

内容不足类优先归类。其中 24 份同时属于窗口外地址，故按全部指令地址统计，窗口外共 487 份；**487 与 145 不可直接相加**。文件名地址、指令行地址及测试窗口不是同一口径。地址统计与互斥分类必须分表，不能混用。

唯一候选的分布为：USB 传感器镜像 `0x08010000` 下 157 份（62 全行、95 高相容）；legacy 镜像 `0x08005000` 下 31 份（18 全行、13 高相容）；pillow 镜像 `0x08008000` 下 7 份（4 全行、3 高相容）。合计 195。此前按短签名或未声明比例得到的数量，不与本判据混用。

## 哈希引用不等于固件身份

两份导出含 `SOURCE_SHA256 fab73ec7…a3386`，它实际对应 `sensor-log-producers/pass1/functions/0801f0d0.txt` 的文本哈希；已对保留的上游导出逐字节重算确认。它不应拿来与九份固件哈希直接比较后认定“缺失固件”。其余 1459 份没有这种内嵌引用，也不能因此断言外部来源清单不存在。

补充表为全部 1461 份导出重算自身哈希，并登记候选镜像哈希和比较基址。这建立可复验的内容对应关系；原始 Ghidra 工程、导出命令与输入构件的来源绑定仍是独立证据。

## 对报告结论的影响

- 原解码器仅从完全/部分主基址相符类取得入口，`foreign` 不参与入口语料。该策略由模型代码确认。
- 原始 `EXPORT_IDENTITY`、解码统计、函数索引、镜像分区、导出对照与模型结果均保留，补充核查前后 SHA256 相同。**784 个入口、48306 条指令与 78.16% 仍是原解码产物的统计**；文件未变化不等于重新证明每一条解码正确。
- 对引用这些导出伪 C 的其他专题，仍须逐项核对构件身份；不能把“这些文件未参与解码”扩大成“所有既有字段和算法结论都不受影响”。

## 来源恢复计划

1. 保留原排除集合，不删除导出，不将兄弟构建代码加入冻结 g0 的种子。
2. 对 195 份唯一候选补原始工程输入哈希、装载基址、导出器版本和命令；相容性与来源确认分别记账。
3. 对多候选及短文件追上游完整函数/调用者，扩大连续字节证据；不能仅靠增加短签名命中数量消歧。
4. 对无支持候选先查编码形式、裁剪范围、来源侧清单和其他保留构件，再考虑补样本。新样本必须独立登记版本与哈希。
5. 其他专题若依赖未绑定导出，则将相应结论保留为条件性解释；只有完成构件绑定及字节复核后，才提升其适用范围。
