# 五态帧解析状态机与 0x08016fdc 跳转表归属

前序分析见[非USB字面量偏移字段图](literal-field-access-20261109.md)、[调用目标闭合与 trampoline 簇](residual-target-closure-20261109.md)与[上报对象构造链](report-object-layout-20261109.md)。本章解析 `0x08016fdc` 的五项跳转表，把 `0x08016e50..0x08016ed4` 的五个状态处理块逐条解码，并给出队列对象、字节填充规则与全局字段。

全部结论来自冻结 BBIN 的只读字节与既有 Ghidra 导出；没有新增 Ghidra 调用，没有执行固件，没有联网或访问设备账号。五个 handler 入口位于 Ghidra 未解码的字节段内，直接按冻结镜像解码，不修改工程。

后续分析见[接收链路下游闭合](receive-path-closure-20261109.md)：`0x0800a578` 是单寄存器推送器，三种模式分别处理字节流、半字流与字流；状态 4 比对成功后按 `0x2000230c` 的 bit7 分两路，汇合到 `0x08017132` 的五项字节表；队列对象 `0x2000240c` 的十一个字段由 `0x0801d888` 单点初始化，空洞 `027c..02a0` 获得基址组见证，无见证字节由 43 降为 7。

## 主要结论

| 项 | 结果 |
| --- | --- |
| 真正的 switch | `08016fd0` 读 `[0x2000240c]` 状态 0..4，`08016fd8` 调用 `__gnu_thumb1_case_shi` |
| 跳转表 | `08016fdc` 起 5 个 int16，`3aff4aff60ff76ff7cff`，增量 -198/-182/-160/-138/-132 |
| 五个目标 | `08016e50`、`08016e70`、`08016e9c`、`08016ec8`、`08016ed4` |
| Ghidra 覆盖 | 五个入口**均无 INSN 行**，也没有直接 `bl` 指向它们 |
| 状态机 | 帧起点重置 → 字节道掩码 → 净荷复制 → 尾值高字节 → 尾值低字节与比较 |
| 帧格式 | `0x7e` 帧标志、`0x7d` 转义、转义后 XOR `0x20`，PPP/HDLC 风格异步填充 |
| 队列对象 | `0x2000240c`：状态 +0、回调 +4、64B 缓冲 +8、head +0x48、tail +0x4c、转义 +0x50 |
| 全局字段 | 19 处 LDR 字面量解析到 **10 个**地址 |
| 解码量 | 状态 0..3 共 **132B / 90 条**（88 条线性 + 2 条冷尾）；状态 4 线性前缀 24 条 |

模型 **89 条断言 0 失败**，独立字节核验 **90 项 0 失败**。见[跳转表](../analysis-tools/system-deepening/state-machine-switch-closure/SWITCH_TABLE.json)、[状态机](../analysis-tools/system-deepening/state-machine-switch-closure/STATE_MACHINE.json)、[模型断言](../analysis-tools/system-deepening/state-machine-switch-closure/MODEL_RESULTS.json)、[字节核验](../analysis-tools/system-deepening/state-machine-switch-closure/BYTE_VALIDATION.json)、[中文结论](../analysis-tools/system-deepening/state-machine-switch-closure/FINDINGS_ZH.txt)。

## 跳转表与分派

`08016fd0` 的状态分派只有五条指令：

```asm
08016fd0  ldrb r0,[r6,#0x0]     ; 状态 0..4
08016fd2  cmp  r0,#0x4
08016fd4  bls  08016fd8
08016fd6  b    08016e22          ; 状态 >4 丢弃该字节
08016fd8  bl   08008484          ; __gnu_thumb1_case_shi
08016fdc  .short -198, -182, -160, -138, -132
```

`08008484` 的语义是：

```asm
push {r0,r1}
mov  r1,lr
lsrs r1,r1,#1
lsls r0,r0,#1
lsls r1,r1,#1
ldrsh r1,[r1,r0]
lsls r1,r1,#1
add  lr,r1
pop  {r0,r1}
bx   lr
```

表基址是返回地址 `08016fdc`，每项是半字增量，目标为 `08016fdc + 2 * int16(entry)`：

| 状态 | 表项 | 增量 | 目标 |
| --- | --- | --- | --- |
| 0 | `3aff` | -198 | `08016e50` |
| 1 | `4aff` | -182 | `08016e70` |
| 2 | `60ff` | -160 | `08016e9c` |
| 3 | `76ff` | -138 | `08016ec8` |
| 4 | `7cff` | -132 | `08016ed4` |

五个目标全部位于 `08015e00..08017000` 区间导出的空洞中。该导出有 496 条 INSN，但从 `08016e4e` 直接跳到 `08016f10`，中间 194B（含跳转表和五个 handler 入口）没有任何指令行。因此逐点追 `bl` 目标无法到达这五个入口，只有解析跳转表才能进入。

## 六组常量装载不是 switch 分支

此前记录为「六组 `ldr` 字面量 → `bl` stub」的配对，实际是序列化与日志路径上的冷路径：

| 配对 | 入口条件 | 值 | 作用 |
| --- | --- | --- | --- |
| `08016e02 → 08015f08` | `08015f02 [r4]==0` | `0xbf800000` | `-1.0f` 默认值 |
| `08016e08 → 08015f28` | `08015f22 [r2+0x1c]==0` | `0xff7fffff` | 清 bit 23 掩码 |
| `08016e0e → 08015f46` | `08015f40 [sp+0x2c]==0` | `0xff7fffff` | 清 bit 23 掩码 |
| `08016e14 → 08015f64` | `08015f5e [sp+0x2c]==0` | `0xff7fffff` | 清 bit 23 掩码 |
| `08016142 → 08012754` | 诊断路径 | `0x080252a8` | 日志格式串 |
| `08016f18 → 080134be` | 定时/状态路径 | `0x2000a498` | RAM 参数 |

前四组把默认值放进寄存器后跳回序列化续点，不是独立分支；后两组是普通调用点。真正的 switch 只有 `08016fdc` 的 5 项。`SWITCH_TABLE.json` 的 `reclassification` 段记录这些指令组的分类依据。

## 五态状态机

队列对象位于 `0x2000240c`：

| 偏移 | 字段 |
| --- | --- |
| `+0x00` | 帧状态 0..4 |
| `+0x04` | 传输读取回调 |
| `+0x08` | 64 字节输入缓冲 |
| `+0x48` | 已填充字节数 / head |
| `+0x4c` | 已消费索引 / tail |
| `+0x50` | 转义标志 |

缓冲耗尽时 `08016fe6` 调 `callback(buffer+8, 0x40)`，把返回值写入 head，tail 清 0。

### 状态 0：帧起点重置

`08016e50` 先判 `r2==1`，否则直接回到 `08016e22`。只有 `0x7e` 帧标志会把 `r2` 置 1。重置动作：

```text
状态 := 1
[0x2000a4a8] := 0                 ; 复制索引
*[0x2000a4ac] := 0                ; 通过指针清零
[0x2000a4b0] := 0                 ; 16 位尾值
[0x2000a4b8] := 0                 ; 道索引
[0x2000a4bc] := 0                 ; 道掩码
```

### 状态 1：字节道掩码

`08016e70` 读取道计数 `[0x2000a4b4]` 与道索引 `[0x2000a4b8]`，计算
`shift = (count - 1 - index) * 8`，把 `1 << shift` 或入 `[0x2000a4bc]`。
每道写入一个 `0x01` 字节；索引到达计数后，把完整掩码写入 `*[0x2000a4ac]`，状态转 2。

### 状态 2：净荷复制

`08016e9c` 以 `[0x2000a4a0]` 为缓冲、`[0x2000a4a8]` 为索引、`[0x2000a4a4]` 为上限复制字节。索引达到上限时走 `08016ea8` 的 `bcs 08016ec4` 冷尾：`str r0,[r6,r2]` 保存最终索引，再跳回 `08016eb0` 完成最后字节与长度比较。线性路径与冷尾合计 44B。

### 状态 3：尾值高字节

`08016ec8` 把状态置 4，并把当前字节左移 8 位后存为 16 位半字到 `[0x2000a4b0]`。

### 状态 4：尾值低字节与比较

`08016ed4` 把状态清 0，把当前字节或入 `[0x2000a4b0]`，随后以
`r0=0x2000070c`、`r1=净荷缓冲`、`r2=字节计数` 调用 `0800a578`，并把返回值的符号扩展半字与 `[0x2000a4b0]` 比较。不等则回队列循环；相等后读取 `0x2000230c` 状态字节，bit 7 作为门控，低 7 位作为后续代码。

`0800a578` 的确切语义尚未闭合：它把一个 sink 对象、缓冲区与字节计数作为参数，按对象模式流式写入，并返回最后一个字。因此这里只记录「返回值与 16 位尾值比较」，不把尾值断言为校验和。

## 帧格式

`0x7d` / `0x7e` / XOR `0x20` 三件事一致指向 PPP/HDLC 风格异步字节填充：

```asm
08016e46  movs r2,#0x0
08016e48  strb r2,[r1,#0x0]    ; 清转义标志
08016e4a  movs r1,#0x20
08016e4c  eors r3,r1           ; 转义字节还原
08016f28  cmp  r3,#0x7d        ; 0x7d 转义
08016f2c  subs r3,#0x7c
08016f2e  strb r3,[r1,#0x0]    ; 转义标志 := 1
08016fc8  cmp  r3,#0x7e        ; 0x7e 帧标志
08016fcc  strb r2,[r6,#0x0]    ; 状态 := 0
```

`0x7d` 的 `subs` 结果写入 `+0x50` 的转义标志，不是帧状态；帧状态始终在 `+0x00`。状态值大于 4 时，`08016fd6` 直接丢弃该字节。

## 全局字段

19 处 LDR 字面量解析到以下 10 个地址：

| 地址 | 作用 |
| --- | --- |
| `0x2000a4a0` | 净荷缓冲指针 |
| `0x2000a4a4` | 净荷复制上限 |
| `0x2000a4a8` | 净荷复制索引 |
| `0x2000a4ac` | 指向道掩码 / 完成值的指针 |
| `0x2000a4b0` | 16 位尾值累加器 |
| `0x2000a4b4` | 道计数 |
| `0x2000a4b8` | 道索引 |
| `0x2000a4bc` | 道掩码累加器 |
| `0x2000070c` | 传给 `0800a578` 的 sink/writer 对象 |
| `0x2000230c` | 状态字节：bit7 门控，低 7 位代码 |

这些都是 RAM 地址，flash 中没有初值；运行时初始化点仍需从其它写者追。

## 边界

1. **不提升块级覆盖率**：本章只补齐未解码代码的分支归属，覆盖率口径不变。
2. **`0800a578` 语义未闭合**：参数顺序和返回值比较已定位，但内部模式 1/2/3 的精确行为仍需更多证据。
3. **状态 4 后续未展开**：匹配后对 `0x2000230c` 低 7 位代码的处理只到 `08016f06` / `0801710c` 两个入口。
4. **状态 2 有两条入口**：线性路径与 `08016ea8` 的 BCS 冷尾，分开记录，不合并成线性前缀。
5. **RAM 初值未知**：`0x2000a4**` 与两个绝对地址的初始化写者尚未定位。

本章不做：不执行固件、不做动态验证、不接设备、不访问账号或网络；不修改 Ghidra 工程、不重新反汇编。89 条模型断言与 90 项独立字节核验全部通过；两组计数在 5 项表、5 个状态、132B、19 处字面量、10 个全局字段上互相吻合。
