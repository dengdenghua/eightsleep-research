# 电容、范围统计与温度：本地处理细节

G0 USB 的正常电容处理链由 `0802572c` 执行，涵盖 FDC 换算、CAPDAC 调整、有效值缓存与状态计时，并生成 `0x33/0x44` 消息。该结论由样本原始指令及主循环调用关系支持；实机启用情况仍需匹配固件版本、配置与帧记录。

## FDC：换算、量程调整和有效值缓存

```text
寄存器 → signed24 × 2^-19
       → 加 CAPDAC × 3.125 补偿
       → 量程调整 / grace 等待 / 有效值缓存
       → 通道映射 → 0x33 或 0x44
       → Frank → raw.sens.capsense / raw.sens.capextended
```

| 环节 | 恢复出的规则 |
| --- | --- |
| 数值换算 | 合并寄存器、符号扩展，再乘 `2^-19`；随后加 CAPDAC 补偿 |
| 自动调整 | 原值 ≤−12.875 时减 CAPDAC；>12.875 时增加，限于 0..31；部分条件会重置到 4 |
| 等待与缓存 | 调整后的 grace 期保留旧缓存；有效缓存年龄达到 5500 tick 时返回 −1 |
| 读数状态 | railed、locked、converged、too low 来自数值范围、变化和持续时间判断 |
| 状态刷新 | 外层每 30000 tick 检查并保存状态；发送读的是缓存状态，不是每包重算 |
| 组包 | 500 tick 发送定时器，按模式选择 6 路整数或 16 路 float；不保证每次发出的都是新测量 |

这些状态描述传感读数。它们不是“是否有人在床”、睡眠阶段或生理质量标签。

### −1 到主控后并不总是缺值

`0x33` 把缓存乘 100 后取 16 位图样。−1 因此变成 `0xff9c`，主控按无符号数输出 **65436**，没有自动转空值。`0x44` 保留 −1.0 的 float 图样；正常解析项的 valid 为真，同样不会自动转空值。

此外，MCU 状态 4 的含义是 `too low`，主控的状态文字表却将 ≥4 映射为 `unknown`。研究原始数据时要保留版本、opcode 和状态映射，不能只看图上的数字。

每侧电容模式的组合器从左右队列各取一条队首记录，使用较小时间戳；差值过大只记日志，不在这里寻找时间最近的另一侧记录。两侧放在同一输出中，不等于已经同步采样或完成信号融合。

## 0x35：四列分别从哪里来

旧式 LIS 分支执行 **16 条均值 → 最近 25 窗范围** 运算，四个输出与主控字段的对应关系如下。

| 主控字段 | 实际来源 |
| --- | --- |
| pres.left1 | 第一组 ADC 范围统计 |
| pres.right1 | 第二组 ADC 范围统计 |
| pres.left2 | 第一 LIS Z 轴换算值与状态位的打包结果 |
| pres.right2 | 第二 LIS Z 轴换算值与状态位的打包结果 |

启动时统计窗口清零，前段仍固定除以 16，因此包含初始化零值。正常包经旧式 Sensor 消费后进入 `raw.sens.lps`；当前 UsbSensor 分派不会用这两个旧 decoder 处理 `0x34/0x35`。

字段名 `pres/lps/left/right` 不足以证明压力单位、人体左右或当前机器启用。固件中旧 LIS 分支还有硬件条件，不能直接套到 K60 实机。

## 温度：换算、筛选均值与加权组合

G0 USB 使用出厂校准值和 ADC 参考值换算电压，再按热敏电阻公式求温度。每路保留最近最多 10 次写入；读取时只纳入 **2..60°C** 的值求均值，全部无效则返回 −100。没有在这里按“距离现在多久”淘汰旧项，所以不能称为固定 10 秒窗口。

两输入组合为：

```text
W(a,b,r) = (max(a,b) + 0.2×min(a,b) + 0.1×r) / 1.3
```

三输入分支按有效性选择并嵌套调用 W。三个输入 a/b/c 全有效时，先算 `u=W(c,a,r)`，再算 `W(u,b,max(b,u))`；第二次输入使用的是中间结果 u，不是原始 a。该处已按汇编寄存器覆盖和独立算例复核。通道组由硬件模式选择；缺少板级证据时，继续使用软件槽号，不给它们擅自冠以皮肤温度或室温。

温度查询和扩展包使用这些结果；其中 `0x3d` 包没有 MCU tick，不能直接与带 tick 的电容包按同一时间轴拼接。

### 主控还会再次筛选，而且两个出口规则不同

同一 `0x3d` 经过主控后，形成两种温度输出：

| 输出 | 主控处理 |
| --- | --- |
| `raw.x.sens.bedtemp` / `stealthTemps` | 八项温度再按 2..60°C 检查，附加字段为负也清有效位；无效项写 null，缺侧整体为 null |
| `raw.sens.bedtemp` / `bedTemp` | 每侧前三项各乘 100、截为 signed16 后求整数平均；只检查整侧可用，未复用上面的逐项检查 |

所以“已经有一个出口把无效温度清空”不等于其他出口也清空。有限算例 `[-100,20,30]` 在前者的第一项为 null，在后者却参与兼容平均，得到 −1666 的百分之一单位整数。这是代码输入算例，未观察实机发生。

实际调用链没有把 `0x3d` 接到另一个名为 `bedTemp2/raw.sens.tempextended` 的编码器；仅凭名称会对应错出口。

## 辅助磁传感 0x39：状态判定与数据选择

G0 USB 的辅助驱动也已追到主控输出。两段有效 CRC 的 I²C 数据进入缓存，XYZ 按 `signed16 / 32768 × range` 换算，range 表选 40 或 133。内部温度另算，但 **0x39 的 temp 字段取自相邻 TMP1075 缓存**，不是磁传感芯片内部温度。

温差>5、轴差>1 的比较控制日志，不是数值更新的滤波死区。0x39 没有 MCU tick；主控收到后赋时，各字段也没有独立年龄标记。

主控按有效磁场值与 `X²+Y²>3.05` 判断连接，再按 X/Y 符号生成方向字段。它描述附件连接和方向，不是睡眠姿态分类。

这里有两层容易混淆的数据选择：

1. 解码器虽然解析单包的两组输入，返回的两份 map 却都复制第一组；原汇编已独立复核。
2. 正常后续只取第一份 map，按 **USB 对象的 side** 进入两个队列。最终 left/right 来自各 side 的队首，不能据前一步推断“左右输出恒同”。

两侧都有新记录时取较小时间戳，不做时间邻近匹配；只取到一侧时，另一侧保留此前 map。已入队的一对记录也可能等下一次输入才触发输出。最终为 `blanketReadings → raw.sens.blanket`，复用既有发布队列。

聚合 version 的构造与赋值规则如下：构造初值为 **0**；`stateBootloaderStartFirmware` 在 `sinfo.rev >= 0x0a00` 时调用主控设置函数，把共享字段写为 **0x82，即整数 130**。`rev < 0x0a30` 的另一模式参数不改变这个赋值。wire version 没有随 64 字节队列记录复制；后续快照和 CBOR 编码读取主控字段，数值 130 编为 `18 82`。因此，不能根据上传的 version 反推传感器包或睡眠算法版本。

这条设置路径清所选 side 的队列，不等于清掉所有 map。当前 USB 对象数量、side 配置、启动/重连时序与真实输出仍待核对；构造为 0 不表示实机一定发布过 0。

## 失败、过期与恢复

FDC 测量超时和完整对象重初始化具有不同的缓存行为：前者不直接清有效缓存，后者清缓存并重设 −1。TMAG 两段 CRC 分别决定是否更新，可形成旧 T/X/Y 与新 Z 的组合；第二段回调到达不证明两段均通过。TMP 读取超时则保留旧温度，没有同款年龄作废 getter。详见[失败恢复与缓存保留](../local-followup-20261108.md)。

## 实际启用仍需核对

旧式 Sensor 由配置中的非空 `sensorPort` 启用；随包 A00 段有 `/dev/ttyS2`，I00/I21 段没有。配置选的是整段对象，不自动继承较旧段端口。实机型号标签、配置和实际 opcode 尚未读取，代码可达不能替代部署证明。

按实际 libc 调用，`00202a64 → 002379a0` 为读取路径，`00202a50 → 00237a60` 为写入路径。
