# 本地机械算法：气囊闭环、校准与床架抬升

这些链都在设备本地执行。气囊 MCU 根据压力反馈控制阀泵，主控校准器提供补偿系数；床架任务接收目标角度，调整运动速度。它们与压电心肺分离、睡眠分期是不同算法，当前实机是否安装对应附件仍待版本核对。

## 气囊 MCU：压力反馈直接控制阀泵

已恢复 A02 `0.2.71.0` 的正常闭环，原件为 143,360 字节。目标压力记为 `SP`，实测压力为 `p`；通用初始化值可能被平台配置和校准覆盖。

| 环节 | 本地规则 | 实际使用边界 |
| --- | --- | --- |
| 充气停止 | `SP + b_eff × clamp(sqrt(duty/100), 0.55, 1)`；duty=0 时缩放取 1 | 实测压力达到此目标才停止；补偿启用时 `b_eff = f32(f32(SP+b)-SP)`，关闭时为 0；保留原 float32 运算顺序 |
| 放气停止 | 补偿启用且 a>0 时用 `(SP-ci)/a`，否则用 SP；SP<1 选择低压系数 | 先经过配置的回稳等待；实测 `p<0.1 kPa` 或 `p≤停止目标` 时转稳态，没有使用预测压力停阀 |
| 稳态判断 | 至少间隔 500 ms 算压力斜率；绝对值<0.06 kPa/s 连续累计到 3 | 需满足最低停留时间，且满 8 秒或累计到 3；满 8 秒不绕过最低停留时间 |
| 避免反复调节 | 离开稳态不足 3 秒就再次调节，会累计振荡次数；超过 4 进入振荡状态 | 稳定至少 10 秒后清计数，另有调度和目标变化分支 |
| 动作选择 | 有安全泄压请求时先选这些袋；否则合并所有放气与充气请求 | 不是按 priority 字段排序，也不是每轮只能动作一个袋 |
| 泵输出 | commanded 优先；同类选目标差绝对值最小的一袋作为参考，再做比例、限幅和单双泵滞回 | 参考袋与动作袋集合是两层选择；最终经过定时 ramp 写 PWM |

公式符号与实际校准字段的对应关系为：`b` 是充气偏置，`ci` 是普通放气截距，低压组为 `al/cl`。符号归属由字段复制与消费者的原指令绑定确定。[字段绑定、默认表与覆盖顺序](../../evidence/analysis/system-deepening-20261108/local-parameter-resolution/FINDINGS_ZH.txt)

放气速度使用 `v = clamp(0.3 × 速度 + 0.7 × v, 0, 1.5)`，再算预测压力 `p-v×预测时长`。**预测值确实被计算，但已核正常停阀分支读取的是实测压力。** 增强遥测也上报速度和停止目标，没有在该包中上报这项预测压力。

### 袋压体动门控：20 点标准差

生产算法的处理规则为：每袋积累 20 个合格压力值，计算总体标准差，再取各袋评分的最大值。

```text
score_bag = sqrt(max(mean(p²) − mean(p)², 0))
score = max(各有效袋的 score_bag)
```

实现使用循环窗口、相对基准的偏差和平方和，并在每写满一圈时重算基准，减少累计误差。它不是相邻压力差分的标准差，也不是把所有袋压先平均。

输入仅限已初始化、处于 OFF/STEADY、双阀空闲、传感正常且非无效值的袋；条件不符就清窗口。名义周期 50 ms，20 点约 1 秒，但这里没有核对采样序号，不能保证 20 个值都是新测量。

通用阈值为 0.050 kPa：超过阈值开始暂缓自动调压，连续安静 3 秒后解除。持续阻挡最多 60 秒，之后恢复调压并等待安静复位；没有合法评分时，正在阻挡的状态会立即解除。阈值相等不触发。

**门控只约束部分非 commanded 的自动调节入口**，不直接打断已经开始的充放气，也不统一阻挡命令调压或安全泄压。这是气囊压力体动控制，不能替代压电在床检测或睡眠分期。

阀、泵请求还要经过延时、分段占空比和 PWM 写入；代码发出动作不等于实物已响应。物理精度、实际阈值和当前运行版本仍待同版本设备验证。

## 气囊：从压力记录到补偿系数

完整路径是 `calibration/start → CalibrationRunner → CSV / LandingTelemetry → 拟合 → 系数校验 → MCU`。随包默认使用 `pulse`，以 Node 结果为准；C# 分析器同时运行作比较。**指定分析器失败不会自动采用另一套结果**，比较结果不直接决定写入。

| 阶段 | 本地处理 | 关键边界 |
| --- | --- | --- |
| 压力参考 | 最后一个有效 `Pressure_S*` 列作大气参考，逐点相减 | 参考均值须满足 `50<均值<150 kPa`；不是固定使用 S4 |
| 预处理 | 居中中值滤波，在全局峰值处分出充气与放气段 | 20 Hz 下中值窗 5 点、回稳窗 8 点、平台窗 20 点 |
| 放气事件 | 差分找回升，IQR 去离群，检查平台斜率 | 每个事件得到 `pBefore`、`pAfter`，后者至少 0.15 kPa |
| 放气拟合 | `pAfter = a × pBefore + ci`，最多相关分析残差剔除 | 至少 5 点；R² ≥ 0.70；剔除用绝对残差的总体标准差 |
| 充气偏移 | 取泵停后的峰值与稳定平台差，再取中值为 `b` | 高变异产生提示，不直接判拟合失败 |
| 写入前检查 | 检查五个系数有限且在设备配置范围内 | 拟合可接受 `a=1.0`，默认写入下限却是 1.1 |
| 应用 | 每袋设置 `a/b/ci/al/cl`，最后请求保存 | 多次请求；未见此处保存后再读回校验 |

这里确有滤波和异常值剔除，但处理对象是**机械校准压力**，不能把它移植解释为睡眠波形清洗。

### CSV 没有修复时间缺口

同一遥测包的所有行写相同的 UTC 秒时间。记录器用设备时间估算缺失点数，但不补行。分析器使用第一行采样率和行号构建窗口，不使用 UTC 列恢复逐点时间；因此“记录了丢点数量”不等于“拟合前修复了缺口”。

部分窗口按采样率换算，另有固定 10/5 点均值和每点差分门限。不能认为换成任意采样率后算法完全等价。

### Landing 是另一条校准路径

`landing` 将压力与增强时间轴按设备时间配对，计算稳态窗口，再按放气阀边缘定位停止压力。它拟合 `Rest = a × Stop + ci`，要求至少 4 点、3 个起始压力档、R² ≥ 0.98，并核对 240 ms 的板端回稳窗口。最后采用 landing 的 `a/ci`，结合 pulse 的 `b`；`landingOnly` 则保留已存的 `b`。

两种方法目前都把低压段系数设置为 `al=a、cl=ci`，没有分别拟合两条不同直线。运行、临时配置恢复、实际保存和物理精度仍不能只靠静态代码证明。

## 校准设置何时真正生效

A02 启动时在有效持久校准与 SKU/side 默认表之间二选一。`0x60/1` 只改待保存区，Get 也读该区；save 成功后才覆盖运行对象。`0x53/9` 则直接改运行 `a/b/ci`，同时令 `al=a、cl=ci`，不写 Flash。clear 成功后的通用默认与重启后的 SKU 默认可以不同。

主控 `Persist=false` 只发 set_bag，不能称为临时应用；Landing 的恢复只表达三个数，不能保证原样恢复不同的低压组。模式命令另改泵上限、阀时序和调度时间，不改五系数。完整状态对照见[参数生效与覆盖](../local-followup-20261108.md)。后续[参数、执行与采集底层](../local-final-pass-20261108.md)补齐R12与请求队列、其余0x53和直接泵阀命令：sleep的80%是策略与目标设置，直接命令仍能覆盖泵目标；11字节开阀配置会用mode表补写关闭参数。

## 床架：止鼾指令之后怎样抬升

已注册的 `bedframe/setangle` 接收 `SnoreMitigation`、侧别和目标角度。专门任务的输入已经是角度，未包含声音或压电波形。因此恢复的是**止鼾运动控制**，鼾声识别和目标生成仍缺实现。

| 环节 | 已恢复的本地规则 |
| --- | --- |
| 排队 | 新止鼾任务只在关节队列为空时进入；普通移动可用“停止→暂停→移动”替换当前止鼾任务 |
| 单侧目标 | 参考另一侧已有目标或当前位置，将两侧目标差限制到 10° |
| 同步运动 | 两侧当前角度差超过 4°，暂停较接近目标的一侧；另有超过 5° 的同步错误处理 |
| 速度统计 | 起始 2 秒后积累位置，取最近 5 条记录首尾的 ticks 差除以时间差 |
| 输出调节 | 起值 8；速度 ≤1.5 则加 5；速度 >5 则乘 0.8、最低 8；中间区间保持 |
| 完成 | 正常运动分支检查已发送、达到角度且停止；另有首次已到目标的提前完成和错误停止分支，不能将返回值一概当作实物到位 |

速度单位是协议 `ticks/s`，不是角度每秒或鼾声强度。每次调节后清统计列表，但不重置首次时间；后续调节不会再次完整等待 2 秒。该调节器本身没有 100 上限，下游 TriMix 发送方法会拒绝超出范围的 feedRate，不能理解为自动夹到 100。

附件 `HardwareVersion="2"` 走普通移动分支，使用请求中的 feedRate；专门止鼾任务则自行从 8 起调。硬件标识不能按字面对应 Pod 代数。

## 敲击闹钟与普通调温的分流

原生函数 `0020dcd0` 检查左右各三个振动任务的有效时间窗，只要一个满足就返回真。USB 敲击入口据此先进入闹钟处理，否则才走普通调温；闹钟分支拒绝处理时，不会自动回退为同一次调温。

这个判断检查两侧任务，且不检查振动实际发送是否成功。它是局部控制规则，不是云端、手动、BLE 之间的一张全局优先级表。
