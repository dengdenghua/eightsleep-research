# 本地音频：文件、循环与播放

这条链从已经选定的音轨开始：`speaker/play → 音轨缓存/转换 → WAV → Pipe → PulseAudio → 输出设备`。已恢复的是播放处理；其输入没有压电波形或鼾声分类结果。

| 环节 | 实际代码行为 |
| --- | --- |
| 文件准备 | 使用已有缓存或下载；非 WAV 交给 FFmpeg 转换，只显式指定输出为 WAV |
| 格式 | WAV 头允许 8/16/24/32 bit，但实际播放器只实现双声道、16/24 bit、小端 PCM |
| 数据搬运 | 每次最多读 4096 字节，按 PulseAudio 请求量提交；已查第一方链未逐点滤波 |
| 声道 | 第一通道映射右、第二通道映射左 |
| 音量 | 正常 0..100 档乘 655，提交给 PulseAudio；这不是声压或功率公式 |
| 渐入 | 从 0 起，后续距上次增长超过 2 秒时加 1，直到请求音量；第一次增长可能更早 |
| 缓存刷新 | 至少一个预取成功或曲目列表为空，12 小时后再刷新；全部失败则从 1 分钟退避，最高 1 小时 |

播放器中的时长和当前位置先做整数除法，因此报告秒数会截去小数。时间转字节位置则使用 `floor(秒 × 采样率) × 声道数 × 位深 / 8`，两处精度不能混为一谈。

循环与跳转还存在三个已由 IL 核对的细节：首次读取包含 WAV 数据起点偏移，后续跳转分支未加该偏移；定时循环末段把剩余时长直接作为终点；循环跳转固定读第一段时长。它们是代码行为，尚未观测到对应实机效果。

这里没有恢复音箱内部 DSP、蓝牙传输和 PulseAudio 服务自身的转换过程，也不能由播放链的边界断言整机没有任何本地音频推理。

## B13 音箱内部：已提取的部分与具体卡点

已继续检查 MTK 包的 V37、V38、V42 三份 FOT。V37/V38 的主体905,216字节完全相同，整文件只差28字节，集中于重复头和尾段。不能仅凭这两个版本号声称 DSP 主体发生变化。

4096字节尾段并非全是不可读载荷：有 `INFO`、`B13`、`BT-Photo`、`LE-Remoter`，相对偏移 `+0x129` 的值分别为37/38/42，与文件版本对应；`+0x10f` 随之反向变化。已保存逐字节差异和原始切片，但它们仍是配置候选，尚未绑定设备读取函数，不能据此命名 EQ 或滤波系数。

真正卡住的是 XCOD 内层格式：`file+0x204/+0x208/+0x20c` 可读出字段，但没有 loader 或打包器解释其含义，不能可靠划分代码段、确定 ISA 与装载地址。已列明范围的标准压缩探测未得到有效执行段；高熵和解压失败都不足以证明加密。

下一步所需材料已具体化为三类之一：

- 同系列 XCOD loader/打包器，核对描述字段和载荷变换。
- 同版本打包前 ELF/AXF/bin 与链接 map，或含加载跳转逻辑的 loader 镜像。
- 生成尾段 INFO/DOWN 的配置工具或序列化结构，给候选字段绑定语义。

当前主控 updater 负责发送整文件，没有内部解码或 DSP 函数，继续追同一发送入口不能补出音箱内部算法。
