# 计数完成、可选数据包与状态统计链

本章继续沿已绑定的冻结 g0 主循环对象 O，连接模式字节、可选 `0x3d` 数据包、计数门控和状态 6 的统计。原始字节与模拟结果分开记录；未发送真实数据，也没有证明云端收到任何包。

## 计数不是发送成功次数

进入所核片段后，有三条路径汇合到 `0x08016712` 的计数自增：

| 条件 | 到达计数前发生什么 |
| --- | --- |
| `O[0x2030] == 0` | 从 `0x08016664` 直接跳到计数，不构造此 `0x3d` 包 |
| 条件字节非零，但 `0x080134be` 返回零 | 从 `0x08016672` 跳到计数，不发送此包 |
| 条件字节非零，调用返回非零 | 构造包，调用 `0x080122d0`；若调用返回，不检查其 r0 返回值，随后计数 |

因此，`O[0x1c08]` 至少在这条处理路径上不能命名为“已发送包数”“发送成功数”或“新采样点数”。它记录处理推进；精确业务单位仍须结合其他状态 5 分支和上游输入确认。

## 发送函数只给出本地尝试与错误状态

`0x080122d0` 在调用 framer `0x0801f2d4` 前，先递增 `0x20002264` 的尝试次数、累加 `0x20002260` 的请求字节数，并清零本地错误字节 `0x2000225c`。返回值来自该字节异或 1；错误字节为 1 时还递增另一个计数。

这些累计发生在完整投递确认之前，不是串口对端、主控或云端 ACK。调用者未检查返回值，也不能据此认定发生了实际丢包：错误是否出现、调用是否返回及硬件传输状态均未实测。

## `0x3d` 包的逐字节布局

该分支使用 52 字节工作区，但实际传给发送函数的长度为 **51 字节**：

| 包内偏移 | 长度 | 内容 |
| --- | --- | --- |
| 0 | 1 | opcode `0x3d` |
| 1 | 1 | 零字节；业务名称未指定 |
| 2 | 1 | 常量 `1` |
| 3 | 4 | 对象 `O+0x1c3c` 的原始 32 位值，按大端编码 |
| 7 | 32 | `0x0801ecdc` 按索引 0–7 各取一次，共八个大端 32 位值 |
| 39 | 4 | `O+0x1c34` 的 32 位值 |
| 43 | 4 | `O+0x1c2c` 的 32 位值 |
| 47 | 4 | `O+0x1c30` 的 32 位值 |

最后三项同样按大端编码。第 52 个工作区字节不在本次发送长度内。数值在其他专题中有转换链分析，但本表只登记来源与字节形式，不新赋予单位或通道物理位置。

独立参考格式为 `3d 00 01 + 12 个 BE32`。对原始打包指令和真实 `0x080122b6` 序列化叶函数做有限解释，64 组人工输入逐字节匹配该格式，覆盖发送返回值为 0、1 的两种模型条件；两者均到达同一个计数入口。getter、memset 和发送调用采用明确摘要，不是对完整原厂运行环境的仿真。

## 提前完成条件的一条构造来源

已经找到 `O[0x3d9a] = 1` 的实际写入路径 `0x0801ddbe–0x0801ddc2`。这不是根据类名或标志名称推测。

该局部路径要求 `uint16(H−0xa80) <= 0x7f`，且局部寄存器 r4 为 1；H 是进入该片段时 `[sp+0x20]` 的值。随后还将 `O[0x378c]` 清零。[模式输入与缓存调度](mode-schedule-20261109.md)已将 H 接回固定标识半字、r4 接回配置回调返回值；所建高标识分支的正常退出路径都经过置位，因此上面的局部条件不能当成 B 置位的唯一条件。部署和物理模式仍未确定。

构造器还将 `O[0x3d9a]` 复制到 `O[0x2030]`，使它同时参与本分支可选包的发送条件。运行期其他 writer 和复制后的一致性没有被排除；“初始化时同源”不表示两个字节永远相等。

## 状态 6 消费的是统计门控字节

在已核路径上，状态 6 先执行若干调用，再将 `O[0]` 置为 0，接着更新两组累计：

| 更新条件 | 累计字段 |
| --- | --- |
| 到达该统计段，相关调用正常返回 | `U32(O+0x290) += 本次计时差`；`U32(O+0x28c) += 1` |
| 另有 `O[0x378e] != 0` | 先把该字节清零，再累计 `U32(O+0x298) += 另一计时差`；`U32(O+0x294) += 1` |

`0x08013658` 根据计时对象中的运行标记，取当前值或已保存终值，再减起始值。这里保留“计时差”口径，不换算为实测毫秒。

这为 `0x378e` 提供了具体消费者：它控制是否记入第二组耗时/次数累计。因此可描述为**该统计段的一次性门控字节**，不能将它命名为“云端已收到”“有效生理样本”或“在床”。更广泛的读写用途仍可能存在。
