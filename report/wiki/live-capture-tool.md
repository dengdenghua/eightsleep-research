# 实时采集工具

项目现已提供本地入口：[打开实时采集](http://127.0.0.1:58764/)。它通过国行官方接口登录、列出绑定设备，并按用户选择读取一段 App live 事件；不发送温控、重启或其他设备控制命令。

2026-11-07 核对已通过新界面登录，找到 **1 台 Pod6**，官方返回 `online=false`。因此没有发起真实 live 采集，也没有取得实时样本。**API-01 仍为需要实机配合**；设备上线后再验证。

## 启动与登录

1. 双击项目根目录的 `启动实时采集.command`。需要 Python 3.9 或更新版本，仅使用标准库。保留启动后的终端窗口。
2. 浏览器打开 `http://127.0.0.1:58764/`。在本地页面输入能控制 Pod 的官方 App 账号邮箱和密码，点击“登录并查找设备”。
3. 页面自动列出该账号绑定的设备。核对型号、设备 ID 和在线状态，选择要读取的设备。
4. 如果显示离线，先让设备通电联网，再点击“刷新”。登录成功和找到绑定设备都不表示实时接口已经返回数据。

终端方式与双击启动相同：

```sh
python3 tools/live_server.py --port 58764 --open
```

主报告 `index.html` 仍可完全离线阅读。实时工具在登录、刷新设备和手动开始采集时访问官方服务；页面状态轮询访问本机服务。打开报告不会自动登录或启动采集。

## 读取、检查与导出

选择 **15、30 或 60 秒**后点击“开始采集”。采集不会自动启动；可以提前停止。每次最多接收 **8 MiB、4000 个事件、200000 个样本**，达到时长或容量限制会结束读取。

页面分别显示 HTTP 状态、事件数、样本数、接收字节和最后接收时间。压电预览仅绘制实际收到的 `piezo.samples`，横轴为样本序号，不同事件分段；不把它转换为假定的时间轴或医学波形。

采集结束后：

- **下载 JSONL**：保存事件、原始内容和本地接收时间，用于后续核对重复、缺点和连续性。
- **下载元数据**：保存设备与采集状态、限制和校验信息；失败或零事件也可保留这份记录。
- **清空数据**：释放本地服务内存中的采集记录。需要保留的数据应先导出，再清空或重新采集。
- **退出登录**：结束本地会话。关闭本地服务也会丢失未导出的内存数据。

密码与令牌不写入项目文件，令牌不发送给浏览器前端。登录会话和采集记录仅保留在本地服务内存中；手动下载才生成由浏览器保存的导出文件。客户端配置另行存放，不与账号凭据或采集结果混在一起。

## 响应怎么判断

| 页面结果 | 当前结论 | 下一步 |
| --- | --- | --- |
| 没有绑定设备 | 该账号未返回可选设备 | 核对能控制 Pod 的官方 App 使用哪个账号 |
| 设备离线 | 官方状态尚未显示在线 | 让设备通电联网后刷新，不重复启动读取 |
| 在线状态未知 | 尚未确认当前连接状态 | 可手动做一次短时读取，以实际响应为准 |
| 持续收到 piezo | 该条件下收到压电事件 | 导出并检查数组、时间和连续性；仍需确定频率、单位和通道 |
| 只有 tap/button | 收到实时事件，尚无压电样本 | 保留事件记录，不称为已取得完整波形 |
| 连接成功、零事件 | 建立连接尚未得到传感载荷 | 保存元数据，对照官方 App 流程与测试条件 |
| HTTP 404 | 当前 live 路径没有得到可用响应 | 核对账号、设备与 App 请求；不猜地址、无自动重试 |
| HTTP 401/403 | 登录或访问检查未通过 | 核对当前账号、设备归属，必要时重新登录 |
| HTTP 429 | 服务限制请求 | 停止尝试，工具不会自动重连 |
| 超时或流结束 | 读取已经结束 | 保存已有记录；有事件不等于整段连续完整 |

实时连接的网络建连上限为 10 秒（不超过所选采集时长）；建立网络连接后，等待 HTTP 响应和读取事件由所选的 15、30 或 60 秒总时限控制，不再使用固定 8 秒的读取超时。到达总时限会关闭当前连接，不自动重试。系统休眠和操作系统 DNS 解析可能影响实际结束时间。

诊断与导出元数据包含连接阶段 `phase`（网络与 TLS、发送请求、等待 HTTP 响应、接收事件）和分类错误 `error_kind`，不包含底层异常原文。HTTP 状态为空表示尚未取得响应头；即使设备状态为在线，也不能据此判断 live 请求已成功。HTTP 200 且零事件表示连接成功但没有收到事件，与连接失败分开显示。

8 秒左右结束、HTTP 状态为空、接收字节为零，与旧客户端的固定 8 秒超时相符；仅凭该现象无法确定具体网络阶段，也不能证明设备没有上传数据。当前修正已通过离线模拟验证，实际账号的 live 返回仍需由用户手动采集确认。

当前尚未确定 `samples` 的采样频率、物理单位、通道映射以及是否降采样。App live 也不是设备向云端上传的完整 ADC/IMU raw 流。接口和截取边界见 [实时采集与上传截取](realtime-capture.md)。

## 无 HTTP 响应的排查边界

用户提供的 30 秒采集结果显示：阶段为等待官方 HTTP 响应、HTTP 状态为空、接收字节和事件均为零。该阶段说明客户端已完成网络与 TLS 连接并执行请求发送；不能证明官方应用服务已接收或处理请求。没有响应头时不能归类为 HTTP 401、404 或“HTTP 200 但无事件”，也尚未触及 JSON/SSE 解析。

已核对 APK 的启动链：`TestDriveViewModel.startSensorEventStream` → `$startSensorEventStream$1$1` → `Ja.U` → `Da.K.b` → `Da.E`。该分支直接打开既有 `/live` GET 请求，设置 Bearer 与 `Accept: text/event-stream`，未见额外的启用传感器 HTTP 请求。`A9.k.a()` 返回 `AuthToken.accessToken`，与工具使用的令牌类型一致。此结论只覆盖该启动分支，不排除安装流程其他步骤或服务器状态对数据转发的影响。

下一步先确认官方 App 能否正常控制设备，以及已有传感器检测入口能否收到实时事件；随后对照官方 App 实际请求的地址、请求头、响应状态与首字节时间。不得仅增加等待时间就宣称解决，不用猜测地址或设备写入指令代替证据。网络路径和服务端转发条件仍未确定。

## 换电脑与演示模式

`report/`不放置运行用国行客户端配置，当前默认从本机已有研究目录读取：

```text
~/Downloads/eightsleep-firmware-research-20261107/analysis/account-readonly/auth-flow/client-config.json
```

完整材料中的`research-evidence.tar.gz`保留APK内置客户端参数的研究副本，包含`research/analysis/account-readonly/auth-flow/client-config.json`等索引项；它们与用户密码、令牌和当前会话不同。实时工具不会自动搜索或读取TAR内部文件。

移动到另一台电脑后，需准备并指定运行配置才能登录。可指定已有配置文件；配置内容不应直接展示在网页或正文中：

```sh
python3 tools/live_server.py --client-config /path/to/client-config.json --port 58764 --open
```

`--demo` 用于界面和采集流程验证，页面会显示“演示模式 · 非实机数据”。它不连接官方服务，不需要真实账号，不得将其导出作为设备记录。以下使用独立端口，避免与真实服务混淆：

```sh
python3 tools/live_server.py --demo --port 58765 --open
```

关闭演示服务后，以不带 `--demo` 的正常启动命令使用真实账号入口。
