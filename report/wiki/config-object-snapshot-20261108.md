# nonUSB 配置对象、时钟源与整数除法验证

相关实现与验证见[回调实现、hwrev 标识与上报字段](callback-implementations-20261108.md)；上报对象的完整布局见[上报对象构造链与 0x3e28 布局分区图](report-object-layout-20261109.md)。

本章分析nonUSB硬件版本对应的配置对象写入快照、外设时钟源条件与整数除法辅助函数，给出槽位值、来源指令和有限模型。

全部结论来自冻结 BBIN 的只读字节与既有 Ghidra 工程的 `-readOnly -noanalysis` 导出；没有执行固件、没有联网、没有访问设备或账号。型号/晶振绑定与实机时序仍需要材料或设备，不在本章范围。

## 主要结论

| 项 | 结果 |
| --- | --- |
| 完整配置对象快照 | 台账从「写了哪些槽」覆盖到「每个槽最终写入什么值」：14 个 setter、16 个 hwrev 边界、顶格 **87 个槽位**，每个槽位带具体值、值类型、写入者版本与写入指令地址 |
| 两次内联重放 | K10 的 `bl 0800f968` 重放整个 K00、K33 的 `bl 0800fafc` 重放整个 K05，累加展开后顶格共 **16 次 setter 调用 / 14 个不同分派行** |
| 条件与外部写入 | K34 的 `+0x1a4` 是 `sku == 4` 条件值（`0x08025f08` / `0x08025f00`）；K35 把旧 `+0x194` 备份进 `0x2000135c`；K90 用 `strb` 清 `+0x18c` 单字节 |
| 6 组未导出消费者 | `0800cf10` 给出 **PCLK = SYSCLK >> APB 预分频表** 的条件侧；`0800e8b4` 的四时钟源 × 三掩码矩阵闭合；纠正 **5 个**「消费者」其实是 literal pool 槽位 |
| 除法 helper | 132 条导出指令逐条建模的 Thumb 解释器，**26757 组输入全部等于整数除法**、132/132 指令地址全覆盖，闭合残余项 |
| 末 4 项除数 | `0x408/0x402/0x108/0x101` 是**整字**传给除法 helper，无拆分指令；「打包」只是字节形态观察，不是已证明的功能布局 |

字节核验 **4886 项 0 失败**；四个模型合计 **147 条断言 0 失败**、26757 组除法用例。见 [逐项核验](../analysis-tools/system-deepening/config-object-snapshot/BYTE_VALIDATION.json)、[配置快照](../analysis-tools/system-deepening/config-object-snapshot/CONFIG_SNAPSHOT.json)、[除法结果](../analysis-tools/system-deepening/config-object-snapshot/UDIV_RESULTS.json)、[消费者模型](../analysis-tools/system-deepening/config-object-snapshot/CONSUMER_MODELS.json) 与 [中文结论](../analysis-tools/system-deepening/config-object-snapshot/FINDINGS_ZH.txt)。

## 二、每个 hwrev 的完整配置对象快照

`model/config_snapshot.py` 是逐条指令的 Thumb 常量传播器（`movs / mov / ldr literal / adds / subs / lsls / str / strb / bl`）。配置对象是入口的 `r0`；`movs rX,r0` 建立别名，`adds/subs rX,#imm` 在对象内移动指针，偏移必须累加——这正是手工纠正过的 `+0xfc` 模式，由脚本内建。

| 版本 | 阈值 | 写入数 | 说明 |
| --- | --- | --- | --- |
| I00 | `0x0000` | 62 | 完整默认对象 A |
| I05 | `0x0805` | 6 | 仅名字与少数槽 |
| J00 | `0x0900` | 7 | 新 init + 3 个 RAM 指针 |
| K00 | `0x0A00` | 48 | 完整默认对象 B，大规模重写 |
| K05 | `0x0A05` | 25 | |
| K10 | `0x0A10` | 2 | `bl 0800f968` 重放整个 K00，再改名字与 `+0x164` |
| K30 | `0x0A30` | 10 | |
| K33 | `0x0A33` | 5 | `bl 0800fafc` 重放整个 K05，再改名字 / init / `+0x114` / `+0x118` / `+0x58` |
| K34 | `0x0A34` | 2 | `+0x1a4` 为 sku 条件写入 |
| K35 | `0x0A35` | 2 | 旧 `+0x194` 备份进 `0x2000135c`，再写 `0x08011101` |
| K36 | `0x0A36` | 5 | |
| K37 | `0x0A37` | 2 | `+0x1a4` 改为 `0x08025ee8` |
| K87 | `0x0A87` | 1 | 工程无函数体，原始 Thumb-1 半字解出，只写名字 |
| K90 | `0x0A90` | 2 | 名字 + `strb` 清 `+0x18c` |

**I00 = 62、K00 = 48** 与独立实现的槽位台账完全一致，是两套代码的交叉验证。

累加规则仍是所有 `threshold <= hwrev` 的行按顺序生效。边界集合 = 14 个阈值 + `0x0AFF`（`080108ac` 分支上界）+ `0x0B00`（顶格）= **16 个**；顶格 87 个槽位。快照同时产出 `sku == 0` 与 `sku == 4` 两版。顶格若干关键槽位：

| 槽位 | 最终写入值 | 写入者 |
| --- | --- | --- |
| `+0x0` | `0x08024268`（K90 版本字符串） | K90 |
| `+0x4` | `0x08012275`（init 回调） | K36 |
| `+0x114` | `0x08012d51` | K33 |
| `+0x118` | `0x2710` = 10000 | K33 |
| `+0x164` | `0x08010d39` | K10 |
| `+0x18c` | `0`（单字节） | K90 |
| `+0x194` | `0x08011101`，旧值存入 `0x2000135c` | K35 |
| `+0x1a4` | `0x08025ee8`（K34 阶段是 sku 条件值） | K37 |

每个值都分类为 `thumb_function_pointer`（奇数 flash 指针）/ `flash_data_pointer` / `ram_pointer` / `integer` / `runtime_value`，并保留 `at` 与助记符，可逐条回溯。

> 边界：这是 **setter 写入的值**，不是运行时对象的最终值。分派行之间、分派之后调用的回调（如 `08011100`）可能继续改写 `+0x1a4` / `+0x194`；`devicesn` 分支分析未展开。

## 三、6 组未导出消费者

### 3.1 `0800cf10`：补上时钟源的条件侧

指令级公式：

```
idx   = (reg@0x40021008 >> 12) & 7        # lsls #17 / lsrs #29
PCLK  = DAT_20000250 >> APB_TABLE[idx]    # 0x080241ac, 8 × u32
```

`0x080241ac = [0,0,0,0,1,2,3,4]`；`0x080241cc = [0,0,0,0,0,0,0,0,1,2,3,4,6,7,8,9]` 是已用的 AHB 预分频表。以 64MHz（的条件性计算值）为参数：idx 0–3 → 64MHz，idx 4 → 32MHz，idx 5 → 16MHz，idx 6 → 8MHz，idx 7 → 4MHz。调用点 `0800e91e`、`0800ea14` 都在 `0800e8b4` 内。

这补上了「实机走哪条静态定不了」里其实能由字节定下来的部分：**条件表达式本身是静态确定的，只有寄存器的运行时内容不是**。

### 3.2 `0800e8b4`：四时钟源 × 三掩码矩阵

`0x40021054` 被三处 `ldr r3,[r3,#0x54]` 读取，按 USART 基址选掩码：

| 基址 | 掩码 | 值 0 | 值 1 | 值 2 | 值 3 |
| --- | --- | --- | --- | --- | --- |
| `0x40013800` | `0x03` | PCLK | SYSCLK | HSI16 | 32768 |
| `0x40004400` | `0x0c` | `0x0`→PCLK | `0x4`→SYSCLK | `0x8`→HSI16 | `0xc`→32768 |
| `0x40004800` | `0x30` | `0x00`→PCLK | `0x10`→SYSCLK | `0x20`→HSI16 | `0x30`→32768 |
| `0x40004c00` / `0x40005000` / `0x40013c00` | — | 恒定 PCLK | | | |

四个源分别是 `0800cf10()`（PCLK）、`0800cd24()`（SYSCLK）、literal `0xf42400 = 16000000`（HSI16）、以及 `movs r0,r3` 里的 `0x8000 = 32768`。`param_1[7] == 0x8000` 是 OVER8 标志，决定走 8 倍还是 16 倍过采样；四个源分支各有一处 `movs r3,#0x80 / lsls r3,r3,#8` 构造，实测命中 `0800e916 / 0800e95a / 0800e966 / 0800e9b4`。

> `0800e8b4` 的 `param_1` 是 `0800ec64` 构造的 **USART 配置描述符**，不是 `0801d888` 的 hwrev 配置对象，两者槽位不可混用。

### 3.3 `0x0802420c` 末 4 项：把猜测收窄成字节事实

16 项 u16 = `[1,2,4,6,8,10,12,16,32,64,128,256,0x408,0x402,0x108,0x101]`。末 4 项可拆成 `0x400|8`、`0x400|2`、`0x100|8`、`0x100|1`，但 `0800e974 ldrh r1,[r2,r3]` 后直接 `0800e976 bl 08008174`：**整字作为除数传入，没有任何拆分指令**。因此「疑似预分频 + 过采样标志打包」的猜测分析不予确认，「打包」只描述字节形态。参数化扫描显示：16/64MHz 下 115200 波特率时末 4 项全部不产生合法 BRR（`N < 0x10`），9600 波特率时部分组合合法，故它们不是常规 UART 波特率除数。

### 3.4 5 个「消费者」纠错

| 地址 | 内容 | 真实读取者 | 含义 |
| --- | --- | --- | --- |
| `0800fbcc` | `0x08025ed0` | `0800fbc0` | 外设地址表 A 指针 |
| `0800fdc0` | `0x08025ec0` | `0800fdaa` | `[1,2,4,8]` 掩码表指针 |
| `080125a4` | `0x08025ec0` | `08012538` | 同一掩码表指针 |
| `08012cf0` | `0x08025f28` | `08012b5e` | 8B 尾部索引数组指针 |
| `0800fc00` | literal | `0800fbf4` | literal 槽，非可调用代码 |

五者导出均为 `function=none` 且只有 `REF_TO ... READ`。补导读取者所在函数，共盘点 **12 个真实消费者**（`080110f6`、`0800ea60`、`0800ebf8`、`08020f94`、`08019c90`、`0801273c`、`08012754`、`08012ad8`、`080124f8`、`0800fd94`、`08011100`、`0800cf10`），逐项见 [消费者模型](../analysis-tools/system-deepening/config-object-snapshot/CONSUMER_MODELS.json)。

## 四、`08008174` 除法 helper 指令级有限验证

`model/udiv_exhaustive.py` 从 132 条导出 INSN 逐条解码助记符，实现最小但精确的 Thumb 解释器（`movs/mov/lsrs/lsls/asrs/rev/cmp/subs/adcs/分支/push/pop/bx/bl`），带 N/Z/C/V 标志语义。**不是**把 Ghidra 伪 C 改写成 Python。

| 指标 | 结果 |
| --- | --- |
| 指令地址覆盖 | **132 / 132**，无未执行行 |
| 最大执行步数 | 226 |
| 用例总数 | **26757**（边界交叉 + 20000 组固定种子随机 + BRR 实参） |
| 与 `(a//b, a%b)` 一致 | 全部，0 失败 |
| 除零 | `r0 = 0`、`r1 = a`，路径 `08008272 → 08008274 → 0800845c`（单条 `bx lr`） |

调用约定：`r0` = 被除数、`r1` = 除数；返回 `r0` = 商、`r1` = 余数。这指令级解释器在所列输入上验证商与余数；全部指令地址覆盖不等于所有32位输入组合的数学证明。

## 五、解释约束

1. 候选清单把 5 个 literal pool 槽当成未导出消费者函数，逐个核验 `function=none` + `REF_TO ... READ` 后纠正。
2. 末 4 项除数的「打包」解释未获指令支持，收窄为「整字除数，无拆分」。
3. OVER8 的 `0x8000` 构造是 **4 处**而非 3 处，四个时钟源分支各一处。
4. 矩阵值 3 对应 32768 在路径 A/B 下都成立；早期基于反编译的猜测曾允许 16000000 作为替代，指令级证据排除。

## 七、边界

- 16/32/8MHz HSE 是写入 `0x20000474` 的软件输入，不是实测晶振；64MHz 是条件性计算值（依赖 PLL lock、SW 切换成功、SWS 读回、复位态未被改写、无致命错误）。
- 所有时钟值、波特率、除数索引在都是显式参数；8 个常见波特率常量在 132896B 镜像里仍是 0 命中。
- `0x4000xxxx` / `0x40021054` 等外设寄存器**不命名**：无数据手册或原理图，静态字节只能给地址与掩码。
- 配置对象快照是「setter 写入值」，回调链后续改写不在快照内。
- 仍需材料/设备：通道索引→物理传感通道、波特率与除数索引的实机值、RCC 时钟源实际走向、64MHz 实测、型号/板型/晶振 BOM 绑定、PLL lock 与切换过渡、ADC CLKIN/DRDY 与真实采样率。
- 回调实现、内部三字符标识和上报字段已有对应台账，见[回调与上报字段](callback-implementations-20261108.md)。有界回调前缀、条件栈和块操作不等于完整运行时数据流证明。
