# nonUSB GPIO 描述表、0x10f0 块字段与调用图

前序分析见[上报对象构造链与 0x3e28 布局分区图](report-object-layout-20261109.md)与[回调实现、hwrev 标识与上报字段](callback-implementations-20261108.md)。flash 内调用目标的可达性闭合与 trampoline 簇见[调用目标闭合与 trampoline 簇](residual-target-closure-20261109.md)。本章给出 GPIO 描述表全表解码、`0x10f0` 大块的字段与两个生产者、`08019bac` 嵌套子块、覆盖率空洞内的写入、全镜像 `bl/blx` 调用图与日志格式串映射。

全部结论来自冻结 BBIN 的只读字节与既有 Ghidra 工程的 `-readOnly -noanalysis` 导出；没有执行固件、没有联网、没有访问设备或账号。引脚功能、字段单位与实机时序仍需材料或设备，不在本章范围。

## 描述表 92 行

描述表在冻结镜像里是连续定长数组：行宽 12B，字段依次为端口基址、针掩码、端口用例号。表尾 `0x08028360` 之后第 8 字节已超出端口索引域，因此 92 行是可判定的边界，不是截断猜测。

| 端口基址 | 行数 | 覆盖针号 |
| --- | --- | --- |
| `0x50000000` | 14 | 0..12, 15（缺 13、14） |
| `0x50000400` | 16 | 0..15 |
| `0x50000800` | 15 | 0..5, 7..15（缺 6） |
| `0x50000c00` | 16 | 0..15 |
| `0x50001000` | 16 | 0..15 |
| `0x50001400` | 15 | 0..14（缺 15） |

`port_index` 不是端口表下标：`pin == 15` 的 5 行要额外 `+1`。这 5 行正好是各端口的第 16 针，说明该字段编码的是"用例号"而非索引，读表代码必须按针号特例处理。

引用统计的做法是在 2690 份保留导出里找 `movs r0,#imm` 后紧跟 `bl` 到三个访问器（`0801fdf0` / `0801fdd0` / `08010020`）的模式，得到 27 个被引用的行号与 309 个调用点。引用最多的 5 行是 `id 68`（50 处）、`id 89`（50 处）、`id 80`（32 处）、`id 81`（27 处）、`id 45`（21 处）。

**65 行未被引用不等于无用**：搜索只覆盖 Ghidra 已解码的导出，169 个无函数体的目标里若存在读表代码，其 ID 不会被看到。这条边界写进 `DESCRIPTOR_TABLE.json` 的 `unreferenced` 段。

## `0x10f0` 块：字段与两个生产者

块位于 `param_2 + 0xb08`，长度 `0x10f0` = 4336B，覆盖 `[0xb08, 0x1bf8)`。消费者 `0801c864` 解引用 11 个偏移：

| 偏移 | 宽度 | 语义 | 语句形态 |
| --- | --- | --- | --- |
| `0x0bdc` | object | 等待对象 A | `FUN_080139e4(p+0xbdc, stack, timeout)` |
| `0x0c16` | u8 | 对象 A 复检标志 | `if (*(char *)(p+0xc16) != 0)` |
| `0x0c6c` | object | 通道 A timer | `FUN_080135fa(p+0xc6c)` |
| `0x0ca4` | object | 等待对象 B | `FUN_080139e4(p+0xca4, stack, uVar3)` |
| `0x0cde` | u8 | 对象 B 循环标志 | `while (*(char *)(p+0xcde) == 0)` |
| `0x0d34` | object | 通道 B timer | `FUN_080135fa(p+0xd34)` |
| `0x0d6c` | object | timer，重装 2 | `FUN_080134a8(p+0xd6c, 2)` |
| `0x0d8c` | u32 fnptr | 间接调用槽 | `(**(code **)(p+0xd8c))()` |
| `0x0d90` | object | timer，重装 300000 | `FUN_080134a8(p+0xd90, 300000)` |
| `0x10e8` | u32 | 对象 A 超时/上限 | `*(u32 *)(p+0x10e8)` |
| `0x10ec` | u32 | 对象 B 超时/上限 | `*(u32 *)(p+0x10ec)` |

两个推导细节：其一，`0x10ec + 4 = 0x10f0`，最后一个字段正好贴在块尾，说明 `0x10f0` 是结构体真实长度而非圆整值。其二，`0x0d90` 的偏移不是从 literal pool 读的，而是 `movs r3,#0xd9` + `lsls r3,r3,#0x4`（`0xd9 << 4 = 0xd90`）现场构造；只扫 literal pool 常量会漏掉该字段。

写入侧共 600 条语句、22 个偏移。去重后**只有两个函数写这个块**：

```c
/* 0801d888：主分派 */
puVar38 = param_2 + 0xb08;
FUN_080086a4(puVar38, 0, 0x10f0);   /* 清块 */
FUN_0801c864(puVar38);              /* 消费 */

/* 08027834：同签名姊妹分派 */
puVar38 = param_2 + 0xb08;
FUN_080106a4(puVar38, 0, 0x10f0);   /* 清块，走另一个 helper */
FUN_08026758(puVar38, uVar33);      /* 消费 1 */
FUN_08026810(puVar38);              /* 消费 2 */
```

`08027834` 与主分派同签名、同样按字节偏移访问 `param_2`、同样清 `0x10f0`，但清块走 `080106a4`，并且把块交给两个主分派一次都不调的函数。这三个地址在 Ghidra 里都没有已解码指令（导出只有一行 `TARGET xxxx function=none`），因此只能确认"以 `(块,0,0x10f0)` 形式清零"和"两个消费者拿到块指针"，不能声称其内部行为。

22 个被写偏移中，`0xb08..0xb24` 七个是块头连续标量，`0x1488..0x149c` 六个、`0x16e4/0x17ac/0x1884/0x1894/0x18c4/0x194c` 六个、`0x1bf0/0x1bf4` 两个贴块尾。其余约 4300B 没有任何字段级写入，只被整体清零/复制，结构上保持匿名——与主对象的结论一致。

## `08019bac` 的 `0x250` 嵌套

入口先做 `FUN_080086a4(param_1,0,0x250)`，随后四段子块首尾相接：

| 子块 | 构造者 | 偏移 | 尺寸 | 游标校验 |
| --- | --- | --- | --- | --- |
| 第 1 段 | `0801991c` | `0x000` | `0xc0` | `0x000 == 0` |
| 第 2 段 | `0801991c` | `0x0c0` | `0xc0` | `= 0x000+0x0c0` |
| 第 3 段 | `080190e4` | `0x180` | `0x60` | `= 0x0c0+0x0c0` |
| 第 4 段 | `080190e4` | `0x1e0` | `0x60` | `= 0x180+0x060` |
| 游标 | — | `0x240` | — | `= 0x1e0+0x060` |

`0x240` 是 timer 对象（`FUN_080134a8` 装载），`0x24c` 是 ID 字节：默认 `0x5f`（`_`），`hwrev - 0x980 < 0x80` 时为 `0x4f`（`O`）。`0x24c..0x24e` 三字节之后 `0x24f <= 0x250`，块内不越界。四段零缝隙且游标正好落在 timer 上，是"`0x250` 不是圆整值"的独立证据：任一段尺寸错，游标不会落在 `0x240`。

## 空洞内 81 条写入

前序布局余下 14 个空洞共 4583B（覆盖率 `11297/15880 = 71.14%`）。主分派里落在空洞范围内的标量写语句统计如下：

| 空洞区间 | 字节 | 写入条数 |
| --- | --- | --- |
| `0000..0140` | 320 | 4 |
| `0158..01b8` | 96 | 9 |
| `0234..0258` | 36 | 0 |
| `027c..02a0` | 36 | 0 |
| `1c08..1c0c` | 4 | 0 |
| `2050..2054` | 4 | 1 |
| `218c..219c` | 16 | 5 |
| `224c..2250` | 4 | 2 |
| `2800..37a4` | 4004 | 23 |
| `3a80..3a84` | 4 | 3 |
| `3b44..3b48` | 4 | 1 |
| `3d98..3dac` | 20 | 21 |
| `3ddc..3df8` | 28 | 12 |
| `3e01..3e08` | 7 | 0 |

最大空洞 `0x2800..0x37a4`（4004B）只有 23 条写入、12 个偏移，说明这块基本是数组/缓冲区而非结构体字段区；`3d98..3df8` 两个小空洞写入密度最高（20B 里 21 条、28B 里 12 条），是紧凑的小字段簇。

**有写入见证不等于有布局语义**：这些语句能证明字节被谁写，不能证明它是什么。空洞字节不计入覆盖，覆盖率仍是 71.14%。

## 调用图与函数体可得性

在 2690 份保留导出上统计 `bl/blx`：

| 指标 | 数值 |
| --- | --- |
| distinct 目标 | 2213 |
| 调用边 | 23952 |
| flash 内目标 | 1265 |
| flash 外目标 | 948 |
| flash 内且已导出 | 1166（92.17%） |
| flash 内未导出 | 99 |

692 个单函数导出贡献 2985 条出边、327 个 distinct 目标，其中 96 个仍未导出，是可继续只读导出的直接对象。

函数体可得性必须单独说明：`523` 个目标有 `FUNCTION_BODY`，`169` 个目标只有一行 `TARGET xxxx function=none`，`17` 个是区间导出，`523 + 169 + 17 = 709`。这 169 个在 Ghidra 镜像里没有任何已解码指令（`INSN` 行数为 0），不是导出失败，通常是 thunk/veneer 或从未被走到的代码。补齐它们需要重新反汇编，属于修改 Ghidra 工程，越过只读边界。

调用频次最高的目标依次是 `0x08012754`（1182，日志）、`0x080086a4`（579，memset 包装）、`0x0801c8f8`（560）、`0x08008574`（476）、`0x080138d0`（449）、`0x0801332a`（423）。

## 日志格式串

日志函数 `0x08012754` 在保留导出中共 909 个调用点。对每个调用点向上最多回退 5 条指令找 `ldr r0,[literal]`：809 个（89.0%）解析出字面量，100 个的 `r0` 来自 `movs`/寄存器传递，静态上无法在窗口内确定。可读且含 `%` 的字面量共 156 条，文本互不重复。

## 边界与剩余

1. **169 个无函数体目标**：补齐需重新反汇编（改 Ghidra 工程），不在静态只读范围。
2. **99 个 flash 内未导出目标**：其中 96 个是上述 692 个函数的出边目标，可继续只读导出。
3. **83B 无见证空洞**：`0234..0258`、`027c..02a0`、`1c08..1c0c`、`3e01..3e08`。
4. **`0x10f0` 块约 4300B 字段级语义**：11 个字段只覆盖消费者实际解引用的位置。
5. **`080106a4` / `08026758` / `08026810` 函数体**：与第 1 条同性质。

本章不做：不执行固件、不做动态验证、不接设备、不访问账号或网络；不修改 Ghidra 工程、不重新反汇编、不新增指令；不把描述表引用次数推断成引脚功能；不把空洞写入当作覆盖提升。448 项字节核验与 279 条模型断言全部通过，两组独立计数在 92 行、11 字段、81 条、709 导出、156 字面量上互相吻合。
