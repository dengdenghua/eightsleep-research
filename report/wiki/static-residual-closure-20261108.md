# nonUSB 通道映射、状态字段与 USART 配置

相关实现与验证见[回调实现、hwrev 标识与上报字段](callback-implementations-20261108.md)；上报对象的完整布局见[上报对象构造链与 0x3e28 布局分区图](report-object-layout-20261109.md)。

本章说明nonUSB通道重排表、配置状态字节、14个setter槽位及USART波特率寄存器计算，所有地址和表项均绑定到所列样本。

全部结论来自冻结 BBIN 的只读字节与既有 Ghidra 工程的 `-readOnly -noanalysis` 导出；没有执行固件、没有联网、没有访问设备或账号。型号/晶振绑定与实机时序仍需要材料或设备，不在本章范围。

## 主要结论

| 项 | 结果 |
| --- | --- |
| 三张次级数据表 | 不是未知内容，而是 5 张 **8 字节 0..7 通道重排数组**（去重后 3 种），通过配置对象 `+0x1a4` 指针消费；相邻的还有两张外设地址表、一张掩码表、一张 16 项 USART 除数表 |
| K90 清的 `+0x18c` | 配置对象里一个 **byte 型状态位**，主分派读出后复制到上报对象 `+0x3a80`，`0xff` 是哨兵；hwrev ≥ `0x0A90` 时清零 |
| 14 个 setter 的槽位 | 已建立逐 setter 台账；`+0x114` 起的 0x50 字节是回调/句柄块，`+0x190` 是左右侧回调，`+0x194` 是 post-init 回调；1000ms 超时由主分派装进上报对象，不是配置槽位 |
| `0800e8b4` USART BRR | 两条完整公式 + 范围检查；64MHz / 16MHz 两种时钟源在 115200 下给出相差 **4 倍** 的 BRR，故 RCC 时钟源分支是实质性的 |

字节核验 **5269 项 0 失败**（3448 条导出指令逐字节、1606 条 flash literal、14 行分派表、9 组全镜像指针引用、57 条关键指令锚点、10 条原始 Thumb 半字、8 项负向核验）；模型 **60 条断言 0 失败 / 256 组 BRR 用例**。见 [逐项核验](../analysis-tools/system-deepening/static-residual-closure/BYTE_VALIDATION.json)、[模型结果](../analysis-tools/system-deepening/static-residual-closure/MODEL_RESULTS.json) 与 [中文结论](../analysis-tools/system-deepening/static-residual-closure/FINDINGS_ZH.txt)。

> 表项以冻结镜像的精确字节为准；相同立即数须结合移位宽度和对象基址解释。

## 二、次级数据表的真实内容

| `0x08025ef8` | 8 × u8 | `[3,2,1,0,4,5,6,7]` = **R** |
| `0x08025f00` | 8 × u8 | `[3,2,1,0,4,5,6,7]` = **R** |

## 三、`+0x18c` 的状态位语义与 K90

`0x18c` 由 `movs rN,#0xc6; lsls rN,rN,#1` 构造，全镜像只有三处：

| 地址 | 动作 |
| --- | --- |
| `0x0800f74c` | `strb r1(=1),[0x2000a4c0 + 0x18c = 0x2000a64c]`，后接 `DSB #0xf / DMB #0x1f / SEV` |
| `0x0800fd3a` | `strb r2(=0),[param_1 + 0x18c]` —— K90 setter（row13，阈值 `0x0A90`） |
| `0x0801e68a` | `ldrb r1,[r7 + 0x18c]` —— 主分派 `0801d888`，其中 `r7 = param_1`、`r6 = param_2` |

读出后的流向（`0801e686..0801e6a4`）：

```
r3 = 0xea << 6 = 0x3a80  -> strb r1,[r6,r3]     上报对象 +0x3a80
r2 = 0x8e + 0xff = 0x18d -> ldrb r1,[r7,r2]
r3 = 0x3a81              -> strb r1,[r6,r3]     上报对象 +0x3a81
cmp r1,#0xff             -> 相等则改走 0801ea3e  （哨兵分支）
```

所以 `+0x18c` 是一个被上报出去的 byte 型状态/模式标识，`+0x18d` 是紧邻的第二个字节，`0xff` 是哨兵。K90 把它清零，即 hwrev ≥ `0x0A90` 的板子不再走哨兵路径。

**排歧（纠正）**：同一个 `movs r3,#0xc6` 还有两种不同移位，都不是这个字节：

- `0x0800c6f4 lsls r3,r3,#2` → `0x318`，是 `0800c680` 里的 u32 函数指针槽；
- `0x080153c6 lsls r3,r3,#5` → `0x18c0`，是另一处带 DSB/DMB 的标志写。

另需保守：`0x0800f744` 写的是全局对象 `0x2000a4c0` 的 `+0x18c`，与配置对象 `param_1 + 0x18c` **偏移相同、基址不同**；静态字节不能证明两者是同一字段。K90 setter 与主分派读写的才是同一个 `param_1 + 0x18c`。

## 四、`+0x1a0` / `+0x1a4` 与 hwinfo 条件

主分派里两处读取（`0xd0<<1 = 0x1a0`、`0xd2<<1 = 0x1a4`）：

```
0801e662  r3 = 0x1a0; ldr r1,[r7,r3]; 非 0 -> 0801e670 复制 8 字节
0801e674  r3 = 0x1a4; ldr r1,[r7,r3]; 非 0 -> 0801e682 复制 8 字节
```

两个槽位都是「指向 8 字节表的指针，为空则跳过复制」。K34 setter 的伪代码直接写 `param_1[0x69]`，`0x69 × 4 = 0x1a4`，与字节偏移吻合。

`+0x1a4` 的三个写入者（14 行按 `threshold <= hwrev` 累加，后者覆盖前者）：

| 写入者 | 条件 | 装入的表 |
| --- | --- | --- |
| K34 `0800fcac`（row8，`0x0A34`） | `sku == 4` | `0x08025f08`（T） |
| 同上 | 其它 sku | `0x08025f00`（R） |
| K37 `0800fd16`（row11，`0x0A37`） | 无条件覆盖 K34 | `0x08025ee8`（R） |
| `08011100` 回调 `08011130` | `hwrev == 0x0A35`、`sku == 4`、`devicesn == 0x5150014E` | `0x08025ef8`（R） |
| 同上 | `hwrev == 0x0A35`、`sku == 4`、`(devicesn & ~2) == 0x5150014D` 且 `FUN_080110f6() == 0` | `0x08025ef0`（S） |

sku=0、devicesn 不匹配时的累加结果：`hwrev < 0x0A34` 为 NULL，`0x0A34..0x0A36` 是 `0x08025f00`，`≥ 0x0A37` 被 K37 覆盖成 `0x08025ee8`（K87/K90 不再改它）。`+0x1a0` 在 14 行 setter 里没有任何写入者。

| row | 阈值 | 版本 | callee | 主要写入槽位 |

| 3 | `0x0A00` | K00 | `0800f969` | 48 个（第二个完整默认对象） |

| 5 | `0x0A10` | K10 | `0800fae1` | `0x0, 0x164` |
| 6 | `0x0A30` | K30 | `0800fc05` | `0x0,0x4,0xd0,0x114,0x118,0x160,0x164,0x16c,0x194,0x19c` |
| 7 | `0x0A33` | K33 | `0800fc65` | `0x0, 0x4, 0x58, 0x114, 0x118` |
| 8 | `0x0A34` | K34 | `0800fc99` | `0x0, 0x1a4` |
| 9 | `0x0A35` | K35 | `0800fcc1` | `0x0, 0x194` |
| 10 | `0x0A36` | K36 | `0800fce1` | `0x0, 0x4, 0x158, 0x15c, 0x160` |
| 11 | `0x0A37` | K37 | `0800fd0d` | `0x0, 0x1a4` |
| 12 | `0x0A87` | K87 | `0800fd25` | `0x0`（工程无函数体，原始 Thumb 半字解码） |
| 13 | `0x0A90` | K90 | `0800fd31` | `0x0, 0x18c`（同上，唯一清 `0x18c` 的 setter） |

字符串表 `0x08024234` 的 idx4/5 是 K10/K05，阈值行 4/5 是 `0x0A05`/`0x0A10`（K05/K10），顺序互换，不能按位置硬配。

**偏移归因的坑**：多个 setter 写入前执行 `adds rN,#0xfc`，所以 `str r3,[r4,#0x18]` 实际是配置对象 `+0x114`。台账已把增量累加进去。`+0x114` 正是主分派 `FUN_08020f94(param_2+0x3e28, param_1+0x45, 0x50)` 复制的 0x50 字节块起点——两侧对上了。

高位槽位的消费者语义（来自 `0801d888`，不是猜的）：

| 槽位 | 消费者 |
| --- | --- |
| `+0x114` | `param_1[0x45]` 起 0x50 字节回调/句柄块，整体复制到上报对象 `+0x3e28` |
| `+0x164` / `+0x168` | `param_1[0x59]` / `param_1[0x5a]`，保存的函数指针 |
| `+0x188` | `param_1[0x62]` → `DAT_2000a4b4`，被 clamp 到 ≤ 4（有界计数/模式） |
| `+0x18c` | byte 状态 → 上报 `+0x3a80`，`0xff` 哨兵 |
| `+0x190` | `param_1[100]` side 回调：返回 1 = "right"，否则 "left" |
| `+0x194` | `param_1[0x65]` 可选 post-init 回调 `(config_object)` |
| `+0x19c` | `param_1[0x67]` → 上报 `+0x3df4` |
| `+0x1a0` / `+0x1a4` | 8 字节表指针，非 NULL 时复制 |

「超时」不是配置对象里的独立槽位：主分派用 `param_1[4]` 把上报对象装成 `+0x3e08 = 回调`、`+0x3e10 = 1000`（毫秒）、`+0x3e14 = 1`，并把 `FUN_080099ec() - 1000` 写进 `+0x3e0c` 作为起始时间戳。完整台账见 [CONFIG_SLOTS.json](../analysis-tools/system-deepening/static-residual-closure/CONFIG_SLOTS.json)。

## 六、USART 波特率寄存器重算

`0800e8b4` 由 `0800ec64`（`0800eca6` 处 `bl 0x0800e8b4`）调用。`08008174` 从指令级确认是无符号整数除法 helper（`r0 = param_1 / param_2`，`r1 = 余数`），不再只靠调用点用途推断。

| 配置字段 | 含义 |
| --- | --- |
| `param_1[0]` | USART 外设基址（`0x40013800` / `0x40004400` / `0x40004800` / `0x40004c00` / `0x40005000` / `0x40013c00`） |
| `param_1[1]` | 目标波特率（运行值） |
| `param_1[7]` | 过采样选择（`0x8000` 或其它） |
| `param_1[9]` | `0x0802420c` 表索引；同时写进外设 `+0x2c` 低 4 位 —— 刚好对应 16 项表长 |

时钟来源：`0x0800ea44` 的编译期常量 `0x00f42400 = 16,000,000`（`0800e96c` / `0800e9da`），或 `0800e9ba` / `0800ea20` 两处 `bl 0x0800cd24` 取运行时 SYSCLK（算出 64MHz，条件性计算值）。由 RCC `0x40021054` 位域在 `0800e900..0800e9d8` 分支选择。

两条写入路径（都写 USART `+0xc` 即 BRR）：

```
路径 A（0800e96e..0800e992，16 倍过采样，直接写）
    q   = clock // table[param_1[9]]
    BRR = (q + (baud >> 1)) // baud
    str r0,[USART,#0xc]

路径 B（0800e9dc..0800ea10，8 倍过采样，×2 + 3 位小数）
    q   = clock // table[param_1[9]]
    N   = (2*q + (baud >> 1)) // baud
    BRR = (N & 0xfff0) | ((N & 0xf) >> 1)
    str r3,[USART,#0xc]
```

`0800ea04 lsls r0,r0,#0x1c` 加 `0800ea0a lsrs r0,r0,#0x1d` 实现「低 4 位右移 1」，保证 bit3 恒为 0，符合 8 倍过采样的 BRR 编码要求。范围检查分开执行：路径A检查最终除法值BRR；路径B在编码前检查N。两者要求被检查值位于`0x10..0xffff`，越界返回1。保留模型对路径B曾检查编码后的BRR，超界输入的分类存在已识别限制；其256组给定用例不能替代该边界验证。

参数化取值（**波特率是显式假设输入**：9600 / 19200 / 38400 / 57600 / 115200 / 230400 / 460800 / 921600 作为 4 字节小端常量在 132896B 镜像里全部 0 命中）：

| clock | baud | idx | 路径 A | 路径 B |
| --- | --- | --- | --- | --- |
| 64MHz | 115200 | 0 | `556 = 0x22c` | `0x453`（N=1111） |
| 16MHz | 115200 | 0 | `139 = 0x08b` | `0x113`（N=278） |
| 64MHz | 9600 | 0 | `6667 = 0x1a0b` | `0x3412`（N=13333） |
| 64MHz | 8MHz | 0 | `8`（越界，返回 1） | — |

64MHz 与 16MHz 在 115200 下路径 A 的 BRR 正好相差 4 倍（556 / 139），说明 RCC 时钟源分支不是无关细节。模型枚举 2 时钟 × 8 波特率 × 16 表索引 = 256 组，并验证所有路径 B 编码的 bit3 恒为 0、低 4 位 ≤ 7。

## 八、边界与仍未闭合

- 通道重排表的每个索引对应哪个物理传感通道，需要原理图或实机。
- `param_1[1]`（波特率）与 `param_1[9]`（除数索引）是运行值；上面的 BRR 数值是参数化模型输出，不是镜像常量。
- 64MHz 仍是的**条件性计算 SYSCLK**，依赖 PLL lock、SW=2 切换成功、SWS 读回 `0x10`、复位态未被改写、无致命错误出口；不是实测核心时钟。
- RCC `0x40021054` 是活寄存器，实机走哪条时钟源分支静态定不了。
- `0x2000a4c0 + 0x18c` 与 `param_1 + 0x18c` 同偏移不同基址，未证明同字段；回调/用途名来自消费者调用点，镜像已去符号。
- 型号 / 板型 / 外部晶振 BOM 绑定、PLL lock 与切换过渡、累计 tick 损失、中断延迟、ADC CLKIN/DRDY 与实际采样率，仍需设备测量。
- 核心生理算法、Autopilot、姿态分类、实机绑定、音箱 DSP 依旧不碰。

逐项闭合与残余边界见 [COVERAGE_RESIDUAL.json](../analysis-tools/system-deepening/static-residual-closure/COVERAGE_RESIDUAL.json)。
