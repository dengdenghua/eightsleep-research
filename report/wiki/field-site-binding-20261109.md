# 字段访问的镜像绑定与共享写入路径

本章将既有字段候选接回冻结 g0 的原始字节，区分导出片段相容、真实指令访问和主对象身份。分析不执行固件，不访问设备或账号；原字段台账与模型保持原样。

## 对象绑定的适用范围

[主循环对象与计数状态](main-object-control-20261109.md)已将本文所列主循环位点的 r7 接回调用者传给构造器的栈对象，并确认 `0x1c08` 的自增计数和 3/4 门限。该绑定依赖普通调用的寄存器保存约定及已建控制流范围，不能推广到所有文件或其他函数中名为 r7 的寄存器。

## 已确认的处理行为

冻结 g0 中的 `0x08016162` 为 `strb r2,[r7,r3]`。它不是固定字段的独立 writer：两条可核字节路径给它不同的寄存器值。

| 路径 | 写入顺序 | 随后动作 |
| --- | --- | --- |
| 从 `0x0801615e` 顺序到达 | `r2=0`，`r3=0x1c08`；写 `M8[r7+0x1c08]=0` | `M8[r7+0]=6` |
| 从 `0x08016740` 经跳转到达 | 先写 `M8[r7+0x1c08]=0`；再令 `r2=1`、`r3=0x378e`，由 `0x0801674a` 跳到 `0x08016162`，写 `M8[r7+0x378e]=1` | `M8[r7+0]=6` |

该结果由原始 Thumb-1 编码、PC 相对字面量地址、寄存器编号和分支位移独立计算，共 22 项断言通过。它说明**同一写指令的字段地址取决于到达路径**；仅按“最近一个字面量”或固定代码地址归并字段会丢失路径差异。r7 的主循环来源已有条件性绑定；上游触发条件和两个字节的完整业务含义仍未闭合，不将它们命名为在床、分期或故障标记。

## 字段候选的字节复核

重新读取原台账对应的 114 份导出，精确复现 2609 条候选。逐项比较字面量加载、字面量值、实际寄存器偏移访问指令，以及相应编码中的寄存器编号；采用 g0、USB、legacy、旧 sensor 和 pillow 五份明确基址的镜像。本检查不代替九镜像全文件归属测试。

| 冻结 g0 复核结果 | 导出记录数 | 可支持的范围 |
| --- | --- | --- |
| 字面量加载与访问紧邻，编码、值与寄存器一致 | 769 | 确认该局部路径存在相对偏移访问；不能代替对象身份绑定 |
| 局部字节一致，但加载与访问不紧邻 | 1363 | 仍需核中间的寄存器改写、控制流和调用影响 |
| 编码、字面量或支持形式未通过 | 477 | 不能直接用于冻结 g0 的字段证明；不表示所有条目都是错误导出 |
| **合计** | **2609** | 导出记录含重复，不能当独立函数或访问点数量 |

2609 条记录去重后为 589 个“加载地址、消费者地址、偏移”三元组；g0 紧邻核实部分为 **138 个不同三元组**。它们仍可能共享消费者，不应按消费者地址再次粗暴合并。

原台账按文件路径分组，再以“同文件含至少两个已覆盖偏移”筛出 68 组。这是检索启发式，**不是 68 个函数已证明属于主对象**：例如 `callsites.asm.txt` 混含多个调用点和所有者，文件内共同出现不能证明共用同一个指针。

## 两个字段窗口的修正

### `0x0234–0x0258`：主对象闭合判断撤回

旧台账的两条“已绑定访问”均来自 `sensor-log-producers/pass1/callsites.asm.txt`，实际重复指向 `0x08022504 → 0x08022508` 的 **同一个 `0x24d` 读取**，不是两处独立见证，也没有提供 `0x24e` 的主对象绑定。

该位点的加载与消费者指令不匹配冻结 g0，在 USB 镜像的指定基址下局部匹配，且两者之间另有指令。因此不能继续把它记为冻结 g0 主对象窗口的已闭合证据。

g0 中仍有 `0x24d/0x24e` 局部访问，涉及 `0x08019bac` 的子对象构造等路径；子对象内偏移与主对象绝对偏移须分开。保留候选，撤回“仅靠同文件偏移交集即完成主对象绑定”的判定。

### `0x1c08`：四个 g0 局部位点得到保留

七条旧记录中六条匹配 g0，但重复后为四个局部位点；另一个位点 `0x0801ff58 → 0x0801ff5a` 匹配 USB 镜像，不匹配冻结 g0。

| 字面量加载 → 访问地址 | g0 中可核运算 |
| --- | --- |
| `0x08016160 → 0x08016162` | 路径上加载 `0x1c08`，执行字节写；消费者还接收另一条偏移不同的路径 |
| `0x08016546 → 0x08016548` | `ldrb r5,[r7+r3]`，`r3=0x1c08` |
| `0x08016712 → 0x08016714` | `ldrb r1,[r7+r3]`，`r3=0x1c08` |
| `0x08016742 → 0x08016744` | `strb r3,[r7+r2]`，`r2=0x1c08`；所核路径中 `r3=0` |

这些是相对 `r7` 的真实读写证据，不等于四字节窗口全部被解释，也本表自身不单独证明 `r7` 就是报告主对象，须结合上面的调用者绑定。`0x027c–0x02a0` 的唯一旧候选也不匹配冻结 g0；`0x3e01–0x3e08` 在该候选集中仍无记录。其他窗口未由本检查重新验收，故不发布新的“14 个空洞完成率”。

## 后续逆向目标

1. 已列主循环位点结合调用者建立条件性绑定；其他文件与函数仍须各自追对象来源，不能按寄存器名迁移结论。
2. 为 `0x08016162` 枚举其余直接分支与计算入口，按到达路径记录 `r2/r3`，建立具体写入值及目标偏移，而非单一 writer 标签。
3. 对 1363 条不紧邻候选做去重及寄存器活跃性分析；跨调用和跨分支者单列，不直接升级为字段见证。
4. 对 USB 中的 `0x24d` 使用其自身调用者与构造器建立对象归属；不能移植回 g0 的主对象空洞。
5. 只有对象基址、构件版本和实际访问均闭合后，再解释字段业务含义及其对采样或上报的影响。
