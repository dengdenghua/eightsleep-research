# 主循环对象绑定、8 位计数与状态切换

本章从冻结 `firmware-sensor-g0.bbin` 字节恢复调用者栈对象、字段计数和共享写入路径。结论适用于指定构建与所列正常调用约定；未观测实机执行，也不将该控制计数解释为心率、在床或睡眠指标。

## 对象来源已接回调用者

入口 `0x080152d8` 先保存五个寄存器，再分配 `0x41a4` 字节局部栈空间。令分配后的 SP 为 S：

```text
0x080152e8: r7 = S + 0x31c          # 对象 O
0x080152ee: r1 = r7                # 第二个参数是 O
0x080152f0: r0 = S + 0x11c         # 配置区
0x080152f2: bl 0x0801d888           # 既有对象构造器

构造器入口 0x0801d8a4: r6 = r1    # 在构造器内用 r6 持有对象
主循环后续: 使用 r7 相对偏移访问 O
```

从 O 到该局部栈分配区末端的空间为 `0x41a4−0x31c=0x3e88`，恰好等于既有布局分析由写入得到的下界。它加强了调用者与布局的对应，但仍不是 C 类型的 `sizeof` 证明。

从上述入口建立的有限控制流图包含 2725 条指令，处理三处明确的半字跳转表。在该图内，`r7` 的显式写入只有 `0x080152e8`。因此，在普通调用遵守寄存器保存约定、所建控制流成立的条件下，已核主循环字段访问可以绑定到传给构造器的这个对象。被调用函数、ISR、所有间接入口与路径可行性没有由该图全部证明。

## `0x1c08` 是计数字节，不能再称简单标记

`0x08016712–0x0801671a` 的真实运算为：

```text
c = uint8(O[0x1c08] + 1)
O[0x1c08] = c
```

加载、加一、`UXTB` 截断和字节写回均有原始指令。故 255 加一会回到 0；这描述数值类型，不表示正常部署一定会发生溢出。

随后读取 32 位门限 `N = U32(O+0x37a0)`，执行无符号比较；另读字节 `B = O[0x3d9a]`：

```text
若 c < N 且 B == 0：跳到 0x08016ca2
否则：
    O[0x1c08] = 0
    O[0x378e] = 1
    O[0] = 6
```

`B` 的业务含义、计数单位及中间工作的物理对应仍未知，保留字段名与条件表达式。

## 构造器选择的门限为 3 或 4

构造器在 `0x0801df82` 读取 `O[0x378c]`：

| 构造路径条件 | 写入 |
| --- | --- |
| `O[0x378c] == 0` | `U32(O+0x37a0) = 3`，位于 `0x0801e6b4–0x0801e6b8` |
| `O[0x378c] != 0` | `U32(O+0x37a0) = 4`，位于 `0x0801df9c–0x0801dfa0` |

这些是已核构造路径，不是对全部运行期 writer 的排除证明。在计数初值为 0、B 为 0、门限保持不变且反复执行该计数步骤时，第 3 或第 4 次分别走完成分支。不能由此推导采样率、真实分组时长或睡眠算法窗口。

## 主循环状态与共享 writer 的关系

`0x08015810` 读取 `O[0]`。索引 0–6 在 `0x08015820` 的半字表中对应：

| 状态索引 | 目标地址 |
| --- | --- |
| 0 | `0x08015cba` |
| 1 | `0x080163be` |
| 2 | `0x08016230` |
| 3 | `0x080162f4` |
| 4 | `0x080160a2` |
| 5 | `0x08016470` |
| 6 | `0x08016cb6` |

状态 6 的已解片段包含多个调用，之后在 `0x08016d0e` 将 `O[0]` 写为 0；完整副作用、调用是否返回和外设效果仍须逐项追踪。状态值超出 0–6 的处理没有据此验收为安全。

共享写指令 `0x08016162` 在所建图中有两个直接前驱：`0x08016160` 与 `0x0801674a`。前者先加载偏移 `0x1c08`；后者带着偏移 `0x378e` 跳入，分别执行清零与置一。此结论不排除图外或动态入口。不能再为这个指令地址固定命名为某一个字段的 writer。

- 54 项字节、指令、常量与控制流断言通过。
- 独立脚本不导入分析器或 Capstone，按选定 Thumb-1 原始指令解释 6912 组人工内存输入，核对计数、完成条件、两个字段和状态值。
