## 自动上传与 live 订阅

设备启动后自行采集并上传。项目本地页面的“开始采集／重新采集”只读取云端 live 事件，不启动床垫采样；官方 App 无需有同名按钮。

用户确认官方 App 可正常调温。在线状态和控制可用尚不能证明 raw 上传正常或 live 转发已建立。设备手势的筛选、断线行为及无鉴权 HTTP 对照见 [实时事件路由与连接边界](live-event-routing.md)。

## 实时读取与结果判定

1. 确认 App 中绑定的是这台 Pod，记录 App/设备版本及在线状态，并用正常控制操作确认连接。
2. 在本地工具刷新并选择设备，在已有 30 秒无响应记录的条件下，可限定一次 60 秒观察。工具按已恢复的GET `/v1/devices/{deviceId}/live`契约读取，记录HTTP状态、接收时间和事件；可导出JSONL与元数据，报告不收录凭据。
3. 先看是否收到 piezo、tap 或 button，以及消息是否持续更新。必要时对照官方 App 已有安装检测页面的请求；进入页面前先核对操作是否会改变设置，不为测试重置或重新配对设备。
4. 收到 piezo 后保存 samples、timestamp、数组长度和消息间隔，并做短时静止、翻身、轻触对照。服务器时间与本地接收时间分别保留；不以 App 进度条变化次数计算新样本数。

| 观察结果 | 能说明什么 | 下一步 |
| --- | --- | --- |
| 持续收到 piezo.samples | 该账号、设备和测试状态下能接收压电事件 | 检查连续性、重复、缺点和响应；确认是否降采样或仅用于检测，暂不认定完整原始波形 |
| 只有 tap/button | 实时事件通道可用 | 核对安装检测流程和事件类型；不能认定能读取压电或 IMU |
| 连接成功但没有事件 | 连接已建立，尚未获得传感载荷 | 在限定观察时段内对照 App 行为；仍无消息则记录条件，不能据此判断传感器故障 |
| 开机在线后仍为 404 | 关机不是当前失败的充分解释；具体原因仍未知 | 核对账号、deviceId、主机和 App 实际请求，一致后停止重复请求，保留服务端条件缺口 |
| 401/403 | 请求未通过鉴权或访问检查 | 核对当前登录及设备归属，不把它误判为采样故障 |

开机验证的目标是先确认“能否接收、接收什么”。只有连续性、单位、通道及处理方式获得证据后，才能决定这些数据能否作为后续算法逆向输入。

## 可选路径

| 路径 | 已确认 | 还缺什么 |
| --- | --- | --- |
| App `/v1/devices/{deviceId}/live` | Bearer 鉴权，事件解析包含 piezo.samples、timestamp、tap、button | 国行实机成功响应；既有请求曾返回 404，原因未知；samples 的单位、频率和通道含义未定 |
| 主控本地 NATS | 发布配置监听 127.0.0.1:4222，raw.> 映射为 rawmem.> | 主控本地访问与生效配置；同一 Wi-Fi 不足以接入 |
| 设备到云端抓包 | CBOR 批次经裸 DEFLATE、TLS 上传；已恢复上传、压缩参数与 ACK 协议 | TLS 明文观察能力；路由器被动抓包只能取得加密载荷与连接信息 |

设备压缩参数、分块门限与明文解析方法见 [压电原始上传](raw-wire-format.md)。

App live 与设备 raw 上传不是同一个接口。拿到 live 的 samples，也不能立即认定取得了完整 ADC/IMU 数据。普通账号凭据也没有被证明能用于下载 raw 上传流。

## 下一步怎么做

1. 设备已在线且 App 可调温，优先取得上面限定时长读取的元数据，并对照官方 App 实际 live 请求。记录原始消息和状态；若仍是 404，核对与 App 请求一致后停止重复请求，不能靠猜参数认定解决。
2. 若收到 piezo，保存 timestamp、samples 原始数组和接收时间；检查长度、间隔、缺点与重复。以静止、翻身、轻触做短时对照，勿把界面计时重放计为新采样。
3. 若 live 数据不足，再取得主控本地访问，核对镜像、监听地址和实际主题，设计独立旁路订阅，保存未经重新编码的 CBOR。保留生产上传器的 consumer 与 ACK 状态，不修改其消息消费流程。
4. 校验侧别、数组形状、时间、增益和缺值，再研究样本能否支持分离、心搏检测和 HRV。只取得压电变化曲线不代表已恢复算法输入全貌。

## 当前限制

设备已开机并由用户完成在线查询与 live 读取尝试；30 秒读取尚未取得 HTTP 响应头或实时事件，失败边界在事件解析之前。当前尚无主控本地访问和实时波形。发布配置不等于当前实机配置；原始数据出口与App live之间的服务器转发、降采样或聚合实现仍缺。

## 原始数据保留窗口：代码证据

本包新建RAM流使用`discard=old`，超额会删除最早消息；已识别的转存磁盘由停止钩子触发。因而实时截取宜在取得本机访问后尽早保存，不能依赖“磁盘配置24小时”事后补回全天波形。实际保留时长还需设备额度、数据速率和stream info。

另外，extADC特定分支虽然准备四组内存数组，线上CBOR仅包含两组。截取成功后仍应按实际topic、flags和布局判断拿到了哪些数据。[缓存满载证据](../evidence/analysis/finishable-20261107/raw-upload/RAW_02_FINDINGS_ZH.txt) · [输出与编码模型](../evidence/analysis/finishable-20261107/host-model/FINDINGS_ZH.txt)
