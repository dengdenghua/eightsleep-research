============================================================
一、结论置顶
============================================================

按上一条盘点建议 1 → 2 → 3 执行，并把 A 类剩余项一起收口。七项闭合：

  1. 描述表 0x08027f10 全 92 行解码完成。行宽 12B，字段为
     [port_base u32, mask u32, port_index u32]，表尾 0x08028360 之后
     第 8 字节已不属于端口索引域，边界可判定。92 = 6 端口 × 16 针 - 4 缺针。
  2. mask 是一位一编码：mask = (pin << 16) | (1 << pin)。高 16 位存针号，
     低 16 位存位掩码。92 行逐行通过该恒等式，无例外。
  3. port_index 不是端口表下标而是「用例号」：pin==15 的 5 行要额外 +1。
     规则 port = ports.index(port_base) + (1 if pin == 15 else 0) 对 92 行全成立。
     pin==15 的是第 13/29/44/60/76 行，即 5 个端口的第 16 针。
  4. 0x10f0 大块从「一处 memset」升级为「11 字段台账」。消费者 0801c864
     只解引用 11 个偏移，其中 10 个由 literal pool 提供常量、0xd90 由
     movs r3,#0xd9 + lsls r3,r3,#0x4 现场算出（不是字面量，这是它在前一轮
     被漏掉的原因）。0x10ec + 4 = 0x10f0，尾部严格对齐。
  5. 该块有第二个生产者：08027834。它是与主分派 0801d888 同签名的姊妹分派，
     同样做 puVar38 = param_2 + 0xb08、同样清零 0x10f0，但清块走 080106a4
     （Ghidra 无函数体），并且把块交给 08026758 / 08026810 两个消费者——
     这两个函数 0801d888 一次都不调。这三个地址都是本轮 pass7 新导出的。
  6. 08019bac 的 0x250 嵌套是零缝隙。0x000/0x0c0 两段 0xc0 由 0801991c 构造，
     0x180/0x1e0 两段 0x60 由 080190e4 构造，游标正好走到 0x240，之后是
     timer 对象 + 0x24c 的 ID 字节（默认 0x5f '_'，hwrev-0x980 < 0x80 时 0x4f 'O'），
     0x24f ≤ 0x250，块内无越界。
  7. 覆盖率空洞内的标量写入已台账化：14 个空洞共 4583B，81 条写入落在其中
     10 个空洞；剩 4 个空洞（0234..0258 / 027c..02a0 / 1c08..1c0c / 3e01..3e08，
     合计 83B）无任何写入见证。

硬数字：448 项字节核验 0 失败、279 条模型断言 0 失败、709 份只读导出
（17 个区间 + 692 个单函数）、116192 条 INSN 逐字节比对 0 失配。

============================================================

表结构（冻结镜像逐字节读出，非推测）：

  基址 0x08027f10   行数 92   行宽 12B   表尾 0x08028360
  字段1 port_base   u32       6 个取值，间距 0x400
  字段2 mask        u32       (pin << 16) | (1 << pin)
  字段3 port_index  u32       0..5，pin==15 时为下标 +1

  ports = 50000000 50000400 50000800 50000c00 50001000 50001400

  端口基址      行数  覆盖针号（缺针标 -）
  0x50000000    14    0..12,15     缺 13,14
  0x50000400    16    0..15        无缺
  0x50000800    15    0..5,7..15   缺 6
  0x50000c00    16    0..15        无缺
  0x50001000    16    0..15        无缺

  14 + 16 + 15 + 16 + 16 + 15 = 92 = 96 - 4

pin==15 的 5 行落在第 13 / 29 / 44 / 60 / 76 行，即每个端口的第 16 针；

0..5 的下标而是 0..5 的用例编号，读表时必须按 pin 特例处理。

  引用调用点     309 处
  未被引用       65 行（70.65%）

    id 89  port5 pin12  50 处

    id 81  port5 pin4   27 处

  0x0cde   u8          对象 B 的循环继续标志                      while (*(char *)(p+0xcde) == 0)

两条推导细节：

  1. 0x10ec + 4 = 0x10f0。最后一个字段正好贴在块尾，说明 0x10f0 不是
     「往大了取」的圆整值，而是这个结构体的真实长度。
  2. 0x0d90 的偏移不是从 literal pool 读的，而是
     movs r3,#0xd9 / lsls r3,r3,#0x4（0xd9 << 4 = 0xd90）现场构造。
     上一轮只扫 literal pool 常量，因此漏掉这一个字段。

写入侧（param_2 + 0xb08..0x1bf8 范围内的写语句）：

  写语句总数      600 条
  涉及偏移        22 个
  导出份数        20 份
  目标地址        16 个
  所属函数        2 个：0801d888、08027834

两个生产者：

  0801d888（第七轮主分派）
      puVar38 = param_2 + 0xb08;
      FUN_080086a4(puVar38, 0, 0x10f0);      清块
      FUN_0801c864(puVar38);                 消费

  08027834（本轮 pass7 新导出，位于 sensor-frame-bounds 轮的导出集）
      puVar38 = param_2 + 0xb08;
      FUN_080106a4(puVar38, 0, 0x10f0);      清块（走的是另一个 helper）

080106a4 / 08026758 / 08026810 三个地址的导出都只有一行 TARGET
function=none，即 Ghidra 在该地址没有已解码指令。因此只能确认

不能声称知道它们的内部行为。这是本轮唯一新增的、需要明确标注为

两个贴着块尾。其余约 4300B 没有任何字段级写入，只被整体清零/整体复制，
结构上保持匿名——这一点与第八轮对主对象的结论一致，不因为本轮多了解

四、08019bac 的 0x250 嵌套
============================================================

  FUN_08019bac 入口先做 FUN_080086a4(param_1, 0, 0x250)。

  子块              构造者        偏移      尺寸    游标校验
  第 1 段           0801991c      0x000     0x0c0   0x000 == 0
  第 2 段           0801991c      0x0c0     0x0c0   0x0c0 == 0x000+0x0c0
  第 3 段           080190e4      0x180     0x060   0x180 == 0x0c0+0x0c0
  第 4 段           080190e4      0x1e0     0x060   0x1e0 == 0x180+0x060
  游标结束                        0x240             0x240 == 0x1e0+0x060

  0x240             timer 对象（FUN_080134a8 装载）
  0x24c             ID 字节：默认 0x5f '_'，hwrev-0x980 < 0x80 时 0x4f 'O'
  0x24d..0x24e      同一 ID 尾部的 2 字节
  0x24f             ≤ 0x250，块内不越界

四段零缝隙 + 游标正好停在 timer 上，是「0x250 不是圆整值」的独立证据：
若某段尺寸错，游标不会落在 0x240，而会落在 timer 中间。
