二、旧清单其余“看起来未闭合”的项目 [Q2–Q5]

Q2. 00207cf0的间接跳转警告仍未消除，但它不构成一个已定位的生理候选。
输入是Sensor对象和状态整数；函数记录stateChange、写状态字段、停计时器；0/1/2分支涉及disconnectSensor、重置串口、power cycle、reboot。未恢复的0x00207fd0位于“旧state=0、新state=2”的reboot分支，给虚方法的参数是固定全局命令对象PTR_DAT005dfe80，不是采样数组。现有调用者在refs中为00208180/002082a4/00208390。
本轮不宣称已经恢复该虚方法全部实现，也不宣称其下游绝无任何计算；但没有证据把复位分支升格为多通道压电HR/RR入口，因此不为追算法而重新扩展这套设备状态机。
证据：physiology/seeds/00207cf0.c:18–66、:73–149；同名.refs.txt。

Q3. 001fd6d0的未知tail-call，在本次piezo调用上下文已由vtable限定。
现有伪代码在方法地址!=001f02b0时才走未知虚调；已审caller的vtable0058eb48+0x10恰为001f02b0，走逐16-bit值编码分支。它是CBOR封装的多态扩展口，不是一个已发现却漏追的频谱/滤波器。其他未枚举调用者或运行期改表不能由此一概排除。
证据：physiology/trace6/001fd6d0.c:15–38；同名.asm.txt:8–22、:38–42；physiology/selected-data-pointers.txt:1–3。

Q4. 原002097a0分派缺口已解决，不能再作为“可能有算法藏在缺失分支”的同一待办。
physiology/legacy-fixed/002097a0.c是有界39槽jumptable修复后的版本，旧trace2导出只覆盖前段，不能作为最终分析。已恢复的16-bit piezo、extADC、capSense/capSense2分支均有接收→缓冲→原始CBOR出口。这个覆盖只针对已恢复分支，未推论所有未识别入口。
证据：LOCAL_PHYSIOLOGY_AUDIT.txt第二至四节；scripts/FixLegacySensorSwitch.java；physiology/legacy-fixed/function-index.txt。

三、剩余覆盖边界与真正阻塞

1. 已有Stealth路线的输入是0x3c内ADC/IMU原始数值，消费者已追到单/双侧loader、CBOR编码和raw NATS发布；时间补点、sentinel、gain名义元数据和缺槽处理不是HR/RR/睡眠结果。ADC0..7在已审loader未输出也不等同没有采样或没有任何别的消费者。
2. 当前没有来自Frank的可核对HR/RR/HRV/睡眠阶段结果schema、结果publisher或模型入口地址。缺失的是“可以从具体值/引用反向追到算法”的锚点，不能用重复搜索无意义filter/quality词弥补。
3. 未穷尽全部12,869函数、所有间接调用/外部共享库、其他进程和运行时订阅者；静态xref不是完整动态调用图。已审原始数据路径不生产所问结果，不代表整个系统没有实现。
4. MCU前端DSP、按键/旧tap计算与云端算法是不同样本/层级；本报告不拿它们填充Frank本地生理推理证据。也不从MT8365推断Pod代际或SKU。
5. 后续若有同版本具体结果字段/订阅者、模型加载路径、尚未审计而确定消费波形的函数地址，可从该锚点继续；当前不需要请求账户、不主动扩大云API、不运行目标固件。此处是证据边界，不是工具失效或需要用户授予权限。
