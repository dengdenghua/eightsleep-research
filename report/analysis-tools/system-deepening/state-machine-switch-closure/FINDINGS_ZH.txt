============================================================
一、结论置顶
============================================================

之前称为 trampoline/case 链的六组「ldr 字面量 → bl」并不是 switch 的
分支。真正的 switch 在 08016fd0：

  ldrb r0,[r6,#0]       ; 状态 0..4
  cmp  r0,#4
  bls  08016fd8
  b    08016e22         ; 状态 >4，丢弃该字节
  08016fd8: bl 08008484 ; __gnu_thumb1_case_shi
  08016fdc: 5 个 int16 跳转增量

跳转表 10 字节：3a ff 4a ff 60 ff 76 ff 7c ff
增量：-0xc6, -0xb6, -0xa0, -0x8a, -0x84
目标：08016e50, 08016e70, 08016e9c, 08016ec8, 08016ed4

五个目标全部落在 Ghidra 未解码的字节段里：08015e00..08017000 的导出
有 496 条 INSN，但这五个入口一条都没有。它们没有直接 bl 调用，只能
经 08016fdc 的表进入。这是此前「分支归属未知」的直接原因。

五个状态构成一个带字节填充的帧解析器：

  状态 0  等帧标志，重置累加器，进入状态 1
  状态 1  构造 32 位字节道掩码（每道写入 0x01）
  状态 2  把净荷字节复制到缓冲区，直到计数/上限
  状态 3  把下一字节作为 16 位尾值的高字节
  状态 4  合并尾值低字节，调用 0800a578，与返回值比较

硬数字：
  - 跳转表 5 项，5 个状态，5 个 handler 入口
  - 状态 0..3 共 132B，90 条已解码指令（88 条线性和 2 条冷尾）
  - handler 内 19 处 LDR 字面量，落到 10 个全局字段
  - 90 项独立字节核验 0 失败；89 条模型断言 0 失败

============================================================
二、为什么六组不是 case
============================================================

六组「ldr 字面量 → bl」位于序列化/日志路径上：

  08016e02 -> 08015f08   -1.0f 默认值
  08016e08 -> 08015f28   清 bit 23 掩码
  08016e0e -> 08015f46   清 bit 23 掩码
  08016e14 -> 08015f64   清 bit 23 掩码
  08016142 -> 08012754   日志格式串
  08016f18 -> 080134be   RAM 地址参数

四组常量装载的入口条件分别是 08015f02 / 08015f22 / 08015f40 / 08015f5e
的零值判断。它们把默认值放进寄存器后跳回序列化续点，属于冷路径默认值
materializer，不是 switch 分支。真正的 switch 只有上面 08016fdc 的 5 项。

分类修正已写入 SWITCH_TABLE.json 的 reclassification 段。

============================================================
三、五个 handler
============================================================

状态 0（08016e50，32B，16 条）
  cmp r2,#1
  bne 08016e22             ; 不是 0x7e 帧标志就忽略
  strb r2,[r6,#0]          ; 状态 := 1
  清零：
    2000a4a8               ; 复制索引
    *2000a4ac              ; 通过指针清零
    2000a4b0               ; 16 位尾值累加器
    2000a4b8               ; 道索引
    2000a4bc               ; 道掩码累加器

状态 1（08016e70，44B，22 条）
  r0 = [2000a4b4]          ; 道计数
  r2 = [2000a4b8]          ; 道索引
  r1 = (r0 - 1 - r2) * 8
  r3 = 1 << r1             ; 每道一个 0x01 字节
  [2000a4bc] |= r3
  [2000a4b8] += 1
  索引到计数后：
    *[2000a4ac] = 掩码
    状态 := 2

状态 2（08016e9c，44B，20 条 + 2 条冷尾）
  r1 = [2000a4a8]          ; 复制索引
  r4 = [2000a4a4]          ; 复制上限
  r1 >= r4 -> 08016ec4
  r4 = [2000a4a0]          ; 缓冲区指针
  [2000a4a8] = r1 + 1
  buffer[r1] = 当前字节
  if [2000a4a8] == *[2000a4ac] -> 状态 3
  08016ec4 冷尾：str r0,[r6,r2]；b 08016eb0

状态 3（08016ec8，12B，6 条）
  状态 := 4
  [2000a4b0] = 当前字节 << 8

状态 4（08016ed4，线性前缀 24 条）
  [2000a4b0] |= 当前字节
  r0 = 2000070c            ; sink/writer 对象
  r1 = [2000a4a0]          ; 净荷缓冲区
  r2 = [2000a4a8]          ; 字节计数
  bl 0800a578
  if sxth(返回值) != [2000a4b0] -> 回队列循环
  匹配后读取 2000230c 状态字节：bit7 为门控，低 7 位为代码
  后续分派转到 08016f06 或 0801710c，未在本轮闭合

0800a578 的确切语义尚未完全解析。已确认它把一个 sink 对象、缓冲区指针和
字节计数作为参数，按对象模式流式写入，并返回最后一个字。这里只能记录
「状态 4 把它的返回值与 16 位尾值比较」，不能断言它就是校验和。

============================================================
四、帧格式与队列对象
============================================================

队列对象基址 2000240c：

  +0x00  帧状态 0..4
  +0x04  传输读取回调
  +0x08  64 字节输入缓冲区
  +0x48  已填充字节数 / head
  +0x4c  已消费索引 / tail
  +0x50  转义标志

取数逻辑 08016fe6：
  r3 = [r6+4]              ; 回调
  r1 = 0x40
  r0 = 20002414            ; r6+8
  blx r3
  [r6+0x48] = 返回值
  [r6+0x4c] = 0

字节填充规则：
  [r6+0x50] = 转义标志
  标志为 0 且字节 == 0x7d：标志 := 1，继续
  标志为 1：标志 := 0，字节 ^= 0x20
  字节 == 0x7e：状态 := 0，并以「帧标志」身份进入状态 0
  状态 >4：字节丢弃

0x7e 帧标志、0x7d 转义、转义后 XOR 0x20，是 PPP/HDLC 风格异步字节
填充的标准组合。状态 0 只在 0x7e 到达时执行重置，这与帧起点语义一致。

============================================================
五、全局字段
============================================================

  2000a4a0  净荷缓冲区指针
  2000a4a4  净荷复制上限
  2000a4a8  净荷复制索引
  2000a4ac  指向道掩码/完成值的指针
  2000a4b0  16 位尾值累加器
  2000a4b4  道计数
  2000a4b8  道索引
  2000a4bc  道掩码累加器
  2000070c  传给 0800a578 的 sink/writer 对象
  2000230c  状态字节，bit7 门控，低 7 位代码
  2000a498  前序已记录的等待/定时对象，与状态 4 的路径相邻

这些地址都由 19 处 LDR 字面量独立解析：
  2000240c + {0x8094,0x8098,0x809c,0x80a0,0x80a4,0x80a8,0x80ac,0x80b0}
  外加绝对地址 2000070c、2000230c。

============================================================
六、边界
============================================================

1. 覆盖率为块级口径，不因本状态机提升。
2. 0800a578 的参数顺序已定位，返回值比较已定位，但它内部模式 1/2/3 的
   具体语义仍未闭合，因此不把尾值称为校验和。
3. 状态 4 匹配后对 2000230c 低 7 位代码的处理只追到 08016f06 / 0801710c
   两个入口，没有继续展开到函数尾部。
4. 状态 2 有一个 BCS 冷尾（08016ec4），已单独列出，不与线性前缀混淆。
5. 2000a4** 是 RAM 地址，flash 中没有初值；各字段的运行时初始化点仍需
   从其它写者追。
