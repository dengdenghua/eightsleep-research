════════════════════════════════════════════════════════════
一、结论置顶
════════════════════════════════════════════════════════════

上一轮明确留下的四项静态缺口，本轮全部闭合：

1. 三张次级数据表不是「未知内容」，而是 0..7 的 8 字节通道重排数组；
   与之相邻还有两张外设地址常量表、一张位掩码表和一张 USART 除数表。
   全部 9 个指针引用点在 132896B 镜像里都有唯一命中集。
2. K90 清的 `+0x18c` 是配置对象里的一个 **byte 型状态位**：
   主分派函数把它读出来复制到上报对象 `+0x3a80`，`0xff` 是哨兵值。
   K90（hwrev ≥ 0x0A90）把它从非 0 改成 0。
3. `+0x1a4` 是**指向 8 字节通道重排表的指针**（`u32` 索引 0x69），
   由 K34 / K37 / `08011100` 三处按 hwrev、sku、devicesn 条件装入；
   `+0x1a0` 是同类指针但 14 行 setter 都不写它。
4. `0800e8b4` 的 USART 波特率寄存器已按指令级重算出两条完整公式、
   范围检查和 256 组参数化取值；**64MHz 与 16MHz 两种时钟源给出相差 4 倍
   的 BRR**，因此 RCC 时钟源分支的选择是实质性的。

同时产出了 14 个 setter 的配置对象槽位台账，把此前含糊的「回调/超时槽位」
落到具体偏移与消费者上。

二、次级数据表与引用点（闭合项 1）
════════════════════════════════════════════════════════════

内存布局（VA → 文件偏移 = VA - 0x08008000）：

  0x08025ec0  4 × u32   [1, 2, 4, 8]                      位掩码表
  0x08025ed0  6 × u32   [0x4000043c, 0x40000438, 0x40000434,
                         0x40012c34, 0x40012c38, 0x40000834]   外设地址表 A
  0x08025ee8  8 × u8    [3,2,1,0,4,5,6,7]                通道重排 R
  0x08025ef0  8 × u8    [0,1,2,4,3,5,6,7]                通道重排 S
  0x08025ef8  8 × u8    [3,2,1,0,4,5,6,7]                通道重排 R
  0x08025f00  8 × u8    [3,2,1,0,4,5,6,7]                通道重排 R
  0x08025f08  8 × u8    [2,1,0,4,3,5,6,7]                通道重排 T
  0x08025f10  6 × u32   [0x4000043c, 0x40000438, 0x40000434,
                         0x40012c38, 0x40012c34, 0x40012c3c]   外设地址表 B
  0x08025f28  8 × u8    [2,0,1,3,2,1,0,0]                尾部索引数组
  0x0802420c 16 × u16   [1,2,4,6,8,10,12,16,32,64,128,256,
                         0x408,0x402,0x108,0x101]          USART 除数表

五张 8 字节表都是 0..7 的排列，去重后只有 3 种：R、S、T。
R（前 4 项反转）与 S（3↔4 交换）都是自逆置换；
T 的逆是 [2,1,0,4,3,5,6,7]。
「哪个索引对应哪个物理传感通道」静态字节答不了，需要原理图或设备。

全镜像小端指针引用（精确命中集，不是顺序推测）：

  0x08025ec0 → 0x0800fdc0, 0x080125a4
  0x08025ed0 → 0x0800fbcc
  0x08025ee8 → 0x0800fd20      （K37 setter 的 literal pool）
  0x08025ef0 → 0x08011160      （08011100 回调分支）
  0x08025ef8 → 0x08011158      （08011100 回调分支）
  0x08025f00 → 0x0800fcb8      （K34 setter，sku != 4）
  0x08025f08 → 0x0800fcbc      （K34 setter，sku == 4）
  0x08025f10 → 0x0800fc00
  0x08025f28 → 0x08012cf0

附：本轮纠正了上一轮笔记里的两处字节记录错误——摘要把三张表的字节序/
起始地址写混了，上面是从冻结 BBIN 重新逐字节 dump 的结果，已由脚本逐项核验。

════════════════════════════════════════════════════════════
三、+0x18c 与 K90（闭合项 2）
════════════════════════════════════════════════════════════

`0x18c` 由 `movs rN,#0xc6; lsls rN,rN,#1` 构造。全镜像只有三处这样构造：

  0x0800f744  写：strb r1(=1),[0x2000a4c0 + 0x18c = 0x2000a64c]
              后接 DSB #0xf / DMB #0x1f / SEV —— 典型的「发布标志并通知」
  0x0800fd3a  写：strb r2(=0),[param_1 + 0x18c]
              K90 setter（分派表 row13，阈值 0x0A90）
  0x0801e68a  读：ldrb r1,[r7 + 0x18c]
              主分派 0801d888，其中 r7 = param_1、r6 = param_2

读后流向（0801e686..0801e6a4）：

  r3 = 0xea << 6 = 0x3a80   →  strb r1,[r6,r3]    上报对象 +0x3a80
  r2 = 0x8e + 0xff = 0x18d  →  ldrb r1,[r7,r2]
  r3 = 0x3a81                →  strb r1,[r6,r3]    上报对象 +0x3a81
  cmp r1,#0xff               →  相等则改走 0801ea3e（哨兵分支）

结论：`+0x18c` 是配置对象里一个被上报出去的 byte 型状态/模式标识，
`0xff` 是哨兵。K90 把它清零，即 hwrev ≥ 0x0A90 的板子不再走哨兵路径。

**重要排歧**：`movs r3,#0xc6` 在别处还有两种不同移位，不是这个字节：
  0x0800c6f4  lsls r3,r3,#2  →  0x318   （0800c680 里的 u32 函数指针槽）
  0x080153c6  lsls r3,r3,#5  →  0x18c0  （另一处带 DSB/DMB 的标志写）
上一轮笔记把 `0xc6` 命中都当成 `0x18c`，本轮已纠正。

另需保守：`0x0800f744` 写的是全局对象 `0x2000a4c0` 的 +0x18c，
与配置对象 `param_1 + 0x18c` 偏移相同但基址不同；静态字节不能证明
两者是同一个字段。K90 setter 与主分派读写的是同一个 `param_1 + 0x18c`。

════════════════════════════════════════════════════════════
四、+0x1a0 / +0x1a4 与 hwinfo 条件（闭合项 3）
════════════════════════════════════════════════════════════

主分派 0801d888 里两处读取（`0xd0<<1 = 0x1a0`、`0xd2<<1 = 0x1a4`）：

  0801e662  r3 = 0x1a0; ldr r1,[r7,r3]; 非 0 → 0801e670 复制 8 字节
  0801e674  r3 = 0x1a4; ldr r1,[r7,r3]; 非 0 → 0801e682 复制 8 字节

所以这两个槽位都是「指向 8 字节表的指针，为空则跳过复制」。
伪代码里 K34 setter 明写 `param_1[0x69]`，0x69 × 4 = 0x1a4，与字节偏移一致。

`+0x1a4` 的三个写入者（14 行按 `threshold <= hwrev` 累加，后者覆盖前者）：

  K34 (row8,  0x0A34)  0x0800fcac：
      sku (DAT_20001cf8) == 4 → 0x08025f08(T)，否则 → 0x08025f00(R)
  K37 (row11, 0x0A37)  0x0800fd16：0x08025ee8(R)   ← 覆盖 K34
  08011100 回调         0x08011130：
      需 hwrev == 0x0A35、sku == 4，且
        devicesn == 0x5150014E       → 0x08025ef8(R)
        (devicesn & ~2) == 0x5150014D
          且 FUN_080110f6() == 0    → 0x08025ef0(S)
      否则不写

累加结果（sku=0、devicesn 不匹配时）：

  hwrev <  0x0A34   → NULL
  hwrev  0x0A34..36 → 0x08025f00
  hwrev ≥ 0x0A37    → 0x08025ee8（K87/K90 不再改它）

`+0x1a0` 在 14 行 setter 里没有任何写入者，只有主分派的读取。

五、14 个 setter 的槽位台账（闭合项 4 的前置）
════════════════════════════════════════════════════════════

分派表 0x08025da4 共 14 行，每行 `[u16 threshold][u16 pad][u32 callee]`：

  row  阈值     版本  callee       主要写入槽位（相对配置对象）
   0  0x0000   I00  0800f58d     62 个槽位，0x0..0x19c（完整默认对象）
   1  0x0805   I05  0800f719     0x0, 0x40, 0x58, 0x11c, 0x120, 0x124
   2  0x0900   J00  0800f761     0x0, 0x4, 0x30, 0x34, 0xe0, 0x108, 0x10c
   3  0x0A00   K00  0800f969     48 个槽位（第二个完整默认对象）
   4  0x0A05   K05  0800fafd     25 个槽位
   5  0x0A10   K10  0800fae1     0x0, 0x164
   6  0x0A30   K30  0800fc05     0x0,0x4,0xd0,0x114,0x118,0x160,0x164,0x16c,0x194,0x19c
   7  0x0A33   K33  0800fc65     0x0, 0x4, 0x58, 0x114, 0x118
   8  0x0A34   K34  0800fc99     0x0, 0x1a4
   9  0x0A35   K35  0800fcc1     0x0, 0x194
  10  0x0A36   K36  0800fce1     0x0, 0x4, 0x158, 0x15c, 0x160
  11  0x0A37   K37  0800fd0d     0x0, 0x1a4
  12  0x0A87   K87  0800fd25     0x0（工程无函数体，原始 Thumb 半字解码）
  13  0x0A90   K90  0800fd31     0x0, 0x18c（同上；唯一清 0x18c 的 setter）

字符串表 0x08024234 的 idx4/5 是 K10/K05，阈值行 4/5 是 0x0A05/0x0A10
（K05/K10），两者顺序互换；本轮按精确字节重新解析，未沿用旧笔记的阈值记录。

**偏移归因的坑**：多个 setter 在写入前执行 `adds rN,#0xfc`，所以
`str r3,[r4,#0x18]` 实际是配置对象 `+0x114`。台账已把该增量累加进去。
`+0x114` 正是主分派 `FUN_08020f94(param_2+0x3e28, param_1+0x45, 0x50)`
复制的 0x50 字节回调/句柄块起点——两侧对上了。

高位槽位的消费者语义（来自 0801d888，不是猜的）：

  +0x114  param_1[0x45] 起 0x50 字节块，整体复制到上报对象 +0x3e28
  +0x164  param_1[0x59]  保存的函数指针（K10 在此写入）
  +0x168  param_1[0x5a]  保存的函数指针
  +0x188  param_1[0x62] → DAT_2000a4b4，且被 clamp 到 ≤ 4（有界计数/模式）
  +0x18c  byte 状态 → 上报 +0x3a80，0xff 哨兵
  +0x190  param_1[100]   side 回调：返回 1 = "right"，否则 "left"
  +0x194  param_1[0x65]  可选 post-init 回调(config_object)
  +0x19c  param_1[0x67] → 上报 +0x3df4
  +0x1a0  8 字节表指针（非 NULL 时复制）
  +0x1a4  8 字节通道重排表指针（非 NULL 时复制）

「超时」不是配置对象里的独立槽位，而是主分派用 `param_1[4]` 装配的：
上报对象 `+0x3e08 = 回调`、`+0x3e10 = 1000`（毫秒）、`+0x3e14 = 1`，
并把 `FUN_080099ec() - 1000` 写进 `+0x3e0c` 作为起始时间戳。

════════════════════════════════════════════════════════════
六、USART 波特率寄存器重算（闭合项 4）
════════════════════════════════════════════════════════════

`0800e8b4` 被 `0800ec64`（0800eca6 处 `bl 0x0800e8b4`）调用。
`08008174` 是无符号整数除法 helper（r0 = param_1 / param_2，r1 = 余数），
本轮从指令级确认，不只是靠调用点用途推断。

配置对象字段：
  param_1[0]   USART 外设基址（0x40013800 / 0x40004400 / 0x40004800 /
               0x40004c00 / 0x40005000 / 0x40013c00）
  param_1[1]   目标波特率（运行值）
  param_1[7]   过采样选择（0x8000 或其它）
  param_1[9]   0x0802420c 表索引；同时写入外设 `+0x2c` 低 4 位
               → 低 4 位刚好对应 16 项表长

时钟来源：
  · 0x0800ea44 的编译期常量 0x00f42400 = 16,000,000（0800e96c / 0800e9da）
  · 0x0800e9ba / 0x0800ea20 两处 `bl 0x0800cd24` 取运行时 SYSCLK
    （上一轮算出 64MHz，是条件性计算值，不是实测晶振）
  由 RCC 0x40021054 的位域在 0800e900..0800e9d8 分支选择。

两条写入路径（写入 USART +0xc，即 BRR）：

  路径 A（0800e96e..0800e992，16 倍过采样，直接写）
      q   = clock // table[param_1[9]]
      BRR = (q + (baud >> 1)) // baud
      str r0,[USART,#0xc]

  路径 B（0800e9dc..0800ea10，8 倍过采样，×2 + 3 位小数）
      q   = clock // table[param_1[9]]
      N   = (2*q + (baud >> 1)) // baud
      BRR = (N & 0xfff0) | ((N & 0xf) >> 1)
      str r3,[USART,#0xc]
      指令 0800ea04 `lsls r0,r0,#0x1c` + 0800ea0a `lsrs r0,r0,#0x1d`
      实现「低 4 位右移 1」，保证 bit3 恒为 0（8 倍过采样的 BRR 编码要求）。

范围检查（0800e98a / 0800e9fa）：
  `subs r2,#0x10; cmp r2,#0xffef; bhi 0800e950`
  → 合法 `0x10 ≤ BRR ≤ 0xffff`；越界则 0800e950 令函数返回 1（失败）。

参数化取值（**baud 是显式假设输入，镜像里没有任何编译期波特率常量**：
9600 / 19200 / 38400 / 57600 / 115200 / 230400 / 460800 / 921600
作为 4 字节小端常量在 132896B 镜像里全部 0 命中）：

  clock   baud     idx  div   路径 A          路径 B
  64MHz   115200   0    1     556 = 0x22c     0x453（N=1111）
  16MHz   115200   0    1     139 = 0x08b     0x113（N=278）
  64MHz   9600     0    1     6667 = 0x1a0b  0x3412（N=13333）
  64MHz   8MHz     0    1     8（越界，返回 1）

  64MHz 与 16MHz 在 115200 下路径 A 的 BRR 正好相差 4 倍（556 / 139），
  说明 RCC 时钟源分支不是无关紧要的细节。

模型枚举 2 时钟 × 8 波特率 × 16 表索引 × 2 路径 = 256 组，
并验证了所有路径 B 编码值的 bit3 恒为 0、低 4 位 ≤ 7。

八、边界与仍未闭合（需要新增材料或设备）
════════════════════════════════════════════════════════════

  · 通道重排表的每个索引对应哪个物理传感通道，需要原理图或实机。
  · `param_1[1]`（波特率）与 `param_1[9]`（除数索引）是运行值，静态不固定；
    上面 BRR 数值是参数化模型输出，不是镜像里读出来的常量。
  · 64MHz 是上一轮的条件性计算 SYSCLK，依赖 PLL lock、SW=2 切换成功、
    SWS 读回 0x10、复位态未被改写、无致命错误出口；不是实测核心时钟。
  · RCC 0x40021054 是活寄存器，实机走哪条时钟源分支静态定不了。
  · `0x2000a4c0 + 0x18c` 与 `param_1 + 0x18c` 同偏移不同基址，未证明同字段。
  · 回调/用途名来自消费者调用点；镜像已去符号，没有函数名。
  · 型号/板型/外部晶振 BOM 绑定、PLL lock 与切换过渡、累计 tick 损失、
    中断延迟、ADC CLKIN/DRDY 与实际采样率，仍需设备测量。
  · 核心生理算法、Autopilot、姿态分类、实机绑定、音箱 DSP 依旧不碰。
