nonUSB 帧接收链路下游闭合与残余字段语义
========================================

输入：firmware-sensor-g0.bbin，132896 字节
SHA256 51531576fd31af96f7239b71d26e1f175815f5cb21dbe9ab305fa9a33cc6a891
VA 0x08008000..0x08028720，offset = VA - 0x08008000
证据目录：report/analysis-tools/system-deepening/receive-path-field-closure/
本轮未调用 Ghidra、未重新反汇编、未创建新的 passN 导出，只消费磁盘上已有的导出与冻结镜像。


一、结论摘要
------------

上一轮把五态帧解析状态机解到「状态 4 比对 16 位尾值」为止，之后的分支、被调用的
sink 函数、以及队列对象的字段初始化都没有展开。本轮把这四处全部接到可执行语义上，
并重新扫了两个残余覆盖空洞。

  A. sink 0x0800a578 不是内存拷贝，而是单寄存器/FIFO 推送器，三种模式分别处理
     字节流、半字流和字流，参数单位不同。
  B. 状态 4 比对成功后按 0x2000230c 的 bit7 分两路，两路最终汇合到同一张五项跳转表
     0x08017132；该表基址是 bl 的返回地址，不是表自身的可见起点。
  C. 队列对象 0x2000240c 的十一个字段由 0x0801d888 一次性初始化，容量为 256 字节，
     帧头字节数上限为 4。
  D. 覆盖空洞 027c..02a0 由 12 个基址组证明是真实字段区；3e01..3e08 在 5631 份导出中
     零候选，仍无见证。无见证字节从 43 降为 7。
  E. 0x10f0 块在 44 个偏移上有 385 次访问，但 0x10f0..0x1487 之间没有任何字段被命名，
     这块不是同质结构。

模型脚本 113 条断言 0 失败；独立字节核验脚本 81 项 0 失败，两遍重跑哈希一致。


二、sink 0x0800a578：三模式单寄存器推送
---------------------------------------

函数体 [[0800a578, 0800a5c1]]，74 字节，35 条指令。签名等价于
u32 sink(ctx, void *src, u32 count)。

进入时把 ctx+0x1d 写 2，退出时写 1，这是忙标志。目标对象是 *ctx，其 +0x08 处
置 bit0，本函数不负责清除。模式取自 ctx+0x20（ctx[8]），按 2、3、1 的顺序比较，
其余值返回 0。

三种模式的共同点是最关键的一点：目标地址始终不变，源指针递增。

  模式 1（0x0800a480，88 字节，44 条）
    count 单位是字节。按 lsrs r7,r2,#2 取字数，每四个字节组装成一个 32 位字：
    b0<<24 | b1<<16 | b2<<8 | b3，即大端语义。余数 count&3 按 1/2/3 字节分别用
    strb / strh / strh+strb 写出。

  模式 2（0x0800a4d8，44 字节，22 条）
    count 单位是字节。按 lsrs r4,r2,#1 取半字数，每两个半字组装成一个 32 位字：
    h0<<16 | h1。奇数尾按 strh 写出。

  模式 3（内联在 0x0800a5a0..0x0800a5b0，6 条）
    count 单位是字。lsls r2,r2,#2 后 adds r2,r1，用 ldmia r1!,{r0} 取源、
    str r0,[r3,#0x0] 写目标；目标寄存器 r3 在整个循环里不变。循环结束后
    ldr r0,[r3,#0x0] 读回最后一个字作为返回值。

模式 3 的「目标不变、源递增」直接说明这不是缓冲区拷贝：连续多个字被推到同一个
地址，符合单寄存器数据口 / FIFO 的行为。三种模式的返回值都是最后一次读回的字，
调用方取 uxth 后与帧尾 16 位值比较。

参数单位不一致是易错点：模式 1、2 收字节数，模式 3 收字数。状态 4 传入的是
[0x2000a4a8]，即帧体字节数；只有当前模式为 1 或 2 时该值才是正确的单位。


三、状态 4 之后：bit7 分派与第二张跳转表
---------------------------------------

状态 4 先把解析状态清 0，把当前字节或入帧尾高半部，再调 sink，把返回值 uxth 后
与 [0x2000a4b0] 比较。不等就回 0x08016e22 继续收字节；相等才进入命令分派。

分派读 0x2000230c 的一个字节，取 code = byte & 0x7f，再用 sxtb 判符号位：

  bit7 置位 → 0x08016f06
    先做 subs r3,r5,#2 与 cmp r3,#3，即只有 code 在 2..5 时才 bls 到 0x08016f10；
    其余走 0x08017102，打印 "Received response to 0x%02x" 后汇入主循环。

  bit7 清零 → 0x0801710c
    先把 0x20002304 清 0，再以 code|0x80 发一个应答字节，然后按 code-1 走第二张表。

第二张跳转表位于 0x08017132，五项字节为 03 0c 14 14 18，增量 3/12/20/20/24，
目标 0x08017138 / 0x0801714a / 0x0801715a / 0x0801715a / 0x08017162。

基址是 0x0801712e 处 bl 0x0800814c 的返回地址 0x08017132，不是表前那条指令的地址。
这一点与上一轮 0x08016fdc 的错误同源：辅助函数的表基址永远取 lr&~1，也就是
bl 地址加 4。0x0800814c 是 __gnu_thumb1_case_uqi，9 条指令，用 ldrb 取字节表并左移
一位加到 lr 上。

五个目标与反汇编文本逐条对齐：

  code 1 → 0x08017138  向栈缓冲写 0x46，func_08012344(0)，返回码 1
  code 2 → 0x0801714a  先 func_08012344(0)，再以长度 0x80 发送 0x0807f804
  code 3 → 0x0801715a  返回码 4
  code 4 → 0x0801715a  与 code 3 共用同一目标
  code 5 → 0x08017162  fun_0800fed8、打印 "Rebooting..."、延时、死循环

code 5 是唯一不会返回的路径，字符串 0x08025518 的内容与之吻合。两条路径共用同一张
表，是这段代码的结构特征：bit7 置位时直接进入，bit7 清零时先发应答字节再进入。


四、队列对象 0x2000240c 与它的十一个字段
---------------------------------------

0x08016e22 入口处 ldr r6,[0x08016f94]，该字面量的值是 0x2000240c。状态机里所有
字段都写作 r6 加小偏移，因此真实地址是 0x2000240c + 0x8084..0x80b0，落在
0x2000a490..0x2000a4bc。这解释了上一轮只从字面量反推时出现的 8 字节错位。

对象头：+0x00 状态、+0x04 回调（初始化为 0x0800fe95）、+0x08 起 64 字节缓冲、
+0x48 head、+0x4c tail、+0x50 转义标志、+0x54 周期（0x0801321d）。

字段与用途：

  +0x8080  通道掩码数组基址，初始化时把 32 项按 0x401 步长逐项置 1
  +0x8084  待选标志，初始化为 0，由 0x08016ffc 检测
  +0x8088  选择事件对象，通过 0x080134be 轮询
  +0x8094  帧体基址指针，初始化为 0x2000230c
  +0x8098  帧体容量，初始化为 0x100
  +0x809c  帧体写索引 / 已收长度
  +0x80a0  长度对象指针，初始化为 0x20002308，使用时解引用
  +0x80a4  16 位帧尾累加器（半字）
  +0x80a8  帧头字节数，初始化为 min(参数,4)
  +0x80ac  帧头字节游标
  +0x80b0  帧头字累加器

初始化写者只有一个：0x0801d888，区间 0x0801d948..0x0801d9dc，共 11 处写入，
顺序为 0x8094、0x8098、0x80a0、0x80a8、0x8080、0x8084、0x8088、0x809c、0x80a4、
0x80ac、0x80b0。容量常量来自 movs r1,#0x80 后 lsls r1,r1,#1，即 256；帧头上限来自
cmp r3,#0x4 与 movs r3,#0x4 的截断。

每帧由状态 0 重清四个偏移：0x809c、0x80a4、0x80ac、0x80b0。帧体指针、容量和帧头
字节数不在每帧重置，它们在初始化时定下来后保持。这条区分决定了缓冲区复用方式：
每帧重用同一块 256 字节缓冲，只把游标和累加器归零。


五、覆盖空洞复扫：43 字节降为 7 字节
-----------------------------------

上一轮报告 43 字节无见证，其中 027c..02a0 占 36 字节。本轮把扫描范围扩到全部
5631 份 txt 导出，同时用两种访问形式（指令级 ldr 字面量后接 [base,rX]、伪 C 的
参数加偏移），并引入两条新规则：

  镜像归属规则：导出的地址必须落在 0x08008000..0x08028720。3650 份满足，
    1345 份属于其他模块，其 param_2 是另一个对象。上一轮 027c 洞那 130 条伪 C
    候选绝大多数来自 host-legacy-sample-consumers/pass5/0018a510.txt，就是这一类。

  基址组规则：同一个基址表达式必须同时寻址洞内偏移和洞外紧邻的已覆盖偏移。
    只看「同函数触及两个覆盖偏移」不够——0x08014298 触及 0x143/0x1c0/0x50e 却有
    一个孤立的 0x281，那不能证明什么。

按这两条规则，027c..02a0 获得 12 个基址组见证：

  左侧接入（0x270 起，延伸到 0x290/0x294/0x298）
    0800bedc、0800bfbc、0800c4aa、0800cd80、0800cdfa、0800ce00 六个 legacy 函数，
    基址分别是各自的 iVar。

  右侧接入（0x294/0x298/0x29c 接到 0x2a0）
    0801830c、080183c6 的两个版本、08025534 的两个版本、0801b63c。

洞内被见证的偏移是 0x290、0x294、0x298、0x29c 四个。以 0801830c 为例，同一
param_1 上连续出现 char +0x29c、int +0x294、uint +0x298、char +0x2a0，是一段连续
字段而不是零散访问。因此 027c..02a0 判定为有见证。

但见证只覆盖 0x290..0x29c，洞的前段 0x27c..0x28f 共 20 字节仍然只有 0x281 一个
孤立候选（来自 08014298，未通过基址组规则），没有任何字段级证据。

3e01..3e08 共 7 字节，两种形式、全部 5631 份导出里零候选，仍然完全无见证。

三个口径同时给出，避免混淆：
  完全无见证的洞        7 字节（仅 3e01..3e08）
  洞内无字段证据的前缀  20 字节（027c..028f）
  两者合计              27 字节

需要说明的是：本轮修正的是上一轮的方法论结论，不是覆盖率的计算。块级覆盖率仍为
11297/15880 = 71.14%，字段见证和分支解码都不改变覆盖率。


六、0x10f0 块：44 个偏移，但不是同质结构
---------------------------------------

窗口 0x10f0..0x21bc，约 4300 字节。既有字段台账在该窗口内记录 44 个不同偏移、
385 次访问（读 201、写 78、间接 106），涉及 59 个函数，其中 43 个偏移达到对象绑定
判据。

第一个被命名的偏移是 0x1488，不是 0x10f0。0x10f0..0x1487 之间没有任何导出给出字段
访问，这段是「未被描述」而不是「确认为空」。

按 0x100 分段后可以看到方向构成明显不同：0x1488 一带以标量配置字为主，读写都有；
0x1c00 之后以只读字为主，服务于遥测和命令组装。最高频的偏移集中在 0x2000 附近，
说明这块尾部是上报侧的聚集区。

字段级命名仍然做不了：现有导出能给出「哪个函数读了哪个偏移几次」，但给不出该偏移
的物理含义。要推进必须解码写入者，这超出了当前只读导出的覆盖范围。


七、边界与未闭合项
------------------

本轮全部结论来自静态字节与既有导出。以下项目明确不在本轮范围内：

  1. 0x10f0..0x1487 共 920 字节没有任何字段访问记录，需要新的导出才能描述。
  2. 0x10f0 块 44 个偏移的物理含义未定，需要解码对应写入者。
  3. 027c..028f 前 20 字节与 3e01..3e08 全 7 字节仍无见证。
  4. 命令分派器 0x40..0x48 那组九项分支、以及 0x080171a0 / 0x08017206 / 0x08017668
     另三处跳转表，只有反编译文本、没有逐字节解码，本轮未展开。
  5. 169 个大函数内部地址仍无函数体，必须重新反汇编，已越只读边界。
  6. 引脚功能、字段单位、实机时序需要材料或设备。

覆盖口径不变：覆盖 = TARGET 地址 ∪ function= 所属函数 ∪ 已导出 RANGE 区间。
块级覆盖 11297/15880 = 71.14%，14 个空洞共 4583 字节，其中 12 个有见证。
