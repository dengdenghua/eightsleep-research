============================================================
一、结论置顶
============================================================

按上一条 A 类剩余优先级 2 → 3 → 7 继续，一次收口；顺带把 0x0802420c
末 4 项除数的引用点扫干净。五项闭合：

  1. 80 个回调指针全部落到「实现」：19 个有 Ghidra 函数体，61 个由冻结镜像
     原始 Thumb 半字解出有界前缀，分 21 类。
  2. 短 thunk 的真实语义确定：movs r0,#imm8 是 0x08027f10 描述表的索引 ID，
     不是字符输出。0801fdf0 写、0801fdd0 读、08010020 三脉冲。
  3. hwrev → 内部 3 字符标识公式找到（0801dd62..0801dd80 共 13 条指令）。
     13 个真实阈值与 flash 版本字符串表逐项一致，形成两套独立机制的交叉验证。
  4. hwrev 分派 → init 回调 → 时钟链闭环：080108ac 按 0xA87 阈值在 16/32MHz
     间选 HSE，08010960 选 8MHz，正好对应第四轮 writer2 的三版 CFGR2。
  5. 主分派上报对象写入台账：136 条写入 / 107 个唯一偏移 / 9 个块操作；
     0x0802420c 全镜像仅 0800ea48 一处指针引用。

硬数字：1250 项字节核验 0 失败、39 条模型断言 0 失败、147 份只读导出、
17155 条指令机器码逐字节比对、158 项输入 SHA 清单。

============================================================
二、A 类 #2：80 个 setter 回调的实现台账
============================================================

从第六轮 CONFIG_SNAPSHOT.json 提取 80 个唯一 thumb_function_pointer（值带
Thumb bit0），清 bit0 得偶数入口，四批 Ghidra 只读导出共 143 个 target。

导出结果分裂得很干净：
  - 19 个在 Ghidra 工程里已有函数体（7~312 条 INSN），含 5 个大 init 回调
    080114bc(176) / 08011914(312) / 08011d90(209) / 08012008(210) /
    08012274(29)，以及 08011100(34)、08012ad8(241) 等。
  - 61 个 function=none，是工程未解码区域。用 scripts/thumb_lite.py 从冻结
    镜像逐半字解码：59 个解到返回、2 个解到无条件跳转、0 个 undecoded。
    其中 0800f488 是 125 个连续 46c0 NOP 后接 4770 的 252B 占位 no-op。

实现分类里最有价值的一族是「共享被调目标」。补导 pass4 后确定：

  0801fdf0(id,value) -> 0800acc8(desc[id].base, desc[id].mask, value)
      value==0 写 base+0x28（清零），否则写 base+0x18（置位）
  0801fdd0(id)       -> 0800acbc(desc[id].base, desc[id].mask)
      读 base+0x10 并判非零
  08010020(id)       -> fdf0(id,1); fdf0(id,0); fdf0(id,1) 三脉冲
  desc 表 0x08027f10 为 12B/项 [u32 外设基址, u32 引脚与掩码, u32 端口索引]
      基址 0x50000000..0x50001400，端口索引 0..5

因此 08010140 一类的 `b510; movs r0,#0x50; bl 08010020; bd10` 是「对描述表
第 0x50 项发三脉冲」的 thunk；080110a4 一类的 `movs r0,#0x53; bl 0801fdd0`
是「读第 0x53 项」的 thunk。24 个被引用的 ID 全部有合法描述条目（基址在
外设区间、掩码非零、端口索引 <=5），逐项核验落在 BYTE_VALIDATION.json。

另几类实现：3 个索引范围检查写表 thunk（0800f8a0 / 0800fbb0 / 0800fbe4，
分别读 08025ed0 / 08025f10 与外设 0x40000434）、6 个传感通道读/写 thunk
（0800b988 / 0800bac0）、RAM 全局量 getter（0800f420/f430/f444，其中 f430
带 DSB/DMB 屏障）、RAM 全局量 writer（0800f7a0 写 0x200014dc）、常量返回
（0800f586 返回 1；0800f714 / 0800f964 直接 bx lr）。

边界：61 个是「有界前缀」，止于首条返回/无条件跳转，不是完整反编译；
GPIO 寄存器名是按偏移用法归纳，不是器件手册命名。

============================================================
三、闭环：hwrev 分派 → init 回调 → PLL → SYSCLK
============================================================

7 个 init 回调装在配置对象 +0x4，其中已解码的 4 个大函数与 2 个未解码函数
（08010bf4 / 08010c6c）都调用一串初始化。差异的核心是两个时钟入口：

  080108ac:  if (DAT_20001cfc - 0xA87 < 0x79)  uVar2=0x10, HSE=16000000
             else                              uVar2=0x30, HSE=32000000
             FUN_0800c828(); ... FUN_0800c8dc(&struct)
  08010960:  HSE=8000000; FUN_0800c828(); ... FUN_0800c8dc(&struct)

这里的 0x10 / 0x30 / 0（8MHz 分支）正是第四轮从 14 槽位局部结构体解出的
s[9] 三版，对应 CFGR2 = 0x56061813 / 0x56061833 / 0x56061803，即
PREDIV = 2 / 4 / 1。三套输入经 (HSE/PREDIV)*24/3 都算出 64MHz SYSCLK。
08012274 首指令 bl 08012008 复用上一 init，不新增时钟入口（第三轮结论一致）。

这把之前分散在第三、四、六轮的三段串成一条：14 行累加分派选 init 回调 →
init 回调按 hwrev 选软件 HSE 与 PREDIV → writer2 构造 CFGR2 → 0800cd24
解出 64MHz → 0800995c 装 SysTick LOAD。仍然守住：HSE 是写入 0x20000474 的
软件输入，64MHz 是条件性计算值，不是实测晶振或实测频率。

============================================================
四、A 类 #7：hwrev → 内部 3 字符标识
============================================================

主分派 0801d888 在解析配置块后（magic (DAT_0807f804 & 0xe0)==0xa0 且
FUN_0801273c / FUN_0801ae3a 解析成功）执行 13 条指令：

  0801dd62  movs r0,#0xf
  0801dd64  ldrh r3,[r4,#0x10]        ; hwrev = u16 DAT_20001cfc
  0801dd66  ldr  r2,[..=200014d8]
  0801dd68  asrs r1,r3,#0x8 ; 0140 ands r1,r0 ; 4131 adds r1,#0x41
  0801dd6e  strb r1,[r2,#0x0]         ; d8 = ((hwrev>>8)&0xF) + 'A'
  0801dd70  asrs r1,r3,#0x4
  0801dd72  ands r3,r0 ; 3033 adds r3,#0x30
  0801dd76  strb r3,[r2,#0x2]         ; da = (hwrev&0xF) + '0'
  0801dd7a  ands r1,r0 ; 3031 adds r1,#0x30
  0801dd7e  strb r1,[r2,#0x1]         ; d9 = ((hwrev>>4)&0xF) + '0'
  0801dd80  strb r3,[r4,#0x0]         ; DAT_20001cec = 1（解析有效标志）

于是 0x0805 -> I05、0x0900 -> J00、0x0A00 -> K00、0x0A05 -> K05、
0x0A10 -> K10、0x0A87 -> K87、0x0A90 -> K90。这解释了为什么字符串表是
I/J/K 三系列。全镜像 0x200014d8 的小端指针只有 5 处
（08012a58 / 08012d08 / 08012ecc / 0801cf14 / 0801ded0），0x200014d9 与
0x200014da 0 命中——它们只通过基址 +1 / +2 访问。

**两套独立机制的交叉验证**：配置对象 +0x0 装的是 flash 0x08024234 的
14 个 4B ASCII 字符串指针，主分派把它复制到上报 +0x3d9c，供
FUN_08012754("[sensor] %s mode") 使用。13 个真实阈值下，运行时公式与 flash
字符串逐字一致。字符串表 idx4=K10 / idx5=K05 与阈值行 4=0x0A05 /
5=0x0A10 的顺序互换不是错配：setter 的 string_index 分别是 5 和 4，交叉
引用后仍一致。

**一处必须单列的差异**：阈值行 0 是 0x0000，含义是「无条件累加基线」，
不代表真实 hwrev；按公式算得 A00，而 flash 字符串是 I00。因此一致性统计
是 13/13（真实阈值），不是 14/14。

边界：公式用 asrs 作用于零扩展 16 位载入值，hwrev >= 0x8000 时与逻辑右移
不同；nibble > 9 时 +0x30 产生标点（hwrev 0x0AFF -> K??，0x0B00 -> L00），
flash 表无对应字符串；解析失败时 DAT_20001cec=0、三字节不写，RAM 里留什么
静态定不了。

============================================================
五、A 类 #3：主分派上报字段写入台账
============================================================

从 pass2/0801d888.txt 的伪 C 扫描所有以 param_2（上报对象，声明为
undefined1*，所以下标与加法都是字节偏移）为左值的赋值，按缩进维护 if
条件栈，得到 136 条写入、107 个唯一偏移、9 个块操作（memcpy/memset）。
每条记录偏移、宽度、值表达式、来源类别与外层条件。来源分 5 类：
配置对象槽位、常量、回调/函数结果、运行时计算或自引用、RAM 全局/指针。

与前面几轮已知链路对上：
  配置 +0x0      -> 上报 +0x3d9c（版本字符串指针，日志 %s mode）
  配置 +0x18c    -> 上报 +0x3a80 / +0x3a81（byte 状态，0xff 哨兵）
  配置 +0x114..  -> 上报 +0x3e28（FUN_08020f94 复制 0x50 字节）
  1000ms 超时块  -> 上报 +0x3e08 / 0x3e0c / 0x3e10 / 0x3e14
条件栈里捕获到 hwrev 比较（0xA32 / 0xA34 / 0x94F / 0xA31 / 0xA33 / 0xA80
等）与 sku 比较（DAT_20001cf8 != 4）。

边界：这是反编译重建出的「可能写入」，不是执行轨迹；条件栈按缩进采集 if，
不覆盖 switch/label 跳转的完整数据流；宽 memcpy/memset 只记为块操作，未展开
成逐字节；字段名称/单位/物理通道在冻结镜像里不存在，本轮不命名。

============================================================
六、0x0802420c 末 4 项除数的引用点
============================================================

全镜像小端扫描 0x0802420c 指针只有 1 处命中：0800ea48（0800e8b4 内）。
16 项 u16 表为 [1,2,4,6,8,10,12,16,32,64,128,256,0x408,0x402,0x108,0x101]。
结合第六轮「末 4 项是整字传给除法 helper、无拆分指令」的结论，本轮补上了
引用点全集：除 0800ea48 外没有第二处消费者，末 4 项的功能定论仍缺材料。

============================================================
七、纠错与踩坑
============================================================

1. 上一轮 pass1 批量导出把 80 个地址拼成单个 script arg，触发
   NumberFormatException，只生成 program.txt。ExportSensorDiff.java 第 47 行
   对每个 args[n] 单独 Long.parseLong(...,16)，必须一项一个 argv。本轮用
   Python subprocess 列表传参，一次导出成功（80 targets + program.txt）。
2. 「短 thunk 的 #imm8 是 ASCII 字符」是直觉误读：它是 0x08027f10 描述表
   索引 ID，由 0801fdf0/0801fdd0/08010020 伪 C 确认。
3. 字符串表 idx4/5 与阈值行 4/5 的顺序互换不是错配，setter 用
   string_index 交叉引用（4->5、5->4）。
4. 阈值 0x0000 是无条件基线，不参与 hwrev 标识一致性比对。
5. 0800f488 不是缺函数体，是 125 个 NOP + bx lr 的占位 no-op 回调。
