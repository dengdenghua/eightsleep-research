  python3 model/build_models.py               -> CALLBACK_LEDGER.json

  3. 第六轮产物 config-object-snapshot/CONFIG_SNAPSHOT.json
VA -> 文件偏移：offset = VA - 0x08008000。

============================================================
二、需要 Ghidra 才能重跑的部分
============================================================

工具链与逐批 targets 见 EXPORT_COMMANDS.json（由 4 份 *-export.log 精确重建）。
所有调用都是：

  export JAVA_HOME=/opt/homebrew/opt/openjdk@21/libexec/openjdk.jdk/Contents/Home
  export PATH="$JAVA_HOME/bin:$PATH"
  analyzeHeadless <project_dir> NonUsbSensor -process firmware-sensor-g0.bbin \
      -readOnly -noanalysis -scriptPath <script_dir> \
      -postScript ExportSensorDiff.java <out_dir> <target...>

四批共 143 个 targets：pass1=80、pass2=8、pass3=18、pass4=37。
脚本 ExportSensorDiff.java 有 SHA256 守门，且 start:end 只 dump 已解码指令，
不会反汇编或改写工程。

**本轮踩坑**：脚本第 47 行对每个 script arg 单独执行 Long.parseLong(args[n],16)。
把 80 个地址用空格拼成一个 shell 参数会抛 NumberFormatException，只生成
program.txt。修法是「一个 argv 元素一个 target」（Python subprocess 列表或
shell 数组 "${targets[@]}"），不要用未加引号的字符串变量。

============================================================
四、结论边界（不要越界解读）
============================================================

- 61 个未解码回调给的是「有界前缀」，止于第一条返回/无条件跳转，不是完整反编译。
- GPIO 描述表 0x08027f10 的字段解释来自偏移使用方式，不是器件手册命名。
- 3 字符标识由运行时 hwrev 计算，写入 RAM 0x200014d8；配置对象 +0x0 的
  版本字符串来自 flash 0x08024234。两套机制独立，只在 13 个真实阈值上一致。
- 上报字段台账来自 Ghidra 伪 C 的赋值扫描，是「可能的写入」，不是执行轨迹；
  条件栈按缩进采集，不覆盖 switch/label 跳转的完整数据流。
- 没有任何实机时序、晶振、BOM、波特率运行值或 64MHz 实测结论。
