============================================================
一、结论置顶
============================================================

按上一条 A 类优先级 #1 收口：主分派 0801d888 的 param_2（undefined1 *，
所有偏移都是字节）已从「零散字段台账」升级为「完整对象布局图」。五项闭合：

  1. 对象下界确定：0x3e88 = 16008B。顶层 FUN_080086a4(param_2,0,0x3e08)
     定义 15880B 主域；[0x3e08, 0x3e88) 是 128B 持久尾部。
  2. 持久尾部的存活机制找到：5 条尾部写入/复制语句在 pseudo-C 中全部排在
     顶层 memset 之前，因此它们跨清零存活。这不是「memset 之后又补写」，
     而是先写尾部、再清主域。
  3. 解析 puVar 别名后，块操作从第七轮的 9 处扩到 12 处（8 memset +
     4 memcpy），新增 3 个位点：顶层 memset、0xb08 的 0x10f0 大块清零、
     0x3df8 的 9B 二选一。0x3df8 要么清零，要么从 0x080241a3 复制冻结
     镜像中的 010101010000000001 默认标志模板。
  4. 12 个唯一构造函数体（13 份含 memset 导出，1 份重复），7 对成对实例
     的偏移差全部等于该构造函数的 memset 尺寸，零缝隙。这是块尺寸最硬的
     交叉验证：两个独立来源（构造函数的清零长度、主分派的两处调用偏移）。
  5. 纠偏：9 个 function=none 导出中只有 8 个是代码入口；080191f4 是
     080190e4 函数尾部 literal pool 的 0x00006001 常量槽，不是代码。

硬数字：203 项字节核验 0 失败、99 条模型断言 0 失败、59 份只读导出、
7576 条 INSN 机器码逐字节比对、656 项 flash literal、13 项 memset 尺寸
由指令常量传播独立复核。

============================================================
二、对象尺寸与 0x3e08 分界
============================================================

主分派签名：
  void analyst_seed_801d888(undefined4 *param_1, undefined1 *param_2)

param_2 是字节指针，param_2 + 0xNNNN 与 param_2[0xNNNN] 都是字节偏移。

顶层清零：FUN_080086a4(param_2,0,0x3e08)  -> [0x0000, 0x3e08) = 15880B
该长度不是猜的：主分派在 0x0801DC98 的 literal 就是 0x00003E08，
冻结镜像逐字节读出并核验。

在 pseudo-C 行序上，以下 5 条语句全部位于这条 memset 之前：
  *(code **)(param_2 + 0x3e08) = pcVar42;
  param_2[0x3e14] = 1;
  *(undefined4 *)(param_2 + 0x3e10) = 1000;
  *(int *)(param_2 + 0x3e0c) = iVar2 + -1000;
  FUN_08020f94(param_2 + 0x3e28, param_1 + 0x45, 0x50);

所以 [0x3e08, 0x3e88) 不受清零影响，是跨调用保持不变的尾部配置区。

持久尾部 8 个字段（连续，只有 0x3e78..0x3e7c 有 4B 空档）：

  偏移     尺寸  类型                     说明
  0x3e08   4    函数指针                 pcVar42
  0x3e0c   4    int32                    iVar2 - 1000
  0x3e10   4    uint32 常量              1000
  0x3e14   1    byte 常量                1
  0x3e18   0xc  定时器块                 FUN_080138d0 + FUN_080135fa
  0x3e24   4    uint32                   param_1[5]
  0x3e28   0x50 从配置对象复制           param_1 + 0x45
  0x3e7c   0xc  定时器块                 FUN_080134a8(...,300000,60000)
  下界     0x3e88 = 16008B

定时器块尺寸 0xc 来自 FUN_080138d0 的 memset(param_1,0,0xc)；
FUN_080134a8 只写 param_1[0]/param_1[1]（8B），是同一 0xc 块的赋值变体，
不是另一个更小的块。

衔接证据（全部由模型逐项断言）：
  0x3e18 + 0xc = 0x3e24
  0x3e28 + 0x50 = 0x3e78
  0x3e7c + 0xc = 0x3e88

============================================================
三、12 个块操作与 puVar 别名解析
============================================================

第七轮 REPORT_FIELDS.json 只识别显式 param_2 + 0xNN，得到 9 处块操作。
本轮解析伪 C 中的别名赋值 puVar44 = param_2 + 0x3df8、
puVar38 = param_2 + 0xb08（按语句位置取最近一次赋值），补齐到 12 处：

  偏移     类型    尺寸    语句
  0x0000   memset  0x3e08  FUN_080086a4(param_2,0,0x3e08)
  0x3e28   memcpy  0x50    FUN_08020f94(param_2 + 0x3e28,param_1 + 0x45,0x50)
  0x3df8   memset  9       FUN_080086a4(puVar44,0,9)
  0x3df8   memcpy  9       FUN_08020f94(puVar44,&DAT_080241a3,9)
  0x2a0    memset  0x868   FUN_080086a4(param_2 + 0x2a0,0,0x868)
  0x37a4   memset  0x2dc   FUN_080086a4(param_2 + 0x37a4,0,0x2dc)
  0xb08    memset  0x10f0  FUN_080086a4(puVar38,0,0x10f0)
  0x3dac   memset  0x18    FUN_080086a4(param_2 + 0x3dac,0,0x18)
  0x3dc4   memset  0x18    FUN_080086a4(param_2 + 0x3dc4,0,0x18)
  0x1c0c   memset  0x444   FUN_080086a4(param_2 + 0x1c0c,0,0x444)
  0x1bf8   memcpy  8       FUN_08020f94(param_2 + 0x1bf8,param_1[0x68],8)
  0x1c00   memcpy  8       FUN_08020f94(param_2 + 0x1c00,param_1[0x69],8)

新增的 3 个块位点 = {0x0000, 0xb08, 0x3df8}，已用集合差断言固定。

0x3df8 是同偏移的两个互斥分支：清零 9B，或从 0x080241a3 复制 9B。
冻结镜像 0x080241a3 起的 9 字节为 01 01 01 01 00 00 00 00 01，
与 pseudo-C 中 param_2[0x3df8..0x3e00] 那组 byte 标志（4 个条件标志 +
4 个保留零 + 1 个标志）完全对上，是默认标志模板。

大块清零的衔接口：
  0x2a0 + 0x868 = 0xb08              接 0xb08 大块
  0xb08 + 0x10f0 = 0x1bf8           接第一处 memcpy
  0x1bf8 + 8 = 0x1c00               接第二处 memcpy
  0x1c00 + 8 = 0x1c08              到 0x1c0c 前留 4B
  0x1c0c + 0x444 = 0x2050          接 *(int *)(param_2 + 0x2050)
  0x37a4 + 0x2dc = 0x3a80          接 param_2[0x3a80]
  0x3dac + 0x18 = 0x3dc4           接下一块
  0x3dc4 + 0x18 = 0x3ddc           接 0x3ddc 起的标量字段
  0x3df8 + 9 = 0x3e01              到顶层 memset 上界前留 7B

最大空洞 0x2800..0x37a4 有一处线索：

============================================================
六、literal pool 纠偏：080191f4 不是代码
============================================================

首版 verify_layout_bytes.py 把所有 function=none 导出都当代码入口做 Thumb
前缀扫描，结果在 080191f4 前缀的半字 c925 上误报 undecoded_16。实证：

  pass1/080191f4.txt 全文只有两行：
    TARGET 080191f4 function=none
    REF_TO 0801916a READ
  0801916a 的指令是 ldr r3,[0x080191f4] REF[READ:080191f4=6001]
  冻结镜像 0x080191f4 的整字 = 0x00006001
  080190e4 的 body 范围是 [[080190e4, 080191e3]]，最后一条已解码指令在
  0x080191e2（无条件跳转）；0x080191e4..0x08019208 是它的 literal pool。

即 c925 是常量 0x0014c925 的一半，不是 LDMIA 指令。给 thumb_lite.py
补 LDMIA 解码只会把数据继续误当代码，所以正确做法是「先按 REF[READ]
判定数据槽，再对其余入口做前缀解码」，不扩充解码器。

修正后：9 个 function=none = 1 个 literal pool 槽 + 8 个真实代码入口；
8 个前缀中 7 个止于 return、1 个止于 unconditional_branch，0 个 undecoded，
172 项前缀机器码逐字节比对全过。

============================================================
八、边界与残余
============================================================

  - 0x3e88 是「有写入证据的对象尺寸下界」，不是 sizeof。没有任何静态
    证据排除对象更大；也没有分配点/长度常量可以定死上界。
  - 14 个空洞中最大 4004B 只有 14 个标量写入，语义未定。
  - 覆盖区间的字段名、单位、打包顺序、上报帧格式仍需外设 datasheet 或实机。
  - A 类 #2（0x08027f10 描述表 92 行全表 + 2560B 未解码代码）、
    #3（62 条日志格式串 -> 调用点）、#5（632 个未导出 BL 目标全量调用图）
    本轮未推进。
  - 所有运行时行为、构造分支实际走哪条、实机时序仍需设备。
