一、不需要 Ghidra 的复核（推荐先跑）

  cd report/analysis-tools/system-deepening/upstream-clock-selection
  python3 scripts/verify_upstream_bytes.py
  python3 model/system_clock_cases.py

前提只有本目录 pass1..pass5 的导出文本，以及冻结归档里的原件：

  materials/eightsleep-full-evidence-20261107/firmware/mtk/rootfs/files/opt/eight/lib/subsystem_updates/
    firmware-sensor-g0.bbin   132896B   SHA256 51531576fd31af96f7239b71d26e1f175815f5cb21dbe9ab305fa9a33cc6a891

verify_upstream_bytes.py 逐条把 INSN 机器码、flash literal、BL/直接分支目标对回原件，
并独立断言 7 组数据表/常数（预分频表、版本字符串表、hwrev 阈值表、init 指针槽位、
cmp r5,#0xe、8MHz 常数、RAM 字段 literal），输出 BYTE_VALIDATION.json。
system_clock_cases.py 只做 9 组整数算术，输出 MODEL_RESULTS.json。
两个脚本只把 BBIN 当数据读，不执行固件、不联网、不访问设备或账号。

二、需要 Ghidra 才能重做的事：重新导出

工具与工程（都在分析机上，不属于交付包）：

  analyzeHeadless  /opt/homebrew/Cellar/ghidra/12.1.4/libexec/support/analyzeHeadless
  JAVA_HOME        /opt/homebrew/opt/openjdk@21/libexec/openjdk.jdk/Contents/Home
  工程目录          /Users/dangbei/Downloads/eightsleep-firmware-research-20261107/analysis/account-readonly/k60-binding/nonusb-flow/ghidra
  工程文件          NonUsbSensor.gpr        程序名 firmware-sensor-g0.bbin
  脚本目录          report/analysis-tools/system-deepening/sensor-nonusb-dispatch/scripts
  脚本              ExportSensorDiff.java

注意：不导出 JAVA_HOME 时 analyzeHeadless 会直接报
「Unable to locate a Java Runtime」以及「Unable to prompt user for JDK path, no TTY
detected」而退出，本轮第一次跑就踩了这个坑。

设置变量（把 EIGHTSLEEP 换成本项目根目录的绝对路径）：

  EIGHTSLEEP="/Volumes/My Passport/EightSleep"
  GHIDRA_PROJECT_DIR="/Users/dangbei/Downloads/eightsleep-firmware-research-20261107/analysis/account-readonly/k60-binding/nonusb-flow/ghidra"
  SCRIPT_DIR="$EIGHTSLEEP/report/analysis-tools/system-deepening/sensor-nonusb-dispatch/scripts"
  HEADLESS="/opt/homebrew/Cellar/ghidra/12.1.4/libexec/support/analyzeHeadless"
  export JAVA_HOME="/opt/homebrew/opt/openjdk@21/libexec/openjdk.jdk/Contents/Home"
  export PATH="$JAVA_HOME/bin:$PATH"
  D="$EIGHTSLEEP/report/analysis-tools/system-deepening/upstream-clock-selection"

  "$HEADLESS" "$GHIDRA_PROJECT_DIR" NonUsbSensor \
    -process firmware-sensor-g0.bbin -readOnly -noanalysis \
    -scriptPath "$SCRIPT_DIR" -postScript ExportSensorDiff.java \
    "$D/pass1" 080108ac 08010960 0800cd24 0800c828 0800c8dc 0800cdb4 08019f7c 0801d6f0 0801d888

  "$HEADLESS" "$GHIDRA_PROJECT_DIR" NonUsbSensor \
    -process firmware-sensor-g0.bbin -readOnly -noanalysis \
    -scriptPath "$SCRIPT_DIR" -postScript ExportSensorDiff.java \
    "$D/pass2" 08010bfa 08010c72 080119ce 080120bc 08011570 08011e50 0800e9ba 0800ea20 0800ce00 08008174

  "$HEADLESS" "$GHIDRA_PROJECT_DIR" NonUsbSensor \
    -process firmware-sensor-g0.bbin -readOnly -noanalysis \
    -scriptPath "$SCRIPT_DIR" -postScript ExportSensorDiff.java \
    "$D/pass3" 080114bc 08011914 08011d90 08012008 0800e8b4 08008952 08009550 080112e8 08011a74 \
      "08010bd0:08010c90" "080241cc:08024210"

  "$HEADLESS" "$GHIDRA_PROJECT_DIR" NonUsbSensor \
    -process firmware-sensor-g0.bbin -readOnly -noanalysis \
    -scriptPath "$SCRIPT_DIR" -postScript ExportSensorDiff.java \
    "$D/pass4" 0800f58d 0800f719 0800f969 0800fc05 0800fc99 0800fd25 0800fd31 "0800f680:0800f6a0"

  "$HEADLESS" "$GHIDRA_PROJECT_DIR" NonUsbSensor \
    -process firmware-sensor-g0.bbin -readOnly -noanalysis \
    -scriptPath "$SCRIPT_DIR" -postScript ExportSensorDiff.java \
    "$D/pass5" "0800fd20:0800fd50"

说明：

  - -readOnly -noanalysis：只读打开既有工程、不自动分析、不写回工程。
  - ExportSensorDiff.java 内置 SHA256 守门，输入不是 51531576…c6a891 会直接报错退出。
  - 传函数内部地址可以，脚本会解析所在函数；function=none 时只输出 TARGET/REF_TO，
    这种区域改用 start:end 范围导出（只 dump 已解码指令，不改反汇编）。
  - 080241cc:08024210 范围导出为空是预期：那是数据表，没有指令，表字节由核验脚本直接断言。
  - 重跑会覆盖 pass* 里的导出文本；要保留本次产物就先另存目录。
  - 交付包不依赖这个 Ghidra 工程。工程丢失时，已发布结论仍可用第「一」步复核。
