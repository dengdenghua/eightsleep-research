Keeson 10211：全局故障 B 的输入、触发和清除链
研究日期：2026-11-08（Asia/Shanghai）

结论
本轮将旧报告的全局故障 B（RAM 0x20003f56）向前追到四路采样处理，向后追到停机请求、故障状态组包和条件清除。它不是四个独立的电机故障字段，也不能将本轮读到的数值直接标成安培或机械过流阈值。新增的关键点是：输入已经过两级滤波、基线扣除和置零；检测门控不成立时保留累计值；清除 B 不要求本次采样恢复正常。

一、材料与核验
样本是 MTK 包内的 OTA_KS8S08C010000001_V10211_nRF52832_202602070917.zip。ZIP 中的 nrf52832_xxaa.bin 与旧研究提取物逐字节相等：73,656 bytes，SHA-256 1856c1baec5f9bca7151e5b550fdf0a8d749e87f889d963a3a343293a4160966。
本轮复用既有 Keeson10211 Ghidra 数据库，以 -readOnly -noanalysis 导出 19 个选定函数，没有重跑全量分析或执行目标程序。保留完整选定函数伪代码、带原始字节的反汇编和交叉引用。1,067 条指令、2,844 bytes 全部与原 BIN 对应位置一致；没有不匹配。
应用字节映射是 VA = 文件偏移 + 0x26000，覆盖 [0x26000, 0x37fb8)。数据库 imageBase 元数据为零，不能拿它替代这一实际映射。0x28358 含位于 0x275c0 的共享尾部，已保留。包内不含本轮可分析的 SoftDevice 和 bootloader。
目录中的 .c 是 Ghidra 静态伪代码，不是原厂源码；关键浮点返回值、截断和存储操作以 .asm.tsv 为准。SOURCE_MANIFEST.json 记录原件和全部导出的 SHA；RAW_EVIDENCE.json 保存逐指令映射；VALIDATION.json 保存回读结果。EVIDENCE_MAP.json 提供文件、行号和地址索引。

二、调用时序：先处理清除条件，再采样与检查
0x2cb6c 经 0x2ca48 注册回调 0x2c70d（Thumb 地址），启动参数包含 0x148。本轮没有闭合底层时钟、预分频和定时器启动语义，因此不把这个参数或下述计数写成 ms / s。
0x2c70c 的选定顺序是：0x2b970 增加全局 tick → 0x28cb0（其中调用 0x2b70c）→ 其他处理 → 0x279cc。0x279cc 仅在 0x20002ae8 == 1 时执行 0x28ed4 采样处理、其他调用、0x28358 故障检查，然后清除此 ready 字节。外层回调末尾再将其置 1。
这说明本次选定调用路径中，B 清除逻辑发生在新的采样检查之前。它不证明实机上观察到某个瞬态，也没有审计所有中断和并发调用。

三、B 使用的数值来自哪里
0x28ed4 为四路样本各准备一个初始化为零的 short，依次调用 0x29530 → 0x33df0，通道参数为 0、1、2、3。
0x33df0 检查忙字节 0x200053cc；忙时直接返回 0x11。非忙路径设置忙标记，经 0x33178 写输出指针与数量 1，触发外设后最多轮询 10,000 次，清理后返回 0。所审循环耗尽路径没有单独返回超时错误。调用方没有检查这些返回值。因此不能保证每一路都是刚取得的新样本；忙返回等路径可留下调用前的零值。这也不是已经测得的丢样率。

对每一路 i，第一层 0x30748 使用以下标量更新（实际运算为 float32）：
  P' = P + 0.05
  K  = P' / (P' + 10.05)
  X' = X + K × (sample - X)
  P  = (1 - K) × P'
P 位于 0x2000354c + 4*i，临时 P' 位于 0x20004980 + 4*i，X 位于 0x20004990 + 4*i。这里没有补造初始化条件。
Ghidra 对 0x30748 的返回类型识别不可靠；汇编在 0x30784 更新 s0，0x30790 存储，0x3079c 返回。0x28ed4 随即从 s0 取值，故不能照伪代码中的 void / extraout 解释成“没有返回滤波值”。

第二层平滑为 Y = 0.7 × X' + 0.3 × Y_old，Y 位于 0x200049b0 + 4*i。之后计算：
  residual_i = int16(truncate_to_int32(Y - baseline_i))
baseline_i 位于 0x200049c0 + 12*i；residual_i 是 0x20003be4 + 0x28*i 的有符号 16-bit 字段。
只有四路运行状态字节（0x20003be1 + 0x28*i）都为 2 时，才检查各路时间戳的年龄；年龄 > 2 时，将该路 baseline 更新为 Y。时间来源 0x2b8f0(2) 是 tick / 100，真实 tick 周期未证。其他状态下更新时间戳并清另一逐轴字段。残差计算在基线更新之前，更新主要影响后续调用。
该轴状态为 2，或已截断的 residual < 0，或 residual > 0x7f00，都会将 residual 置零。故这里的零值可以来自状态门控、范围处理或未更新的输入，不能直接等同于物理负载为零。

四、故障 B 的产生条件
0x28358 首先要求四个字节 0x20003f74..0x20003f77 全部 < 30；旧研究将这组字节归入 PWM 相关状态。仅在门控成立时，它才重新检验四路 residual。
每路先按 float32 执行 residual × 3.515625 × 1.5 ÷ 0.235，再转为 int32 并取有符号低 16 位。实际存储常量 0.235 是 float32 的 0.2349999994…，详见 VALIDATION.json。四路通过区间分别为：
  轴 0：[-561, 561]；轴 1：[-471, 471]；轴 2：[-538, 538]；轴 3：[-471, 471]。
这是转换后整数的区间；低 16 位截取可能改变符号和数值，不能简化成原始残差或电流的单调阈值。
四路全部通过时，8-bit 累计 C（0x20002add）清零并立即返回。任一路不通过，C 加一并按字节保存。门控不成立则跳过检验及清零，保留原 C，仍继续下面的 C > 50 判断。
C > 50 时设置 B = 1，调用 0x2af68 停机请求，再调用 0x27eec 组包故障状态。从 C=0 开始至少需要 51 次符合门控的异常检查；不能写成“连续 51 个周期”，因为门控不成立可能暂停累计而不清零，且此后仍可触发。C 本身还是会回绕的 8-bit 字段。
触发之后若四路处理后的 residual 恰好全为零，则 H（0x20002af0）置 500，C 清零，并清四个全局标志。这不是每次故障都执行的固定冷却分支；尤其不能省略“触发后四路 residual 全零”的条件。

五、清除条件与停机边界
0x2b70c 先处理若干命令寿命计数，然后仅在两个命令字 0x20003d90 和 0x20003d9c 均为零时进入 B 的保持/清除分支：
  H 非零：H 减一；四轴的两个软件状态字节均写 2；清四个全局标志；返回，不清 B。
  H 进入该分支时已为零：B 清零。
因此，若 H 初值为 500 且条件一直满足，需要 500 次减计数，再在下一次满足条件的调用清 B。H 刚减到零的那次不清 B。这里没有重新要求采样健康，也没有已证的固定秒数。若 C 仍 > 50，后续检查仍可能重新设置 B；本轮没有用真实运行记录验证反复置位的频率。
0x2af68 会清多个自动/目标状态和目标值，但只有 0x275a0 返回零（RAM 0x20003530 == 0）才遍历四轴，将非 2 的运行状态改成 2 并请求输出更新。该门控可以跳过这段遍历。即便软件状态已写为 2，也不能直接宣称四台物理电机已立即停转；外围驱动、时序与机械状态不在本轮证据内。

六、外发故障字段的含义
0x27eec 仍按全局 A（0x20003f57）优先输出 2；A 未置位而 B 置位时输出 1；两者都未置位输出 0。同一值复制到四个外发字段。这个事实沿用并复核了旧报告的组包结论；本轮新增的是 B 的具体输入和生命周期，不是发现四套独立过流判断。没有追全 A 的生产者/清除链，也没有将 B 命名为某种确定的硬件故障。

七、覆盖与下一步
已闭合：选定定时回调 → 采样与两级处理 → B 的门控/累计 → 停机请求与故障组包 → 条件清除。19 个函数为定向证据，不代表应用全部执行路径已恢复。
未闭合：外设通道与板上采样电路/四个物理轴的映射；增益、基线初值与物理单位；真实定时周期；全局 A 链；全部状态写入者与中断交互；电机输出寄存器到硬件驱动的实际动作；SoftDevice/bootloader 与其他固件版本。
优先下一步是从 0x200053d8/0x200053d9 的初始化及通道配置写入者闭合输入来源，再核对 0x2cac4 的时基；有原理图或板照后再解释量纲。另一条独立任务可追全局 A 的置位/清除与四轴输出函数，避免把当前 B 的结论套到全部故障。
本轮只读本地文件并运行反汇编导出/原字节校验；没有发命令、连接附件、执行升级或更改实机。
