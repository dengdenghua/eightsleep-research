nonUSB hwrev 14 项分派表全表映射
2026-11-08；只读静态复核。不执行固件、不连接设备/账号/网络，不改写历史证据文件，不改写 Ghidra 工程。

结论（置顶）

1. 上一轮「14 项全表映射未穷尽」已闭合：0x08025da4 的 14 个阈值行、0x08024234
   的 14 个版本字符串、14 个 setter 之间建立了**一一对应**，定位依据是每个 setter
   的 literal pool：14 个字符串指针在整个镜像中各只出现一次，位置与 setter 一一相扣。
2. 上一轮「字符串序 K10/K05 与数值序不同，不强行配对」现在有确定答案：字符串表
   索引 4/5 是 K10/K05，而阈值表第 4/5 行是 K05(0x0A05)/K10(0x0A10)。
   两张表顺序确实相反，但 setter 各自指向自己那条字符串，不存在歧义。
3. 上一轮「0800fd25 / 0800fd31 无已解码函数体」也已闭合：这两个地址不是空洞，
   而是工程没有反汇编的两段极短 Thumb setter。从冻结文件的原始半字解码：
   - K87 @0x0800fd24：`ldr r3,[pc,#4]`（→0x0800fd2c = 0x08024264 "K87"）、
     `str r3,[r0,#0]`、`bx lr`、padding。只写版本名。
   - K90 @0x0800fd30：`ldr r3,[pc,#12]`（→0x0800fd40 = 0x08024268 "K90"）、
     `movs r2,#0`、`str r3,[r0,#0]`、`movs r3,#0xc6`、`lsls r3,r3,#1`（=0x18c）、
     `strb r2,[r0,r3]`、`bx lr`、padding。写版本名并把配置对象 0x18c 字节处清零。
   逐半字解码器与预期语义、literal 值、原始字节都在核验脚本里复算。
4. 分派是**累加生效**，实际调用次数是 16 次而不是 14 次：除 14 行顺序执行外，
   K10 setter 先 `bl 0800f968` 完整重放 K00 setter，K33 setter 先 `bl 0800fafc`
   完整重放 K05 setter，两次重放各自覆盖 slot1 后再被本行覆盖。
5. 找到第 7 个 init 槽位候选 08012274（由 K36 装入 slot1）。但它不新增时钟入口：
   函数第一条指令就是 `bl 08012008`，复用上一轮已记录的变体，之后追加 0x48/0x47
   两项外设初始化。全镜像 BL 扫描确认 080108ac 只有 4 个调用点、08010960 只有
   2 个，与上一轮一致，没有第 7 个入口。
6. 把「版本 → 最终 init → 时钟入口 → HSE 软件输入」串起来后得到一张可复算的区间表
   （model/apply_dispatch.py，16 个边界、26 条断言 0 失败）：
   - I00/I05/J00 → init 08010bf4 / 08010c6c → 080108ac → 32000000
   - K00/K05/K10 → init 080114bc / 08011d90（K10 重放回 080114bc）→ 08010960 → 8000000
   - K30/K33/K34/K35 → init 08011914 / 08012008 → 080108ac → 32000000
   - K36/K37 → init 08012274 → 复用 08012008 → 080108ac → 32000000
   - K87/K90 → 同一个 init，但 hwrev 落入 0x0A87..0x0AFF，080108ac 改写为 16000000
   即 080108ac 里那句 `hwrev - 0xA87 < 0x79` 的边界**正好从 K87 这一版开始**，
   这一版起 HSE 软件输入由 32MHz 降为 16MHz。上一轮只能说「不知道 K87 对应什么」，
   现在至少能说它在时钟配置上是一个明确的分界。仍没有证据把它绑到营销型号、板型
   或外部晶振。

  行布局 `[u16 threshold][u16 pad][u32 callee]`；`0801d8cc` 的 `cmp r5,#0xe`
  原字节 `0e 2d` 固定 14 行；分派循环 `0801d8b4 ldrh r3,[r4,#0x10]` 读 hwrev，
  `0801d8c0 bhi` 决定跳过，`0801d8c4 ldr r3,[r4,#0x4]` 取 callee。
  字符串表物理顺序：I00 I05 J00 K00 **K10 K05** K30 K33 K34 K35 K36 K37 K87 K90。

二、setter 的其它副作用（如实记录，不强行解释语义）

  - I00（默认）写满整个配置对象，含 slot0x14=16000000、slot0x1a=8000000。
  - K00 大 setter 改写大量槽位，出现 4000000 / 2000000 常量、slot0x62=2。
  - K34：`sku == 4` 时选 0x08025f08，否则 0x08025f00，写入 slot0x1a4。
  - K35：把 slot0x194 旧值备份到 0x2000135c，再用 08011101 覆盖。
  - K37：把 0x08025ee8 写入 slot0x1a4（与 K34 同一槽位）。
  - K90：额外把配置对象 0x18c 字节处清零。
  - I05 / J00 / K30 / K33 / K36 各自还写若干回调指针与超时（200、10000、30000）。
  这些都只是配置槽位的静态赋值；它们对应哪个外设、哪条业务路径本轮没有证明。

三、init 与时钟入口的调用图（全镜像 BL 扫描）

  080108ac ← 08010bfa / 08010c72 / 080119ce / 080120bc     （4 处，写 16 或 32MHz）
  08010960 ← 08011570 / 08011e50                          （2 处，写 8MHz）
  08012008 ← 0801227a                                     （第 7 个 init 复用）
  0800f968 ← 0800fae4                                     （K10 重放 K00）
  0800fafc ← 0800fc68                                     （K33 重放 K05）
  扫描方式：对镜像每 2 字节半字对做 Thumb-2 BL 目标重算，命中上述 5 个目标即记录，
  不是靠工程里的函数识别或引用列表。

四、字节核验与模型

  scripts/verify_dispatch_map.py：**109 项检查 0 失败**。含 525 条导出指令行逐字节
  对回冻结 BBIN、135 个 flash literal、7 个 BL 目标、8 个直接分支目标、两张表、
  14 个字符串 literal 的全镜像唯一性、14 个 slot0 写入、7 个 slot1 写入与 literal、
  两段原始 Thumb setter 的字节与解码语义、5 组 BL 调用点集合。
  model/apply_dispatch.py：16 个 hwrev 边界、**26 条断言 0 失败**，输出每个边界的
  最终版本名、init、时钟入口与 HSE 软件输入。
  两个脚本都只把固件当数据读，Ghidra 工程丢失也不影响复核。

五、边界

  - 全部是静态字节与有限整数模型。HSE 字段是 0800cd24 在 HSE 分支读取的**软件输入**，
    不是实测晶振、不是核心时钟；运行时 RCC_CFGR 的时钟源选择仍可改变最终公式。
  - 14 个 ASCII 标签不等于营销型号、板型或硬件 BOM 的绑定，本轮没有建立这种绑定。
  - 0x18c 字节清零、0x08025f00 / 0x08025f08 / 0x08025ee8 三张数据表的内容、
    以及各 setter 写入的回调/超时槽位语义，均未解码。
  - 仍未闭合：writer 2 (0800c8dc) 的 PLL 配置解码、两个配置入口局部结构体到实际
    核心频率、切换过渡与累计 tick 损失、实机 PLL lock / 中断延迟 / ADC 时序。
  - 上一轮两个 callee「无函数体」是工程状态描述，本轮用原始字节补上；历史证据文件
    与上一轮 Wiki 一律不改写，用本页与新增「后续更新」段承担修正。
  - 气囊与床架仍暂缓；核心生理算法、Autopilot、姿态分类、实机绑定、音箱 DSP、
    USB `0x2B` 首次生产者、旧波形 RAW writer 保持原状。共享日志格式缓冲/重入专项
    此前被自动安全检查中止并标记未验收，本轮未重试、未改写措辞、未引用其草稿结论。
