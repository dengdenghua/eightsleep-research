USB 5.5.34.0：实际日志生产者与转义后的长度上界
2026-11-08；限定静态审计与离线有限枚举，未执行目标或访问设备/账号/网络

结论
本轮把上一轮“日志包装器body≤514，但未知是否能跨1024”的缺口收窄了。
在有效格式化、原始固定前缀、无共享缓冲重入和无内存破坏的前提下，本次识别的277个直接日志调用点，其日志文本最多511字节、body最多513字节。正常两字节长度模式的整个转义帧上界为1021字节；即使把长度模式放宽到四字节，仍最多1023字节。因此这些日志不能靠正常长度/转义内容触发1024满槽提交分支。
这是基于固定字节数量的上界，不需要假设动态%s内容短或只含ASCII。未知后缀已经全部放宽为可转义字节，CRC两字节也按最坏转义计算。没有把人工超长字符串称为实际可达日志。
此结果不排除重入：sampling IRQ可能进入日志链是另一个问题，共享log/封包指针被打断修改时，本轮“同一调用保有自己的buffer与计数”前提不成立。也不证明所有间接调用、其他固件版本或实机部署都覆盖。

按调用点分组：

二、511字节怎样从实际写出链得到
0801c8f8的文本源base=200002e6，前4字节初始化为“FW: ”。reset把Flash08032288复制到RAM20000200；因此该前缀原始字节位于Flash0803236e、文件offset0x2236e，为46 57 3a 20，后接00。不是从未初始化Ghidra RAM猜字符串。
包装器在base+4=200002ea先格式化“%lu ”，capacity=508；tick取32位返回值，十进制数字+空格为2..11字节，都无需转义。设其长度为t。
随后从base+4+t调用第二次格式化，capacity=508−t。
本包0802ad90及0802acf8把内部可写量设为capacity−1，并在写指针处补00。内部stream flags=0x208；0802ae20检查扩容mask0x480，二者按位与为0，所以当前snprintf流不走扩容分支。该helper只复制min(剩余量,请求量)，并同步递减剩余量、推进指针；0802b406按给定数量复制。
0802aee0的固定文本及0802b1bc/0802b0dc的转换、符号与填充都经该写出callback。终止符位置不超过：
  4 + t + ((508−t)−1) = 511。
因此后续strnlen(base,512)在这些正常格式化条件下至多返回511，而不是粗略容量界512。若转换提前输出00或结果更短，只会缩小后续文本。
文本前至少包含FW:的4字节、tick的至少2字节、当前format首次转换前至少4字节，共10个无需转义的字节。后面%s、%c等可能产生的任意有效内容都可以按最坏情况放宽，无需逐个证明它们短。
本轮未证明错误指针、内存破坏、重入或异常格式化状态下也满足上述契约。

三、实际长度字段与完整上界
0801c764生成：未转义7e | 长度字段 | body | 两字节校验。后面三段对7d/7e转义；长度字段宽度为global==4则4、==2则2、否则1。
配置表14个callback已单独导出：08018bd0写config+0x188=1；阈值rev>=0xA00的08018fb0将其改为2；其余所审配置callback没有再改该字段。初始化08027920复制至2000a914，当前该全局既有引用中仅此一处直接写入。K系列对应的>=0xA00配置链得到2，但不能据此绑定用户设备当前版本。四字节模式仍作为防御性放宽一并计算；一字节模式的字段截短不改变encoder收到的完整body长度。

定义：
  n = log文本长度，10<=n<=511；p>=4 = format第一次转换前的普通字节数；t>=2 = tick文本长度。
  N = n+2 = body长度；body头为07、u8(n)。
  E_len = 实际N按w字节编码后，其中7d/7e字节的数量（w=1时截低8位）。
  E_body <= n−4−t−p + esc(u8(n))；07不转义。
  CRC原始2字节，最多额外增加2字节。
则整帧：
  T <= 1 + w + E_len + (n+2) + E_body + 2 + 2。
这里逐项计算真实长度字段与body头，不是把通用1041上界随意减去一些前缀。

遍历全部n=10..511和w=1/2/4，共1506个组合，放宽取p=4、t=2：
  w=1：T<=1020；w=2：T<=1021；w=4：T<=1023。
最大界均在n=511处：N=513；两字节长度0201、四字节长度00000201均不转义；body头07ff亦不转义。日志文本中保留10个普通字节，剩501字节全部按可转义放宽。
正常两字节例：1(marker)+2(length)+513(body)+501(body额外转义)+2(CRC)+2(CRC额外转义)=1021。
长度/头部某个字节恰为7d或7e的小n组合也已纳入枚举，例如N=125/126以及n=125/126；它们远小于最大n组合，不会遗漏局部转义峰值。
1021/1023是保守上界，不是已构造并证明可达的实际日志长度；真实CRC取值和format固定后缀通常继续减小结果。

四、验证与仍未覆盖的边界
scripts/model_log_bound.py共7项检查通过，BOUND_ENUMERATION.json保留1506项逐字段计算；MODEL_RESULTS.json保留最大值及前提。测试覆盖capacity−1与终止位置、uint32时间位数、全部格式前缀、长度字节与body头转义、各宽度完整枚举，以及放宽后缀示例。
示例只验证上界公式，不执行原printf、不执行固件，不声称人工后缀是一个真实调用者参数。字节校验与有限模型不能推导实机发生率。
原指令字节核验通过：16738个唯一地址、36764个唯一字节；计重导出25672条/57458字节；2510个flash literal、2503个BL/B.W目标一致。另逐条核277个logger直接BL目标、337个字符串原字节及17个literal加载公式。最终文件哈希见SOURCE_MANIFEST。

已闭合：旧255点及新增22点的format候选集合；日志公共格式化截断；固定前缀的reset来源；长度字段逐字节计数；无重入时这些调用无法到1024的保守界。
未闭合：任意未知间接调用/动态代码、255旧表之外未在选定owner出现的调用、全部字符串实参生命周期与内存安全、真实部署版本、日志与framer共享global的抢占/重入、USB消费时序。
所以不能写“全固件不存在发送问题”。可以写“所审普通生产者及已识别日志在无重入有效输入下均不足1024；不再把正常日志长度本身列为未解触发源”。重入和异常接收payload仍应单独追踪。

本轮也为并行的重入审计保留了计时helper、HardFault、timer入口和已识别mask指令清单；这些附带导出本身不构成重入已实测结论。重入结果以独立报告为准。
