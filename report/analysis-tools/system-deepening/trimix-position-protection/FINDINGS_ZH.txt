TriMix V25：位置状态写入者与保护输入生产链
静态证据补充，2026-11-08；未运行固件、未连接设备、未生成控制流量。

可引用结论
1. phase1 使用的四个“当前位置”是软件计数状态：GPIO 输入的已接受电平变化触发
   09F58，按锁存方向 AA/55 做有上下界的 +1/-1。它们还会被启动恢复和端点校正覆盖，
   因此不能等同于绝对角度、位移或直接测得的机械到位。
2. 1464E 保护比较的输入来源已闭合到 5×16-bit 的 ADC/DMA 缓冲，实际入口是完成标志
   0x2 触发的 18CFE。第一路 r0 来自 20007FE6，其余三路为 20007FEA/FE8/FEC。
   已核的正常调度是“启动扫描→完成 IRQ→读取/比较→完成标记→下一次启动”，
   不是主循环无条件重复读取旧值来给这一保护计数加一。
3. 端点校正读取的是另一层处理结果缓存 200077AC/AE/B0/B2；其更新依赖主循环 14822。
   所以“连续 200 次校正检查”不能写成 200 份新样本，也不能直接换成毫秒。

一、输入身份及地址规则
原件：mediatek/rootfs-selected/opt/eight/firmware/8Sleep_H6_SW-V25-2025-07-24.bin。
原件 71056 字节，外层头 128 字节；payload 70928 字节。
payload SHA256=b5099dad86bd475a3e0fc5a208d6921eccb3302e176bc9876d795475f875f239。
VA=0x08008000+payload_offset；原包偏移=VA-0x08008000+128。
原包 SHA256、头部 SHA256、逐条字节核验见 RAW_FACTS.json / BYTE_VALIDATION.json。
Ghidra 工程只读、noanalysis；没有修改函数边界、指令或 SRAM 属性。
既有 SRAM 标为 write=false；本次只设置本地反编译选项 RespectReadOnly=false。
若 C 伪代码与共享尾/寄存器约定冲突，以下结论以原指令为准。

二、四个计数值如何改变
软件 selector / 计数参数 / 状态 / 输入掩码 / 锁存方向 / 上下界地址：
  1 / 0 / 20007F1A / 0x8 / 20007BCB / 20007E8C、20007E8E
  2 / 1 / 20007F1C / 0x4 / 20007BF3 / 20007E96、20007E9A
  3 / 3 / 20007F20 / 0x2 / 20007C43 / 20007EA2、20007EA6
  4 / 2 / 20007F1E / 0x1 / 20007C1B / 20007EAE、20007EB2
这里保留旧报告的 selector，避免把 RAM 顺序误当成 selector 顺序。
GPIO 读取均为 MMIO 40011408 的对应位，经 09D10/14/1E/22→D54A 返回 0/1。
未据此确定板上丝印、传感器类型、线束或每圈脉冲数。

09F58 的实际 TBB 表位于 08009F66，原字节 02 14 3A 27，四个目标为
9F6A、9F8E、9FDA、9FB4；不是按相邻函数相似性推断的四路映射。
每次调用：锁存方向为 AA 且 P<上界时 P++；为 55 且 P>下界时 P--；否则不变。
这不是每个完整周期只加一次：当前证据计的是被接受的电平变化。
不要把“计数随脉冲变化”改写成“编码器绝对位置已经恢复”。

有两条输入接受路径：
A. 四个向量入口 18E6E/18EAE/18EEC/18F3E，分别对应掩码 8/4/2/1。
   先读 GPIO，再检查 40010400 的使能位及 40010414 的 pending 位，条件满足时清 pending。
   仅当当前 GPIO 值不同于轴结构 +0xE 的已接受值，才更新该值、递增 +0x8 事件计数，
   并经共享尾 18EE4→18EE8 调用 09F58。未改变则不调用。
B. 向量 18E34 检查/清 MMIO 40001C00 的事件，通过参数 13 进入 18A6C，
   187B4 还要求 20007FA8==AA，然后进入 A182 扫四轴的 GPIO 回调。
   与 +0xE 相同则清 +2/+4 计数；不同电平需要对应连续检查计数达到 10，
   才调用 09F58、更新 +0xE、递增 +8，并把 +0xC 置 1。
两条路径共享已接受值；这可抑制同一稳定电平被顺序重复计数，不能证明不会丢边沿、
不会在中断嵌套或快速抖动时出错。NVIC 配置/抢占优先级和实际输入时序未在本轮穷尽。

计数使用的 +0xF 锁存方向与 phase1 主方向字节不是同一位置。
A14A 的已核路径：主方向经 +0x18 指针读到 35，而 +0xF 仍不等于 35 时，
递增 +0xC；达到 5001 次这类检查后，将 +0xC 清零、+0xF 置 35。
该路径来自 18DB2→参数 2→187C2→A14A。不能把 5001 次直接写成固定秒数。

三、恢复、清零和端点覆盖
启动路径 108D8→1376C：先 A000 设置结构和边界，再 FC76 恢复。
A000 从 20007984/86/88/8A 设置四个计数上界，把对应下界写为 0；配置来源尚未追透。
FC76 经 A800 从 flash 地址 080FF800 读取 7 个 halfword 到 20007FD0。
FD9E 计算的校验值与第 7 个 halfword 比较：
  不相等：FCB6/B8/BA/BC 把四个计数状态全部清为 0。
  相等：恢复四个 halfword，并分别按当前上界封顶；不等于每次开机必然归零。
080FF800 超出当前 payload 地址范围；实机保存内容不包含在这份固件里。
本轮保留了 FD54 的保存入口作为证据，但没有闭合所有保存触发/掉电一致性。

另一组写入者是 17642、1789A、17B20（数据库归在 17D34 内）、17ED2。
它们分别由 1785C、17ADC、17D34、18114 包装调用；真实调度来源为
18DF0→参数 6→18A6C→18800，且 1882C 处要求 20007FA8==AA。
满足各自条件时，两个计数器分别累积；达到 200 后写上界或下界，并把对应完成字节置 AA。
各轴写位置的两处地址：
  P1A：176AE、17702；P1C：1792E、17990；P20：17BB6、17C18；P1E：17F66、17FC6。
共同约束包括“尚未完成”、对应处理结果 <14；上界分支还检查状态字节为 AA 和位置>
参考值；下界分支检查状态字节非 AA，并要求本轴 +8 事件计数与上次记录相同。
方向条件有非对称处：轴1上界允许 20007E0C 的备用方向；另三轴上界直接检查主方向。
四轴下界均有备用 55 方向路径。细节见各原指令，不能只套一个统一对称伪代码。
条件不满足时对应累积计数清零；200 次是调用次数，未证固定间隔或每次使用新采样。
写下界在 A000 的初始配置下会得到 0；运行期配置的所有改写者没有穷尽。
这些是软件校正条件，不是已独立验证的机械端点。

四、1464E 的输入由谁填入，何时读取
12C20 配置链和 11E1E 的寄存器写入已对上：
  DMA 通道结构基址 40020008；源 4001244C；目的 20007FE4；传输数量 5。
  配置字段合并为 0x25A0，随后开启中断位 0x2 和通道位 0x1，得到 0x25A3。
  对应字段为外设固定、内存递增、两侧 16-bit、循环缓冲；这里保留寄存器值以便复核。
  采集外设基址 40012400：扫描开关字段为 1，连续转换字段为 0，长度字段为 5。
  五个 rank 写入通道号依次 0、5、6、14、4，采样时间字段均为 0。
  12D66 首次通过 17350 将 CR2 对应位置 OR 0x500000，启动一轮扫描。
以上是固件配置及标准寄存器布局解释；实机芯片型号/时钟、电路信号种类和物理单位未实测。

原向量表 slot 27 存 08018CFF。18CFE 调 11F3E(2)，读 40020000 的 bit 1；
若未置位立即返回；若置位则经 11F54(2) 写 40020004 清标志，然后转到 145F8。
145FE 绑定缓冲基址；14602 将第二个 halfword 20007FE6 读入 r0。
因此 1466C 的 r0 已找到直接生产缓冲，并非未绑定的函数参数。
四轴保护输入与 ADC rank：
  selector1：20007FE6，rank2 / channel5；selector2：20007FEA，rank4 / channel14；
  selector3：20007FE8，rank3 / channel6；selector4：20007FEC，rank5 / channel4。
rank1 / channel0 进入另一路处理，没有证据把它归为第五个执行轴。

对应保护使能 byte==1 时，值低于阈值则把连续命中计数清零；达到/超过阈值则
写调试环形缓冲、计数加一；计数>=5 才进入后续原因/保护处理。
这里不把后续 17614/1786C/17AEC/17EA4 的全部延迟/执行语义写成“立即机械停机”。
147BA 在所有这些比较之后把 200074CC 写 AA。
18DB2 的参数 2 路由进入 187C2；仅看到该标记 AA 时先清 0，再调用 17350 启动下一轮。
因此在所核正常配置/事件路径下，每次这段保护检查都跟随完成事件，下一轮重启在尾部标记之后。
固件未给每项增加时间戳/序号；它也没有在该段验证传感器是否卡值或采样内容是否有效。
“新完成一轮搬运”不等于信号一定新鲜、所有通道严格同时、没有 DMA/硬件异常。
未核实际启动间隔，5 次不能换算为 5ms；不能由阈值数字直接推安培。

五、另一层缓存影响端点校正的新鲜度
145F8 还把五个值写入 200074CC 结构的五段数组。正常索引从 0 到 39，
第40次写入后将索引改为100。之后 IRQ 仍做1464E保护，但不再往这批数组追加。
主循环 10952 调用 14822；仅索引>=100 才处理这批数组、更新 200077AA/AC/AE/B0/B2，
最后 1497E 将索引清零，恢复下一批积累。
本轮核实处理结果的读写/门控，没有完整审计 147DE/149C0/浮点 helper 的滤波算法。
端点校正和外围慢保护读取的 AC/AE/B0/B2 是这层缓存；若主循环未消费完，
定时器可以再次检查同一份值。因此两条保护/校正链不能共用“每次都是新样本”的结论。

六、覆盖边界与值得继续的问题
已闭合：四个直接计数更新分支及实际 TBB；GPIO输入/中断与轮询两条接受路径；
已识别直接恢复/清零/端点覆盖；1464E输入缓冲、DMA配置、完成入口和重启握手；
处理结果缓存与端点校正的更新节奏差异。
未穷尽：任意指针别名/整块内存写入、所有配置改写、GPIO/EXTI/NVIC初始化与抢占顺序、
所有保存入口、所有下游保护动作、所有硬件异常路径。不能把直接xref清单称为全固件无遗漏证明。
源导出里的 function owner 不是运行调用链：例如 18D98 实际传10，不能因其数据库
函数体包含 A182 就当作轮询入口；18DD6 实际传5，不能因其函数体包含18800就当作校正入口。
