USB 传感固件：逐发送入口长度、转义膨胀与 1024 字节提交边界
2026-11-08；限定静态代码 + 离线行为模型；未运行固件或访问设备/账号

结论
1. 正常 0x3c 原始数据体固定 377 字节。即把所有内容、长度字段和两字节校验全部放宽成最坏转义，整帧也不超过 767 字节。因此不能拿这条正常采样链证明 1024 分支在实机可触发。
2. 已识别的其他数据、事件和状态发送体不超过 216 字节；已审的正常命令回复生产链最大 130 字节。回复缓冲“容量 512”不能当成“现有命令会生成 512 字节”。
3. 唯一尚未被长度上界排除的近界入口是日志包装器：strnlen(...,512)+2 给出数据体不超过 514 字节的保守界。它有 255 个已识别直接调用点，本轮保留这些引用并检查公共包装器，但没有证明存在某个真实格式/实参组合能产生足够的 0x7d/0x7e 跨过 1024。上界大于 1024 不是可达性证据。
4. 封包器本身的条件行为已闭合：写入偏移达到 1024 就提交；提交函数只将偏移归零，不重新选择缓存槽。当前发送回调保存原指针供发送或排队，未复制该槽内容。因此如果同一帧确实还有字节要写，且回调没有改变全局槽指针，随后会从同一槽 offset 0 继续写。若之前提交的指针仍在被读取，便存在覆盖其内容的条件；实际 USB 是否因此损坏、是否来得及取完，未实测。
5. 在本轮模型限定的无重入、合法初始状态下，每次输出字节前都先检查偏移，写入 offset 只在 0..1023。这里确认的是“交出去的槽继续被改写”的所有权条件，不是已经证明向 slot[1024] 写越界。

A. 封包和提交的确切顺序
0801c764 有两个已识别直接调用者：0801c8c8（计数后转发 ptr/len）与 0801d594（发送挂起的命令回复）。
每次选择 32 个槽中的一个；槽步长 0x401 = 一个状态字节 + 1024 字节数据。数据指针是 200028c4，状态指针是 200028c8，输出偏移是 2000a8ec。选择失败达到计时阈值后会清数据/状态指针；该失败路径不等于一个成功发送的大包。
成功选槽后按顺序输出：
  未转义起始字节 0x7e；长度字段；body；校验函数返回值的低16位按大端两字节；最后提交。
长度宽度的代码分支为 4、2，否则1；初始化把配置值大于4的情况钳到4。本报告对 w=1/2/4 全部成立，不额外声称具体设备当前采用哪个配置。
长度字段1/2字节分支仅截短字段；body encoder 和校验调用仍收到原 uint32 长度。现有正常生产者长度另行分析，不能靠字段宽度替代生产者长度检查。
080292a0 把 0x7d -> 0x7d 0x5d、0x7e -> 0x7d 0x5e，其余字节原样写入。每个输出字节前和每段 encoder 末尾调用 08029280。
08029280 在 offset >= 0x400 时调用 08029254。08029254 调用当前 callback(data, offset, status)，然后仅写 offset=0；没有换槽操作。
初始化 08027834 将 callback 设为 0801d6fc。已导出的 0801d6fc 在直接发送或排队成功路径保存 data/length/status 指针，设置 status=0；gate/队列满失败路径记录失败。该函数没有改变 200028c4 / 200028c8。失败返回也没有向 encoder 提供“停止写入”的控制结果。
这里只结合已经审过的 USB 队列持有原指针事实；底层 PMA 实际读取、完成回调和迟到回调细节仍见先前 sensor-usb-packet-read / sensor-usb-lifecycle，未重复扩展。

长度依据与容易漏掉的共享分支：
- 0x3c：9 字节固定头 + 5*64 字节 ADC 序列化 + 48 字节 IMU = 377；266dc 输出16个大端32位值。该分支在 1f9aa 直接跳进 1f374 的 BL，绕过 1f370/1f372 的参数设置。只看函数调用 xref 会漏掉这个生产者。原分支和引用均单独导出。
- 0x34：6 +4+4+2 +25*(4+4)=216。1bca0 在可用空间>3时写/返回4，否则0；这些固定循环的剩余空间足够，因此长度不是“最多256”。
- 0x35：12 +4 +10*(4+4+4+4)=176，同一 helper 的容量条件均满足。
- 1fd8c：两字节头 + 1或2个17字节条目；1fe92：4 + (16或21)。
- 27636：26ec8 已审返回15或17，调用者加4。
- 日志：1c8f8 先格式化 tick，再格式化 caller 文本，最后调用 2ad7a(source,512)；发送长度是返回值+2。这是无须假设 printf 内容的保守界。格式化终止符、固定前缀、数字/ASCII实参可能使实际上界更低，本轮不把它们笼统当成“可构造满512个转义字符”。
- 回复：20fd4 先清 pending length，然后追加 opcode。1bcbc 只追加 min(requested,512-current)；这项界依赖 current 初始在0..512、没有重入/破坏，正常 dispatcher 每次清零。1bcec 追加一个字节状态；主要共享 append 尾部 2100c 和 2122e 的所有已识别入边已列出。数据长度包括1、3、4、5、8、9、15/17、11或15项*3、47，以及最多128字节元数据；最多的正常回复为 opcode1+status1+128=130。2607c 返回时只追加一个状态；26130 成功追加状态+9字节。正常已识别生产者并没有填满512回复缓存。
完整逐项依据在 CALLER_BOUNDS.json；共享分支 refs 文件位于 pass6，相关生产者/序列化 helper 位于 pass2–pass7。

C. 1024 阈值的可达条件与不能据此声称的结论
设 E 为长度字段、body和两字节校验中等于0x7d或0x7e的字节数，w为实际长度字段宽度：
  T = 1 + w + N + 2 + E；T <= 1 + 2*(w+N+2)。
本报告以初始 offset=0、选槽成功、没有重入修改为前提。
- T<1024：单帧不会触发中途满槽提交，最后正常提交一次。
- T=1024：会触发满槽提交，但整帧没有后续字节时不会发生本帧后续复写；不能把“>=1024分支执行”直接等同“内容被覆盖”。
- T>1024：至少一个字节在首个满槽提交返回后继续写入，当前实现使用同一全局 data 指针，offset 从0开始。若提交把该槽原指针交给仍未取完内容的消费者，存在覆盖条件；如果已完全取完或提交直接丢弃，则不能仅凭模型认定数据损坏。
- 转义对本身可能跨提交界线：0x7d落在offset1023，其第二字节落在同槽offset0。仅“转义对拆成两个传输块”不是独立错误，关键是原存储被复用且消费者仍在读取。
- 本轮排除的是上述普通数据/状态/回复生产者通过正常内容转义达到1024；未排除日志真实参数组合、未识别间接入口、内存破坏、HardFault/中断重入。不能写“整份固件所有情况安全”，也不能写“找到已经可触发的 USB 漏洞”。

D. 模型与核验
scripts/model_frame_bounds.py 精确建模字节转义、每字节检查、段末检查、提交后index归零且指针不变；10项测试覆盖1023/1024/1025、转义对跨界、接受持有与直接丢弃、377B最坏长度及所有短包上界。
模型将两字节 trailer 作为显式合成输入，不执行硬件CRC，也不声称合成 body/trailer 来自真实日志。模型不模拟USB时间、总线、DMA、完成回调或重入；证实条件行为，不能替代生产者可达性/实机结果。
BYTE_VALIDATION.json：4737条指令出现、10178字节全部匹配原BBIN；其中4325个唯一指令地址、9292个唯一指令字节。543个flash literal、351个BL/B.W目标重新核对通过。计数允许多个导出间重叠；这些核验保证证据与该原件一致，不替代语义/全部执行路径证明。
SOURCE_MANIFEST.json 记录原BBIN、使用的旧证据及本轮所有输出的 SHA256（清单自身不自哈希）。REPRODUCE.txt 和 COMMANDS.json 保留重放方法。

剩余最有价值的下一步
1. 现在可做：只对日志中可能产生长字符串/大量0x7d或0x7e的格式和实参做定向追踪，证明具体触发者或给出低于1024的内容上界；255个引用不能替代逐路径证明。若没有这样的生产者，应把风险继续降格为封包器条件分支，而非制造一个超长测试包当成实机输入。
2. 现在可做但属于另一项：梳理日志/HardFault和普通发送对共享global buffer的重入保护。当前最长合法包的单线程上界不处理重入，不能借本轮结果宣称该问题存在或不存在。
3. 需实机或新增被动记录：若后续找到真实近界生产者，再核对设备部署版本、实际length宽度、原CRC结果和USB读出完成顺序，判断槽复写是否赶在消费者取完之前。未授权/未执行任何设备构造流量。
