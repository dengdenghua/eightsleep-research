Keeson V10211：位置字段的 GPIO 生产者、替代计数及清零边界
日期：2026-11-08（Asia/Shanghai）。静态只读，未运行固件或连接设备。

结论
0x20003bc8 + 0x28*i 的 P 是一个软件位置字段。正常分支用 P0.21、P0.22、P0.23、P0.24 的下降沿事件更新；方向来自软件 run_state，而不是双相编码器解码。P 还会被模式1的定时替代计数、持久记录恢复和软件清零覆盖。因此，上轮自检的 motor_HallNum 比较确实能连到输入链，但不能无条件解读成“每次比较都来自新收到的 Hall 脉冲”，也不能把 P 换算成毫米、角度或实机采样率。

1. 输入身份和验证方式
样本为 MTK 根文件系统中的 Keeson/OTA_KS8S08C010000001_V10211_nRF52832_202602070917.zip 的 nrf52832_xxaa.bin；与既有分析提取件逐字节相同。BIN 73,656 B，SHA-256 1856c1baec5f9bca7151e5b550fdf0a8d749e87f889d963a3a343293a4160966。应用 VA 0x26000..0x37fb7，对应文件偏移 VA-0x26000。不是主控 MTK 的执行代码；它是其随包附件程序。不能由此确认用户床架当前安装版本。

复用 Keeson10211 工程，-readOnly -noanalysis，未创建函数或改库。export 保留35个函数完整反编译、汇编、调用引用；pseudo 对既有库未定义的 0x2c490..0x2c49c 做临时 Thumb 解码。共核对2,358条原 listing 记录和7条临时解码、6,260 B；其中 0x26578..0x2657f 是库误作四条指令的8 B literal 数据，已单独标记，不用于执行结论。扣除后为2,361条指令、6,252 B。90个 literal word 和4段 ROM 数据另存。每一保留字节均与原 BIN 一致，且 BIN 与 MTK ZIP 成员相同。具体统计见 VALIDATION.json；命令见 COMMAND.txt。

2. 引脚表来自启动压缩数据，而不是未初始化 SRAM 猜值
既有 Ghidra 项目把 SRAM 建为未初始化块。直接读其 RAM 地址得不到固件启动后的初值。本轮沿 reset 0x263e0 → 0x2655c 的 scatter 初始化表，确认两条记录：
  0x37b68: source=0x37d3c, destination=0x20002aa8, length=0xcc8, handler=0x26580；
  0x37b78: source=0x37fb8, destination=0x20003770, length=0x4898, handler=0x2c490。
第一段是字面量/零串/回溯复制压缩；独立静态脚本按指令语义解出3,272 B，实际消耗634 B（到0x37fb6，不含末尾2 B填充）。每个压缩块的源、目标范围保存在 STARTUP_DATA.json。第二段 handler 不读 source，按4 B清零，BSS范围到0x20008008（右端不含）。这也给出 P/E/T/last_direction 等字段的启动清零来源。

解压后 RAM 0x20003539..0x2000353c = 15 16 17 18，故逻辑 i=0..3 分别选择 GPIO 21..24。芯片只有一个 GPIO port，记为 P0.21..P0.24。恢复出的 0x20003496 初值为0x11，自检状态机不是仅凭 BSS=0便自动从 stage0 开始。两项都是启动数据推导，不是实机内存快照。
注意：0x2655c 的反编译把 literal 后的相邻解压器错误串成后续执行；结论只使用 0x2655c..0x26577 的实际跳转、表内容与独立解压器，不采用该段伪代码的错误尾部。

3. GPIO/GPIOTE 配置到回调
main 0x3098c 调 0x29d2c：先 0x33954 初始化 GPIOTE，再对四个表项调用 0x33884(pin, config, 0x303b1)，最后逐项 0x337e0(pin,1) 开启。
config 是小端 0x00020002，即 [02,00,02,00]。0x33884 的 bit 路径选择专用 GPIOTE 硬件事件槽（0..7），不是低功耗 PORT/SENSE 检测支路。0x2ec50 从空槽分配并保存 pin→slot 与 slot→callback；不能把逻辑轴号直接等同于固定槽号，尽管干净初始化后的顺序分配会落到前四个槽。

已证寄存器写入：
- GPIO PIN_CNF[pin]，0x50000700+4*pin，写入0：输入、input buffer连接、内部上下拉关闭、标准驱动、SENSE关闭；不能据此断言电路没有外部上拉或滤波。
- GPIOTE CONFIG[slot]，0x40006510+4*slot，PSEL=pin，POLARITY=2；随后 MODE OR 1。依 Nordic 官方寄存器表，这是 Event 模式下降沿事件。
- 清对应 EVENTS_IN（0x40006100+4*slot），INTENSET（0x40006304）写 1<<slot；初始化同时配置 IRQ6（NVIC使能位0x40）。0x26058 的向量字=0x26659，连到 0x26658。
- IRQ 0x26658 扫八个 EVENTS_IN：事件位非0且对应中断使能才清位并记录；随后从 CONFIG 取 pin/polarity，调用相应 callback。回调 0x303b0 只使用 pin，没有把第二个 polarity 参数作为方向来源。

门控/失败边界：初始化已发生时 0x33954 返回8，0x29d2c送错误处理函数。0x33884 在 pin已分配时返回8，无槽时返回4，但该调用点不检查这些单 pin 返回值；后续 enable 仅对有效映射操作。以上不能等同于实机配置成功或失败。0x29c40 对表中 pin 返回0..3，非表项返回0；当前注册链使用表内 pin，不宣称正常路径会错归轴0。

官方寄存器含义和访问日期见 PUBLIC_REFERENCES.json；代码事实与芯片寄存器语义分别记录，板级 Hall 器件类型、接线及物理轴仍未知。

4. 回调如何更新 P
以下均为逻辑轴 i=0..3；所有地址加 i*0x28：
  P  +0x00，0x20003bc8：当前用于比较/上报的软件位置，32位；
  E  +0x04，0x20003bcc：GPIO事件方向计数，32位；
  T  +0x08，0x20003bd0：定时替代计数，32位；
  A  +0x10/+0x14，0x20003bd8/3bdc：活动态累计事件数，64位；
  D  +0x18，0x20003be0：上次活动方向，8位；
  S  +0x19，0x20003be1：run_state，0增加/1减少/2停止；
  L  +0x1a，0x20003be2：参与顶部/运动状态判断的字节。
另有 H[i] = uint16(0x20003f5e+2*i)，是回调刷新、定时回调递减的无事件倒计数。这里的字母只是本报告局部记号，不是还原出的原始源码字段名。

0x303b0 在模式字节 M=uint8(0x20003fb7) !=0 时立即返回，不更新 E、P、A、D、H。
M=0 时：
- S=0：若 E !=0xffffffff，E++ 且 P=E；A 始终加1，D=0，H=85。
- S=1：若 int32(E)>0，E-- 且 P=E；A 始终加1，D=1，H=85。
- S=2：按 D=0 或1沿上次方向增减 E，并在实际改变时 P=E；不增加 A；H=85。D不在0/1则直接退出。
- 其他 S：直接退出。

所以停止状态不是冻结位置：只要输入事件到来，仍可按上次活动方向计数。这可以描述停止后的脉冲处理规则，不能凭此确认惯性运动或线路噪声。方向没有从脉冲相位、第二根引脚或当前 GPIO 电平解码；软件状态负责给计数加上符号。

边界由实际分支确认：
- 增加通过 E+1 是否为零挡住0xffffffff回绕，不限制到机械行程顶点。
- 减少用 signed BLE/BGT；E=0以及0x80000000..0xffffffff都不会减少，0x7fffffff会减少。不能笼统写成无符号零下限饱和计数。
- A 用 ADDS/ADC，按64位模数回绕，没有饱和保护；它只计 S=0/1的已处理回调，并非所有边沿总数。
- 被上限/下限挡住时 P 不重写，但活动态 A 仍增加、H仍刷新。因此 P、E、A 不能互相代替。
- IRQ读取的是硬件事件位，回调一次加减一次。没有由此证明所有电气边沿都一一送达、无合并或无丢计数；此回调中也未见时间戳/软件去抖。不能将回调数量等同于实测频率。

5. 定时替代源与自检关系
0x2c70c 仅在 M==1 时调用 0x29d9c，然后在该轮后部递减非零 H。上轮已确认该重复回调的配置间隔名义值为328/32768秒；这是回调配置频率，不是 Hall 输入频率，也不是每通道有效采样率。
0x29d9c 对四轴：S=0且 L!=1 时按 T增加（同0xffffffff上限），S=1时按 int32(T)>0减少；实际变更后 P=T。进入这两条分支后无论计数是否到边界，都置 L=2、H=100；随后同一 0x2c70c 轮会把H减为99。S=2不变，S=0且 L=1也不变。
模式表：M=0允许 GPIO计数、没有定时替代；M=1阻断GPIO计数并使用定时替代；M=2及其他非零值在这两条生产链都不更新。这里只覆盖这些位置源，非对整机所有功能的概括。

0x2b044 的 stage3/4 确实直接比较 P 与快照0x200046ec[i] 的有符号差值是否>5，累计 motor_HallNum。其 stage5：HallNum==8设 M=0；否则 CurrentNum==8设 M=1，再否则设 M=2，并设置相关倒计时。因而“定时替代”不是随意命名：它与这条软件自检结果相连。CurrentNum的缓存累计规则见上轮 keeson-sampling-fault，不能当成实时电流积分或物理健康证明。
正常 main 初始化后显式 M=0；配置加载0x2969c此前可读入模式，但随后被这一赋值覆盖。新的自检触发条件/重入时如何初始化旧模式，不在本轮闭合范围；不能直接宣称自检必定在 M=0 完成，或必定被替代计数误通过。

6. 清零和持久恢复是另外两类来源
0x2b56c 在主循环被调用：S==1且 H==0 时把 P、E、T同时清零。0x288d4 后部也有同条件的清零，并更新状态。这里判断的是软件方向与无事件倒计时，不是已证明的独立机械限位开关输入。既有回底/位置管理函数0x2a098、0x2a8a4还有受命令状态和H门控的相同三字段清零；完整上下文保留，未把它们全部压缩成“任何停机都清零”。

0x2b680 把0x20003c68[i]复制到 P，四轴循环中没有同步 E 或 T。0x29840从0x76000起按32 B记录扫描并恢复该RAM块；没有可用记录或触发异常记录处理时清零该RAM块，然后调用0x2b680。main又调用一次0x2b680。0x2b6a8反向快照 P 到该块，CRC/停止态门控属于持久化提交流程的一部分，本轮没有闭合整个擦写事务。

由此可以确定“恢复函数只写 P”的局部事实。若某时刻 P=保存值、E/T不同，下一个允许更新的生产者会按自身 E/T覆盖 P；这是条件推导。还不能据当前函数搜索断言任意真实重启一定跳变或任意模式切换必有失配：未完成所有间接写入、初始化交错、记录内容及运行时的穷尽证明。
0x27cac、0x27c38输出的四轴位置只取 P 的低16位，以高字节在前编码；内部32位溢出边界与这两个报文的16位截断是不同层。不可把其显示回绕当成内部计数一定回绕。

7. 覆盖、限制与值得继续的问题
本轮闭合：原包→启动解压引脚表→专用GPIOTE配置/IRQ→带模式和方向门控的 P生产者→清零/局部恢复→自检比较与两个位置报文读出。查询范围及准确文件行号见 EVIDENCE_MAP.json、COVERAGE.json、SOURCE_SEARCH.txt。符号搜索只作用于既有反编译语料，不能证明全程序不存在别名指针写入。

仍可现在做的高价值问题：
A. 自检的触发/重入入口与 M、E、T 初始化是否联动？本轮已恢复默认 stage=0x11，并知道 stage5输出模式。下一步应只追 stage0 写入者与相关模式/计数重置，区分正常启动、自检重入及替代模式下的比较；不是重新查已闭合的GPIO计数。
B. 持久化事务如何保证 P 与 E/T 的恢复一致性？沿0x29840/0x2b680/0x2b6a8闭合32 B记录、CRC、提交/擦除完成回调以及全部别名写入，做有限断电/切换顺序推演。现阶段只能静态确认条件风险，实机是否出现跳变仍需日志。
需要实机/板级材料的问题：
C. P0.21..24各连哪一执行轴、每边沿对应多少位移、边沿是否存在合并/噪声或停机后脉冲？需要板图/连线或同步的GPIO波形、命令状态和位置报文。单凭本固件无法给毫米/角度、物理过流或实际计数速率。
