二、第 1 项：每个 hwrev 的完整配置对象快照
============================================================

方法：model/config_snapshot.py 的 Thumb 常量传播器逐条复算
      movs / mov / ldr literal / adds / subs / lsls / str / strb / bl。
      配置对象是 r0；movs rX,r0 建立别名，adds/subs rX,#imm 在对象内移动
      指针，偏移必须累加（上一轮手工纠正过的 +0xfc 模式，本轮由脚本内建）。

每个 setter 的写入条数（与第五轮独立实现的槽位台账完全一致，交叉验证通过）：

  版本 阈值   写入数  说明
  I00  0x0000  62    完整默认对象 A
  I05  0x0805   6    仅名字 + 少数槽
  J00  0x0900   7    新 init + 3 个 RAM 指针
  K00  0x0A00  48    完整默认对象 B（大规模重写）
  K05  0x0A05  25
  K10  0x0A10   2    BL 0800f968 重放整个 K00，然后只改名字与 +0x164
  K30  0x0A30  10
  K33  0x0A33   5    BL 0800fafc 重放整个 K05，然后改名字/init/+0x114/+0x118/+0x58
  K34  0x0A34   2    +0x1a4 是 sku 条件写入
  K35  0x0A35   2    旧 +0x194 备份进 0x2000135c，再写 0x08011101
  K36  0x0A36   5
  K37  0x0A37   2    +0x1a4 改为 0x08025ee8
  K87  0x0A87   1    工程无函数体，原始 Thumb-1 半字解出，只写名字
  K90  0x0A90   2    名字 + strb 清 +0x18c

累加应用规则：所有 threshold <= hwrev 的行按顺序生效。
边界集合 = 14 个阈值 + 0x0AFF（080108ac 分支上界）+ 0x0B00（顶格）= 16 个。
顶格共 16 次 setter 调用、14 个不同分派行；多出的 2 次是 K10/K33 的内联重放。

关键槽位最终值（顶格 hwrev >= 0x0A90，sku=0/4 两版快照均产出）：

  +0x0     K90 版本字符串指针 0x08024268
  +0x4     最后一次写入的 init 回调（K36 装 0x08012275，K87/K90 不再改写）
  +0x1a4   0x08025ee8（K37）；K34 阶段是 sku==4 ? 0x08025f08 : 0x08025f00
  +0x194   0x08011101（K35），旧值保存在 0x2000135c
  +0x18c   0（K90 的 strb 单字节写）
  +0x114   K33 写入的 0x08012d51，是主分派复制到上报 +0x3e28 的块起点
  +0x118   K33 写入的 0x2710 = 10000
  +0x164   K10 写入的 0x08010d39

值分类：thumb_function_pointer（奇数 flash 指针）/ flash_data_pointer /
        ram_pointer / integer / runtime_value（条件写入）。
每个槽位都记录「写入者版本 + 写入指令地址 + 助记符」，可逐条回溯。

边界（必须守住）：
  · 这是「setter 写入的值」，不是运行时对象的最终值。分派行之间、
    分派之后调用的回调（如 08011100）可能继续改写 +0x1a4 / +0x194。
  · sku / devicesn / hwrev 是运行时字段；本轮只显式建模 sku==0 与 sku==4
    两版快照，devicesn 分支未展开。
  · 值里的 4000000 / 2000000 / 30000 等是 setter 常量，不是硬件测量。

三、第 4 项：6 组未导出消费者
============================================================

3.1 0800cf10 —— 补上第四轮「实机走哪条静态定不了」的条件侧

  指令级：
    ldr r3,[0x0800cf2c]  = 0x40021000
    ldr r3,[r3,#0x8]     -> 读 0x40021008
    lsls r3,r3,#0x11 ; lsrs r3,r3,#0x1d  -> idx = (val >> 12) & 7
    lsls r3,r3,#0x2  ; ldr r3,[r3,r1]    -> 0x080241ac 表
    ands r3,r1(#0x1f); ldr r0,[r2,#0x0]; lsrs r0,r3

  公式：PCLK = DAT_20000250 >> APB_TABLE[((reg@0x40021008 >> 12) & 7)]
  0x080241ac 8 项 u32 = [0,0,0,0,1,2,3,4]
  0x080241cc 16 项 u32 = [0,0,0,0,0,0,0,0,1,2,3,4,6,7,8,9]（AHB 预分频，上一轮已用）
  参数化结果（64MHz 是上一轮条件性计算值，不是实测）：
    idx 0..3 -> 64MHz；idx4 -> 32MHz；idx5 -> 16MHz；
    idx6 -> 8MHz；idx7 -> 4MHz
  调用点：0800e91e、0800ea14（都在 0800e8b4 内）。

3.2 0800e8b4 —— USART 时钟源选择矩阵（完整条件侧）

  0x40021054 被三处 ldr r3,[r3,#0x54] 读取，按 USART 基址选掩码：

    基址        掩码   0          1            2            3
    0x40013800  0x03  PCLK       SYSCLK       HSI16        32768
    0x40004400  0x0c  0->PCLK    4->SYSCLK    8->HSI16     0xc->32768
    0x40004800  0x30  0->PCLK    0x10->SYSCLK 0x20->HSI16  0x30->32768
    0x40004c00 / 0x40005000 / 0x40013c00 -> 恒定 PCLK

  四个源：
    PCLK   = 0800cf10()
    SYSCLK = 0800cd24()
    HSI16  = literal 0x0800ea44 = 0xf42400 = 16000000
    32768  = movs r0,r3，其中 r3 由 movs #0x80 / lsls #8 构造 = 0x8000

  OVER8：param_1[7] == 0x8000 决定 BRR 路径。
    四个源分支各有一处 0x8000 构造，实测命中
    0800e916 / 0800e95a / 0800e966 / 0800e9b4。
    注意 0800e8b4 的 param_1 是 0800ec64 构造的 USART 配置描述符，
    **不是** 0801d888 的 hwrev 配置对象，两者槽位不可混用。

  路径 A（16 倍）：BRR = (clock // divisor + (baud >> 1)) // baud
  路径 B（8 倍） ：N = (2*(clock//divisor) + (baud>>1)) // baud
                   BRR = (N & 0xfff0) | ((N & 0xf) >> 1)
  范围检查：0x10 <= N <= 0xffff（literal 0xffef），越界返回 1。
  64MHz / 115200 / divisor 1 -> 0x22c（A）/ 0x453（B）；16MHz -> 0x8b（A）。

3.3 0x0802420c 末 4 项：把猜测收窄成字节事实

  16 项 u16 = [1,2,4,6,8,10,12,16,32,64,128,256,0x408,0x402,0x108,0x101]
  末 4 项拆位：0x400|8、0x400|2、0x100|8、0x100|1。
  但指令是 ldrh r1,[r2,r3] 后直接 bl 08008174：
  **整字作为除数传给除法 helper，没有任何拆分指令**。
  所以「打包」只是字节形态观察，不是已证明的字段布局；上一轮把它
  当作「疑似预分频+过采样标志」的猜测本轮不予确认。
  参数化扫描：16/64MHz 下 115200 波特率时末 4 项全部不产生合法 BRR
  （N < 0x10）；9600 波特率时部分组合合法。因此它们不是常规 UART
  波特率除数。

3.4 5 个「消费者」纠错（重要）

  上一轮候选清单把下列地址当成未导出消费者，实测都是 literal pool 槽：

    地址       内容          真实读取者   含义
    0800fbcc  0x08025ed0    0800fbc0    外设地址表 A 指针
    0800fdc0  0x08025ec0    0800fdaa    [1,2,4,8] 掩码表指针
    080125a4  0x08025ec0    08012538    同一掩码表指针
    08012cf0  0x08025f28    08012b5e    8B 尾部索引数组指针
    0800fc00  (literal)     0800fbf4    literal 槽，非可调用代码

  导出文件均显示 function=none 且只有 REF_TO ... READ。
  真正的消费者是这些读取指令所在的函数，已补导 pass3 并写入清单。

3.5 其余消费者（12 项，全部有导出与逐字节核验）

四、第 5 项：08008174 除法 helper 形式化穷举
============================================================

  做法：model/udiv_exhaustive.py 从 pass1/08008174.txt 的 132 条 INSN
  逐条解码助记符，实现一个最小但精确的 Thumb 解释器
  （movs/mov/lsrs/lsls/asrs/rev/cmp/subs/adcs/分支/push/pop/bx/bl），
  带 N/Z/C/V 标志语义。**不是**抄 Ghidra 伪 C，也不是把反编译改写成 Python。

  结果：
    指令地址覆盖      132 / 132（无未执行行）
    最大执行步数      226
    用例总数          26757（边界交叉 + 20000 组固定种子随机 + BRR 实参）
    全部与 (a//b, a%b) 一致，0 失败
    除零              r0=0（商）、r1=a（余数），路径
                      08008272 -> 08008274 -> 0800845c（单条 bx lr 空函数）
    反事实            把它当乘法用必然不成立

  调用约定：r0=被除数，r1=除数；返回 r0=商、r1=余数。
  这闭合了第四轮明确留的「除法语义来自三处调用点用途，未形式化证明」。
  上一轮 BRR / SYSCLK 模型里把它当无符号整数除法使用，现在有了形式化依据。

六、边界（守住，不越界）
============================================================

  · 16/32/8MHz HSE 是写入 0x20000474 的软件输入，不是实测晶振；
    64MHz 是条件性计算值（依赖 PLL lock、SW 切换成功、SWS 读回、
    复位态未被改写、无致命错误）。
  · 所有时钟值、波特率、除数索引在本轮都是显式参数，不是运行时读数；
    常见波特率常量在 132896B 镜像里仍是 0 命中。
  · 0x4000xxxx / 0x40021054 等外设寄存器**不命名**：没有数据手册或原理图，
    静态字节只能给地址和掩码，不能给寄存器名。
  · 配置对象快照是「setter 写入值」，回调链后续改写不在快照内。
  · 仍需新增材料/设备：通道索引→物理传感通道、波特率与除数索引的实机值、
    RCC 时钟源实际走向、64MHz 实测、型号/板型/晶振 BOM 绑定、
    PLL lock 与切换过渡、ADC CLKIN/DRDY 与真实采样率。
  · A 类剩余未做：setter 回调实现（第 2 项）、hwrev/sku → 上报字段完整
    枚举（第 3 项）、hwrev → 内部 3 字符标识（第 7 项）。第 6 项本轮已
    按字节证据收窄为「整字除数、无拆分指令」，但未给功能定论。本轮按用户
    「继续」时明确的 1 → 4 → 5 范围收口，未扩张。
