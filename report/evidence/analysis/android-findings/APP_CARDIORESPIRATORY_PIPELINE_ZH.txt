Eight Sleep 中国 Android 7.63.5：HR / RR / HRV 结果与本地计算
静态审计日期：2026-11-07。未启动 App、执行目标代码、调用业务 API 或读取用户数据。

1. 可回答的核心问题
本 APK 已能补上固件研究缺失的“生理指标结果如何进入 App”一段：睡眠趋势接口返回会话时间序列，客户端转换/缓存后，日图直接消费已算好的指标。已逐指令核实三个日图处理器：HRV 图取 rmssd；呼吸率图取 nemeanRespiratoryRate；静息心率图取 heartRate。HRV 的页面标题不意味着它读取同名 hrv 序列，更不意味着在手机上从心搏间隔重新计算 RMSSD。
App 有本地处理：时间包装、数值类型转换、会话选择、图表 min/max、与基准比较、显示取整。服务器还返回当晚 current、范围、评分、异常状态和 aggregate.avg 等统计量。本报告只区分这些已追明的职责，不声称 App 整体不存在其他算法。
本轮没有获得多通道原始波形到 HR/RR 的检测算法、压电/IMU 融合权重或睡眠模型权重。结果契约与消费者已恢复，并不等于服务端推理已恢复。

4. 会话时间序列实际输入格式
TimeSeriesResponseJsonAdapter.java:13-26 定义六个列表，fromJson:45-117 要求前五项非 null，shortAwakes 为可空列表：
  respiratoryRate        → RawTimeSeries.a → TimeSeries.a（Double）
  nemeanRespiratoryRate  → RawTimeSeries.b → TimeSeries.b（Double）
  heartRate              → RawTimeSeries.c → TimeSeries.c（toDomain 用 Number.intValue）
  hrv                    → RawTimeSeries.d → TimeSeries.d（Double）
  rmssd                  → RawTimeSeries.e → TimeSeries.e（Double）
  shortAwakes            → RawTimeSeries.f → TimeSeries.f（Integer；null 转 empty list）
类型说明是客户端 domain 转换，不额外宣称 wire 必须是 JSON 整数字面量。列表可为空；“必需非 null”不等于存在有效采样。hrv 与 rmssd 是两个独立字段，nemean 的算法含义不能仅据名字展开。（E11、E13、E17、E18）
MetricPointResponse 没有走常见的生成对象 adapter：J/p332nc/a.java:6-21 匹配该类型并返回 nc/c；ce/l.m3 的 S:10081-10103 将该 Factory 加入注册集合。nc/c.fromJson（J:28-58；完整 S:100-226）先 beginArray，再按 token 遍历：STRING 走 Instant adapter，NUMBER 走 Number adapter，结束时要求两者都有值。未限定恰好两个成员，也未限定 string 必须先于 number；重复 token 会覆盖对应已有值。（E22、E25、E28、E39、E56）
可读的期望点形状是 ["时间字符串",数值]，这是从 parser 归纳的说明，不是真实网络样本。parser 的 toJson（J:62-73）却写 {dateTime:...,value:...} 对象；不能把 writer 输出误认成网络输入契约，也不能不加验证地拿此 adapter 做双向重放。
InstantAdapter.fromJson:7-20 先 Instant.parse，失败后 ISO_LOCAL_DATE_TIME 并按 UTC 转换；ce/l.m3 的 S:10251-10255 注册该 adapter。（E64、E69）
TimeSeriesResponse.toDomain:132-267 只逐点取时间和值，做 doubleValue/intValue 转换，创建 RawMetricPoint；RawDailyTrends.a:212-252 将六序列逐点转 MetricPoint；RawMetricPoint.a:20-22 以 ClockSystem 包装 Instant，保留值。（E13、E23、E26）
这里未见压电采样点、IMU 六轴、逐通道维度或 RR-interval 列表作为图表处理器输入。不能据此排除未覆盖的另一条接口，只能说当前正向恢复链从已计算的服务器指标开始。

7. 多传感器质量与算法边界
已追模型是每时间点一个数值，未恢复每个压电/IMU 通道的 SNR、覆盖率、融合权重、剔除掩码或硬件采样率字段。
保留的全 Java 定向搜索 signalQuality/sensorQuality/signal_quality/sensor_quality/sensorAccuracy/sampleQuality 没有命中（E05）；metrics 域字段搜索只显示算法版本/QUALITY=sqs 等已有线索（E35）。这些负结果仅限定搜索表达式和本次索引，不能证明未命名、混淆、JNI 或动态路径没有质量算法。
native 索引针对 rmssd|heart_rate|respiratory|nemean|piezo|tensorflow|onnx|tflite 的定向搜索无命中（E55）。这不是全部 native 函数的审计，不据此宣称包内无推理。
Session.processing/incomplete、sleep/presence/hrvAlgorithmVersion 由睡眠结果审计另行追踪；它们是结果状态/版本，不能冒充传感器质量或模型权重。China App 的结果字段也不能单独证明该 APK 对应的所有中国硬件均为某一 SoC 或 Pod6 传感器型号。
附带候选（未作为本轮主要已回答链）：HeartbeatDisturbancesMetricDataProcessor 与 BreathingDisturbancesMetricDataProcessor 可见对返回的 health-score 时间项按小时分组求和、与常量比较（E31、E47）。其完整响应生产路径及所有边界未在这里闭合，不能把它们叫作本地心搏/呼吸原始信号检测器。
