传感 MCU 上传前数值处理：仅依据当前固件代码
2026-11-07；用户明确要求“基于代码”后的直接复核。
样本 firmware-sensor-g0-usb.bbin，SHA256 1a125674542934f36266f88d9f8ca378a6a5ca696d9e58305d1b0e533f795563。
所有地址采用既有BBIN映射基址0x08010000；下列.c/文本中的C是Ghidra恢复伪代码，不是厂商源码；关键分支有同文件汇编。
这是复核已恢复的实际入口，不是新发现一个完整生理算法。

1. ADC读数：0x0801D7DC
源：analysis/sensor-mcu/freshness/0801d7dc.txt。
该函数在对象启用时处理读取；缓存计时小于8ms时，直接把object+0x64的32字节复制到destination。
正常读取先检查ready回调，再调用0x0801D228；失败立即返回，未写destination。
成功后只对STATUS低8位中对应ready的通道赋值。逐通道赋值为：

    destination[channel_map[ch]] = software_multiplier * signed24_be(received[ch]);

这是解释原指令语义的短式，不是可直接编译的原厂代码。
汇编0x0801D910–0x0801D934依次取map索引、拼3字节、ASR符号扩展、乘倍率、STR写入；未ready通道跳过该写入。
这条循环没有相邻通道求和/平均、频带分离、峰检测、运动分类或质量打分步骤。
限于这个函数及已核对调用上下文，不能扩大成整个MCU或其他程序无这些算法。

2. SPI/CRC：0x0801D228
源：analysis/sensor-mcu/frontend/0801d228.txt。
设置SPI模式、片选、传输；CRC配置启用时遍历返回字计算残差，非零则增加错误计数、设置错误标志并返回失败。
0x0801D7DC收到失败立即return 0，因此共享的旧值可以继续存在。错误检测不是将被污染波形还原。
CRC开关有条件分支：不能说函数所有调用永远做CRC，也不能把通信CRC当生理信号可信度评分。

3. IMU读数：0x0801EF68
源：analysis/sensor-mcu/frontend/0801ef68.txt。
先读STATUS，再读取12字节轴数据；相应ready位未置位时跳过该组三轴的写入。
可观察的数值变化为将有符号16位最大值32767改为32766，以及转成大端序输出；并维护轴值变化计时。
读取/状态失败时return 0，不在destination填新的故障样本。
该函数中未见加速度与压电波形做消噪参考相减，亦没有融合四颗IMU的共同运动估计。
这里只是该读取函数边界；不排除别的处理阶段使用这些信号。

4. 定时快照：0x080233F4
源：analysis/sensor-mcu/freshness/080233f4.txt。
采样回调将tick和两组请求增益/缓存元数据写入共享记录，再调用队列push复制当时ADC cache；每五次另push当前IMU cache。请求增益不证明硬件已写入并生效。
两个push失败分别增加overflow统计。回调不先按心搏质量筛选，不检查本次每通道的ready/CRC状态才入队。
因此在已审链中，输出数值重复既可能来自信号相同，也可能来自保留旧cache；不能仅靠相邻值相同判为重复包。
完整队列/打包与可用位分析沿用SAMPLE_FRESHNESS_ZH.txt；本报告没有运行固件或实测重复/丢包率。
