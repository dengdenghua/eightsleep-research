二、实际请求包含哪些 metric
HealthCheckHomeViewModel$2$invokeSuspend$$inlined$flatMapLatest$1.invokeSuspend 在 194 行取 SmartFetchMetricAggregatesUseCase；204–206 行传两个 null 和 flags=0xE 调 P2.c.y。该调用是健康页实际观察流的一部分，不是只看到 METRIC_TYPES 常量。[A01]
P2.c.y 的完整 Smali（6233–6295）先取 ZoneId.systemDefault；flags&4 非零时以 AggregateMetricType.getEntries() 转成 metrics 列表；flags&8 非零时 periods=[WEEK]。0xE 同时满足两项，随后传入 uc/g1。[A02]
uc/g1.invokeSuspend 在 129–145 行把同一 metrics/periods 交给 MetricsRepository.smartFetchAggregates。smartFetch 先查询对应周期缓存，取组合流结果，只有该结果列表非空时才调用 fetchAggregates$default；否则返回成功结果流。因此这是“走到网络分支时会携带这些 metric”的静态证据，不是每次开页面必发请求，也不是已观察到线上服务器返回。[A03–A05]
fetchAggregates$default 不筛选 metrics，只默认 refreshCache=false；正常 fetch 将 metrics 同时交给 pc/B（网络）与 pc/C（缓存响应处理）。[A26–A27]
pc/B 将 metrics 用 k1/I(27) 映射后逗号连接，k1/I 的 case 27 明确返回 AggregateMetricType.getQuery()，再交给 Loc/b.a 的 metrics 查询参数。[E41,E66；A06]

  HEART_RATE / WELLBEING_HR_UPPER  → hr / wellbeing_hr_upper
  HRV / WELLBEING_HRV_LOWER        → hrv / wellbeing_hrv_lower

三、返回数值如何成为 Sample.double map
pc/C 取 MetricsAggregateResponse.periods 调 xc/c.i；AggregatePeriodResponseJsonAdapter 的字段包含 samples。AggregatePeriodResponse.toDomain 在 267–273 行逐项调用 SampleResponse.toDomain，并把列表交给 RawAggregatePeriod。[E42,E46,E48]
SampleResponseJsonAdapter 读取 date、metrics；metrics 是 List<AggregateStatisticResponse>。AggregateStatisticResponseAdapter.fromJson 读取 name，并按 getQuery 匹配 AggregateMetricType；对应 DoubleStatistic 的 value 走 JsonReader.nextDouble，然后直接构造 DoubleStatistic(name,value)。ce/l.m3 的 Moshi 配置确实注册了这个 adapter。[A08–A11；H41 的 ce/l.smali:8487–8491]
这条解析路径没有从 hr/hrv/br 数值推导 wellbeing_* 界限。wire name 决定类型和值的归属；数值本身来自 JSON。这里没有构造“真实响应样本”。
SampleResponse.toDomain 筛出 DoubleStatistic，然后执行 map.put(getName(),getValue())。构造 RawSample 的第二个参数就是该 map；RawSample 保存为 b。RawAggregatePeriod.b(displaySettings) 创建 Sample 时继续传 RawSample.b，时间/LocalTime 另做显示包装。[A12–A14,A24,A29；E52]

缓存范围必须分清：xc/c.i 对 aggregate 级别的 map 有旧新合并，stdDev map 还有缺省 0，旧报告已指出，不能称整个缓存无条件透传。[E68]
本次专门复核的合并分支在 1016–1026 行把 RawAggregatePeriod.j 样本列表交给新 RawAggregatePeriod，随后形成缓存实体。三个界限消费者读取的是 Sample.b，既不是 aggregate.stdDev，也不执行那个缺省 0 分支。[A15；E68] 本报告不穷尽缓存失效、网络错误与新鲜度策略。

四、Sample → processor → 三对 UI 序列
旧 H64 已闭合健康页观察者将 trends、aggregate 列表最后项、tags、pregnancyMode 交给 updateContent。这是实际消费者入口。[H64]
updateContent 从 AggregatePeriod.j 取 Sample，按显示日期筛选，建立 date→Sample map（1421–1510）；随后遍历 METRIC_TYPES，为每项选 dataProcessors 中同 key 的处理器，按日期取 Sample，以 WEEK 调 transformPeriodData（2065–2288），把返回图点加入列表，存入 metric→list map（2392–2446）。[A16–A19,A23]
三个具体处理器 constructor 绑定各自界限枚举；完整 transformPeriodData 均为 66–109 行：
  RestingHeartRateTrendMetricDataProcessor     → Sample.b[WELLBEING_HR_UPPER]
  HeartRateVariabilityTrendMetricDataProcessor → Sample.b[WELLBEING_HRV_LOWER]
  BreathRateTrendMetricDataProcessor          → Sample.b[WELLBEING_RR_UPPER]
每个方法只有取 map、按 key get、转 Double、构造 wg/r0；Sample 不存在或键缺失时值为 null。wg/r0 的完整构造器只保存 Double/date/标志，没有改变 Double。[A20–A22,A28]

五、能与不能据此得出的执行位置结论
能：在这条已编译客户端链上，界限已作为响应数值到达，手机承担类型解析、map/缓存组织、日期选择和图点包装。三项处理器没有本地生成/重算界限的调用，也未见它们把 dayOfWeekAverage、dayOfWeekStdDev 或异常上下界 DTO 字段送入生成器。没有在此链发现尚需追踪的本地界限生产函数。
不能：据此指定服务端用 EMA、固定窗长、特定异常分布、U-Net 或任何融合/清洗公式；不能把返回上界/下界等同整个后台异常判定；不能证明固件或 App 其它路径完全无数据处理。原始波形清洗、心搏/呼吸提取、多通道融合和界限的服务端 producer 仍未取得。
本轮没有新的原始生理算法入口。可执行的后续只在新增原厂服务端实现/部署物或经授权的实际响应出现后，验证具体生成逻辑和版本绑定；从这三个图点消费者继续追一般绘图不会补出原始清洗算法。
