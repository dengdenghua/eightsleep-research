G0 USB 采集驱动：硬件状态→DMA/IRQ→请求结果→正常采样入口
日期：2026-11-08，Asia/Shanghai

本轮闭合的内容
1. 传感器 I2C 不是把“启动成功”直接当成“采样成功”。规范非零长度请求走 DMA；DMA 块完成后仍等待 I2C 的结束事件，最终完成回调才把软件总线状态写成 1。main 再取该状态，只有 1 才调用器件回调。
2. BERR/ARLO/OVR、NACK、DMA 错误有明确不同入口，最终接到软件状态 2；DMA abort 可能异步完成，不能把进入错误分支等同于回调已经执行。I2C 11 tick 软件等待超时与这些 IRQ 错误仍是两条不同来源。
3. ADS/IMU 的 SPI 走同步轮询，包装传入 timeout=2；传完指定数据还要检查 TX FIFO、BSY、RX FIFO。包装只保留成功/失败，未把 HAL_BUSY/HAL_TIMEOUT/结束检查失败编码进每条原始采样。
4. GPIO DRDY、SPI 成功和芯片寄存器 ready 是三个不同条件。ADC DRDY 按低电平有效读取；四个 IMU DRDY 按高电平读取，随后还要通过 STATUS_REG 与规范读事务。这里没有把 GPIO 边沿次数等同于已提交的新样本数。
5. 板型表有 14 个门槛，按顺序累积应用。0x0a10 会重新应用 0x0a00 的 SPI 描述符，0x0a33 会重新应用 0x0a05 再改一个片选；所以不能用“最后命中的一行配置”解释全部采集绑定。

一、原件、方法和停止点

VA=0x08010000+文件偏移，保留原 128 B 头；向量表从0x08010080开始。未与 nonUSB、旧 sensor、pillow 或历史 NXP 样本混用。
仅只读静态分析。source/复用已保留原导出，pass*/是同一 Ghidra 项目的 -readOnly -noanalysis 导出；未定义的正常入口只在临时会话补函数，未保存工程。pass13/0801a8ec是内部地址的过程导出，不作为真实调用入口证明；实际MSP入口0801a8cc见pass14。function=none 文件保留为过程记录，有补充导出时以后者为准，不能由空导出得出“没有实现”。
未运行原厂代码，未访问设备、账号或 API，未模拟畸形包或内存破坏；没有继续共享日志缓冲/重入专项。模型只按显式输入的正常驱动状态执行选定合同。
本轮把上轮 local-sensor-recovery-followup 的“请求成功/失败”前端接到具体驱动；已有 CRC 数学、缓存失效、stop/start 和全局复位结论不重复当新增。

二、三条 I2C 总线的真实绑定
总线对象 / HAL handle / 寄存器基址 / 正常完成回调 / 错误回调：
  2000ac00 / 20000b50 / 40005400(I2C1) / 08018ab4 / 0801c64c
  2000ad6c / 20000acc / 40005800(I2C2) / 08018d8c / 0801c660
  2000aed8 / 20000a48 / 40008800(I2C3) / 08018a98 / 0801c674
08023a3c 把平台两个函数指针装入总线对象；0801c52e 根据规范请求类型选择它们。地址字段由包装左移一位传给 HAL。0801a1ec/1a1c4/1a214 调用08013988（主发送DMA）；0801a264/1a23c/1a28c 调用08013ac0（主接收DMA）。对应对象与主循环三次0801c688调用已经接齐。
平台初始化为 HAL handle +54/+58 绑定相同正常完成回调，为+70绑定错误回调。三个正常回调只将各自总线+20写1并执行内存屏障；它们本身不执行 FDC/TMAG/TMP 的数值换算。

DMA绑定来自08010e54，不是由IRQ名字猜测：
  I2C1 RX handle200009e8→DMA1_CH3；TX20000988→DMA1_CH4。
  I2C2 RX20000928→DMA2_CH4；TX200008c8→DMA2_CH5。
  I2C3 RX20000868→DMA1_CH5；TX20000808→DMA1_CH6。
每个 DMA handle+28写回所属 I2C handle；I2C+38/+3c分别保存TX/RX DMA handle。向量IRQ10的0801bd18包含I2C1 RX，IRQ11的0801bd30包含其他五个；两者均调用08012990。原GPIO配置中I2C1选PB8/9，I2C2选PB10/11，I2C3选PC0/1；这是固件配置，不证明实机板上焊接及外接线路。
外部IRQ23→0801bd84处理I2C1；IRQ24→0801bda4依次处理I2C2/I2C3。它们先看ISR&0x700：非零走08013c7a错误入口，否则走08013c68，后者调用当前handle+34的事务ISR。规范非零长度DMA请求把该字段设为08013320。

三、启动、DMA块、结束与错误如何变成请求结果
启动：08013988/13ac0要求 HAL state=0x20、ISR.BUSY(0x8000)未置位、lock未占用；不满足返回2。开始时写state0x21(TX)/0x22(RX)、mode0x10、error=0，设置DMA完成/错误回调、设置CR2长度与START，并开启相应DMA请求。DMA句柄缺失或DMA启动失败走非零返回。
0801a1xx包装把HAL返回0转换为1（启动获准）；非零则调用0801963c清状态、必要时重建DMA、关闭再开启I2C并返回0。该0由原始汇编结尾r0验证，反编译器把0801963c标void不能替代实际返回寄存器。0801c52e收到包装0，立即将request+4写2，不启动成功计时。

DMA硬件IRQ：08012990读取DMA ISR/CCR。选定通道的HT/TC/TE标志还须对应中断使能；半完成、完成、错误分别调用handle+30/+2c/+34（均先检查指针）。正常非循环DMA完成后，0801310c(TX)/0801315c(RX)关闭本次I2C DMA使能；无剩余数据时只打开TC/STOP相关事件。它们没有把软件bus+20写1。
有后续块时驱动重设DMA与长度；普通传感读写常为短块，模型只用规范2 B/7 B事务，不把泛型驱动支持的长块视作已找到的新采样包。
I2C事件08013320：NACKF分支清标志并error|=4，开启STOP等待；TCR/TC处理剩余长度和传输结束；STOPF进入0801301c。该函数清STOP、清事务ISR和CR2字段，若无error且state为TX/RX则调用已绑定的正常完成回调→bus=1。若已有error则进入08012f2c错误清理。其他顺序传输完成入口080131b0也调用同组回调，本文不扩大到所有slave/memory/sequence模式。

硬件错误位与HAL错误码的对应：
  ISR0x100 BERR→error|=1；ISR0x200 ARLO→error|=2；ISR0x400 OVR→error|=8。
08013c7a要求CR1.ERRIE(0x80)使能，逐位写ICR清标志后进入错误清理。NACK不是这三个bit，它由事务ISR的0x10分支产生HAL error4。DMA TE进入080130f4，经父I2C handle置error0x10。它们不能统一解释成“传感器CRC错”。
08012f2c会关闭事务中断并处理活跃DMA；若需要异步abort，先装08012f0c并等待完成，再经08012ee4调用HAL错误回调。因此模型将“错误清理完成”设为独立外供事件，不声称任何物理IRQ发生后立即bus=2。
0801c64c/660/674→0801c598：必要时申请中止当前事务，清I2C标志；距恢复timer起点>9999 tick时才重新初始化DMA并关闭/开启I2C，更新该timer。无论该节流分支是否执行，结尾都将bus+20写2。它是错误回调中的恢复门控，不是每10000 tick自动执行一次复位。全部可能总线错误组合与DMA abort响应时间没有穷举。
最终，已有0801c688只在bus=1时调用器件回调；bus=2不调用，异步等待到11 tick自行失败也不调用。这个接口边界解释了为何没有新的FDC/TMAG/TMP读取完成，并不替代上轮对旧缓存是否保留的证明。

四、SPI的返回值、超时预算与结束检查
0801a134→handle20000c74→SPI2(40003800)；0801a164→20000d00→SPI1(40013000)；0801a194→20000be8→SPI3(40003c00)。三个包装都调用080158d4，长度取低16位、timeout参数为2。handle未初始化则直接失败；HAL非零返回统一变成包装1，HAL0变包装0。ADS/IMU事务函数使用“包装0为成功”，与上述I2C启动包装的约定正好不同，不能无声拼接。
080158d4在已配置8-bit、master、2-line正常路径里，轮询SR.TXE(2)和RXNE(1)完成发送/接收。循环仍未完成且tick差已到2时返回HAL_TIMEOUT=3；这只是所配置预算，不是测得一笔传输必耗2ms。
计数完成后080156f8依次要求SR&0x1800(TX FIFO level)==0、SR&0x80(BSY)==0、SR&0x600(RX FIFO level)==0。后两类辅助等待保留剩余tick预算及有限循环倒计数。结束检查失败设HAL error0x20并由080158d4返回1；包装同样仅表现为失败。不能因为已经写入过接收buffer就把整个事务判成功。
08018f08接受mode0..3与请求频率16/8/4/2/1 MHz，写CR1 prescaler/CPHA/CPOL；这是软件分频选择。它不测量时钟，实际SCK频率还依赖时钟源。早期板型mode函数08018bca只是返回1，使用初始化时的配置；不能从该stub推断后来动态改过硬件模式。
SPI初始化含可替换的MSP回调DAT_20000be4。默认分支配置SPI1的PB3/4/5、SPI2的PD1/3/4、SPI3的PC10/11/12；这些默认引脚不能直接当成所有版本的接线表。所选初始化上下文已保留：0a00/0a10/0a30选用的0801ac18/0801b070直接把两个SPI handle+84设为08019944，配置SPI1 PB3/4/5与SPI2 PD1/3/4；0a05/0a33及其后USB平台使用的0801b4ec/0801b764把三个handle+84设为08019a20，配置SPI1 PE13/14/15、SPI2 PD1/3/4、SPI3 PB3/4/5。0801b4ec还设置全局MSP替代指针；0801b764不需要依赖该全局指针，因为已直接替换三个handle。这里是已选平台路径中的软件绑定，不是实机导出的寄存器快照。

五、DRDY与寄存器ready：ADC和IMU实际正常读入口
ADC两组旧DRDY函数0801a2b4/1a2cc读PD2/PB0并取反；新平台0801a80a/1a81a从GPIO表索引38/3f读取PD11/PE2并取反。规范配置的CS函数也按低电平有效写GPIO，但DRDY输入与CS输出不能混同。
main调用0801dd6c后再调用0801d7dc；0801dd6c末尾在enabled时实际返回DRDY函数的r0，disabled时返回1。0801d7dc有独立enabled和同步窗口门控，窗口外再次读DRDY；低电平未出现时不发这笔数据事务。通过规范SPI和已有CRC检查后，响应首个状态word的低字节才是通道ready mask；mask=0仍不更新共享通道值，非零只更新对应映射通道。已沿用上轮缓存/复制证据，没有把这次DRDY当新鲜度序号。
IMU四个DRDY包装0801a82a/1a834/1a83e/1a848分别读取GPIO表45/46/27/28，对应PE8/PE9/PC10/PC11，返回GPIO高电平。main只在对象enabled且该函数非零时调用0801ef68，并先更新对象DRDY计时。
0801ef68先设置SPI模式，再经0801ef0c/08028e7c规范读取reg0x1e；bit0/1都为0则不发后续数据burst。否则发首字节0xa2的13 B规范事务。成功后STATUS bit0允许更新accel组三项，bit1允许更新gyro组三项；任意GPIO/状态读取/数据事务失败都不能自动获得这两组新值。该状态来源比“DRDY已来”多一层，main更新DRDY timer也不等于gyro/accel均成功换新。
安装方向、物理左右、时钟真实频率、脉冲宽度和主循环遗漏多少DRDY现场事件仍未知。GPIO寄存器及函数绑定能确认软件看的脚，不能替代板级原理图或逻辑分析仪记录。

六、板型表与本轮选定配置边界
08027834从独立生产信息区读取hwrev；该区0x0807f804不在本BBIN文件覆盖内，因此未声称知道实机hwrev。0x0802fbc8的14条记录依次为：
0000→18bd0；0805→18d60；0900→18da8；0a00→18fb0；0a05→19144；0a10→19128；0a30→1924c；0a33→192ac；0a34→192e0；0a35→19308；0a36→19328；0a37→19388；0a87→193a0；0a90→193ac。
每条满足threshold<=hwrev就执行，且顺序为表中顺序。关键正常采集变化：
• 默认两ADC分别用SPI2/SPI1，四IMU描述符未绑定；0805将两个ADC CS函数替换为no-op。
• 0900补I2C2驱动绑定；0a00布置两ADC与四IMU，ADC请求4MHz，IMU请求2MHz，IMU分布SPI1/SPI2。
• 0a05清第一ADC描述符，把后两IMU改到SPI3，同时调整CS/初始化。
• 0a10函数直接调用18fb0，重新恢复上述0a00采集描述符；不能保留0a05的SPI3结论。
• 0a33又调用19144，再改第二ADC的CS；0a34/0a37改变通道映射表，前者还看SKU。映射值在RAW_TABLES保留，不将其命名成物理轴或床面位置。
模型的selected-board-bindings.json只列六个SPI设备描述符及命中过的门槛；全局single-side模式、SKU组合、传感器存在检测与之后init成功/失败不在该模型内。08027834/27008的真实初始化门控沿用已有报告，不因描述符存在就断言设备被装配或正在采集。

七、时间来源与内部测温ADC的界限
SPI/HAL时间读取080119ec取软件tick全局2000121c；SysTick向量15→080114a2→080119d4，每次加频率步进20000258。平台初始化调用080119f8(1)，0801195c按SystemCoreClock/(1000/step)配置SysTick，再设置优先级；正常成功配置对应名义1ms tick。正文保留tick写法，未把中断延迟、时钟误差或停止期间的行为当作实测时长。
内部温度ADC使用40012400/handle2000075c，和外置ADS的SPI数据链不同。08010a5c及替代0801a8cc均把DMA handle200006fc绑定DMA2_CH2(4002041c)，并建立ADC+50→DMA、DMA+28→ADC父子关系。规范080120bc启动把DMA完成/错误回调分别设为08011a64/08011aea；IRQ11→0801bd30→08012990进入这些回调。08011a64在正常状态调用ADC+64，初始化将它绑定080223a0，后者仅将200026e8完成计数加1；DMA错误08011aea则设置ADC state|=0x40、error|=4并调用+70错误回调，不走该完成计数入口。08027834完成ADC校准后向200026bc请求转换，并按计数等待这一正常完成；该计数不是外置压电ADC的成功读数序号。旧080108f0与新0801a9e4有不同通道/扫描配置，实际测温换算和窗口处理复用既有local-signal-closure，不在本轮重复模型化。

八、模型、核验及明确未穷尽项
model/normal_driver_contracts.py当前33个有限场景：I2C DMA完成与STOP分离、正常完成与main回调分离、NACK/DMA错误的显式清理阶段、三类硬件错误位与ERRIE门控、启动BUSY/DMA失败、10000 tick恢复门槛；SPI返回值折叠；IMU GPIO/status/事务三层门控；0a05/0a10/0a33配置累积覆盖。模型不承担硬件并发/完整HAL模拟，不生成畸形输入，错误清理完成及FIFO/BSY结果均为显式外供正常事件。
所有模型case保存deepcopy快照，最终落盘observed/expected逐条核对，产物SHA单独核对。原件逐指令、Thumb BL与文件内literal校验见BYTE_VALIDATION；源文件/行号见EVIDENCE_MAP；完整清单见SOURCE_MANIFEST。
明确未穷尽：全部HAL slave/memory/sequential传输模式、所有硬件故障同时出现的优先级组合、外设错误如何由模拟电气条件触发、真实IRQ/DMA响应延迟、板上引脚与器件型号实测、实际hwrev/SKU/启动状态、实时采样发生率。这些都没有被写成已完成或已在实机验证。
参考资料：reference/SOURCES.json记录本轮访问的ST官方CMSIS/HAL原文件URL、SHA与访问时间。用于寄存器命名及驱动合同交叉核对；不据此认定固件精确HAL版本或实机MCU完整料号。代码结论仍以本BBIN原指令为准。
