2026-11-08。范围：仅主版本应用，正常记录生产/消费；未执行原厂代码、写Flash或访问设备。

结论
本轮补到了此前未被识别的启动数据和两个Flash完成回调，但仍未绑定“当前32B RAM快照→76000位置区追加”的生产者。不能据此说设备不保存位置，也不能把缺失生产者直接放进未取得的系统服务。
新增最有价值的结果是：主Flash对象与FDS对象的真实初值、主完成回调的行为、全已识别函数范围内的计算地址候选，以及93处间接调用的寄存器/对象来源账本。旧六个SDK写入直调不是本轮新发现。

2. 新恢复的初始.data明确了两个Flash对象
原启动表37b68..37b87有两项：
  (src37d3c, dst20002aa8, len0xcc8, helper26580)
  (src37fb8, dst20003770, len0x4898, helper2c490)
按26580原指令重建正常数据解压：634B输入生成3272B初始.data，SHA256=8d51ebaf55bfc3a5f0a608d3c4ff7e6e1ae087d1056f0c963346056aa1e80b51。保存为startup-data.bin，是派生的启动初值，不是实机RAM。
26580规则：tag低3位给literal计数，0时取后字节；高4位给run计数，0时取后字节。先拷literal_count-1字节；bit3=0追加run个零，bit3=1按下一字节回距拷run+2字节（允许重叠）。到输出长度停止。两个小正常token夹具只检验重建器的典型分支，不冒充整个压缩格式形式化证明。
2c490则按4字节把BSS范围20003770..20008007清零；32B记录20003c68..20003c87和变化标记20003fc0在其中，之后Flash恢复会覆盖记录。
初始.data最后两个20B对象：
  主对象20003748 = { API=0, info=0, callback=2faad, start=74000, end=77fff }
  FDS对象2000375c = { API=0, info=0, callback=2faa5, start=0, end=0 }
该边界不是位置记录已写入的证据。主对象允许范围包含74000配置区与76000位置区；API可写不等于存在32B提交者。
在重建.data中，按4字节对齐筛选落在本应用的Thumb代码指针，只有这两个callback候选，均为上一轮工程未定义的入口。没有发现记录RAM指针嵌在该初始.data里；该结论只覆盖对齐指针和初值，不排除后续运行写入或未对齐数据。

3. 初始化、API表与完成事件闭合
29658：r0=20003748、r1=36f98、r2=0→3221c。3221c把传入API指针放入对象首字，再调用API+0。
36f98的8个word原值依次为30099、365f1、353a9、369f9、2f67d、35739、369f3、30685。已核正常使用：+0初始化30098、+8读取353a8、+c写入369f8、+10擦除2f67c、+1c忙查询30684。
30098设置flash-info=36f8c；其原word给erase_unit=1000、program_unit=4。读取353a8仅将参数的源/目的/长度转交memcpy2648c。写入369f8把fs对象、源指针、目的和长度装入28B队列项，随后启动底层；这仍是已有写入封装的内部路径，不能算新32B producer。
完成分发2f99c从queue_entry[0]找到fs对象，再取fs+8回调：事件kind1提供写入地址/长度，kind2提供擦除地址/页数，result来自传入状态。
新补原指令2faac：主对象回调只检查result和kind，然后调用现有诊断输出；成功写、成功擦、错误三类均未构造下一条队列项、未复制位置RAM、未再调用Flash写API。此处只核正常回调控制/数据流，没有展开任何日志重入或安全专项。
新补2faa4只有ldr r0,[r0,#4]和跳到350d0，属于FDS状态队列推进。主完成回调不等于FDS回调，不能把FDS内部追加状态机套在76000的32B位置记录上。

4. 计算别名与块复制候选如何排除
记录范围用半开区间[20003c68,20003c88)。候选筛选同时保留附近对象，以避免只搜完整字面量遗漏base+offset。
• 29840读取76000+index*32，按scanword选前一条，随后memcpy32到RAM或清RAM；这是恢复消费。
• 298bc读取164B配置和32B Flash记录，拼196B诊断结果；来源不是当前RAM快照。它没有追加写。
• 2b680读四个记录word恢复P；2b6a8改前16B、计算前24B CRC、更新+28并清变化标记；函数没有提交写队列。
• 20003c88处的7行表位于记录后方；长度38/3c的复制从该地址开始，不向前覆盖记录。其配置保存落到20003dc0的164B集合，不能把邻接内存当成32B record。
• 原26b38路径明确r2=1c，r1=20003ba8，r0=200046ff，是28B回复复制。高层P-code把同一合并函数其他路径的c4长度带进候选集合；不能交叉组合成“20003ba8起196B”的真实一次复制。
• 279a0的32B拷贝在两个栈区之间，来自现场组装状态，随后31e2c发送；3163a的32B来自外设初始化参数，拷到栈后交33ec0/340f4；长度同为32不能据此认定位置保存。
• 原件每字节起始的4B字面量扫描和重建.data扫描分开保存。3个未对齐的75000..77fff命中实际与普通指令字节重叠，未当作Flash指针。
目前已解码引用和常量候选中，20003fc0只有2b6f4的清零写，没有绑定到读取该标记并追加的正常消费者。此为限定检索结果，不能排除任意计算别名。
