本地处理总验收与版本覆盖
2026-11-08

1. 验收对象
本轮针对已取得的官方 MTK 固件、随包第一方组件和国行 APK，沿正常输入、数值处理、状态、输出和实际消费者追踪。
不是逐函数穷尽全部历史程序、全部第三方库或所有故障组合；也没有执行原厂程序或连接账号/设备。
FUNCTIONAL_COVERAGE.json 是功能覆盖账本；INPUT_VERSION_COVERAGE.json 将六份 subsystem BBIN 分别绑定完整原件 SHA256 和最终报告。
local-signal-closure/COVERAGE_RESIDUAL.json 中的 parallel/next 状态属于较早的分工快照，最终进展应查上述总账，不应据旧快照认定后续项目未做。

2. 本轮恢复的范围
Sensor：G0 USB 与 nonUSB 分别绑定；两份旧 Sensor 独立追采样、增益/校正、队列、批次和报文；Pillow 独立追六路 ICM、电容、方向均值、温湿度、自检与振动。
Frank：补齐 FDC/温度/范围统计和辅助磁传感数据的实际消费者；区分解析结构、按设备侧别归并、最终 CBOR 与旧字段。此前采样/时间/补点/上传模型沿用原证据。
机械：主控 pulse/landing 校准、A02 袋压闭环与20点压力标准差门控、阀泵PWM、床架位置平滑与恢复、止鼾运动同步。两版旧 Sensor 正常温控 GPIO、报警模式/PWM及普通命令另列。
Capybara：压力/电流等遥测的字段取舍、时间整理、秒分组与独立发布队列；音轨缓存、格式转换调用、WAV切片/循环和音量。
App：健康异常消费者、潮热汇总与图表、午睡状态/倒计时、Jetlag分组/时间/完成率/编辑与通知入口。服务端给出的结果或计划不冒称客户端重新推理。
Frozen、启动依赖、NATS/uploader与Frank发布前队列沿用既有限定验收，来源哈希在 carried_forward 列表。

3. 复核怎样区分证据
原件身份：文件大小和SHA256；机器码地址映射回原件，DLL与原bundle偏移对应，APK关键结论按DEX/Smali互证。
语义：关键数值分支复读汇编/IL，不能仅看反编译器伪C类型和函数名。修复分析数据库不会修改原厂输入字节。
有限模型：分析者复写的正常/边界算例；用于区分阈值、时间、量化和队列规则，不等同固件执行、算法准确率或实机事件频率。
交叉审查：已修正G0三温嵌套加权的中间值；保留放气p<0.1停止分支及严格参考气压范围；将旧报警命令范围与有效pattern表区分。对应REVIEW文件随本轮保留。
交付校验：verify_delivery.py 核对六份BBIN、最终报告和可用来源清单；外层增量包再逐文件核对SHA256和ZIP CRC。哈希相同只证明字节一致，不证明所有解释都完备。

4. 本地处理不等于取得生产生理实现
尚未取得心搏/呼吸提取、双人分离/生理融合、HRV 1.2.0、在床3.2.1、分期0.1.1与Autopilot目标生成的对应生产代码/模型。
气囊压力体动、温度加权、姿态标签消费者、枕头方向XYZ和App汇总都不能替代这些缺失实现。
从云端接口读到结果，只能确认结果交付位置，不能单靠该事实证明每一步计算的部署位置。

5. 仍未闭合的具体范围
部署/硬件：当前设备各MCU版本、生效配置、物理通道和板卡、实际采样相位/旧值/丢样率、执行器响应；需同次启动或板级材料。
现有静态材料：Keeson32字节追加记录生产者仍未完全绑定；B13内部loader/DSP和其他历史附件版本未恢复完整执行语义；全部间接调用、框架内部与复合故障未逐分支穷尽。
缺少生产材料：USB0x2B首次请求生产者、旧波形RAW writer/layout、上述生产生理模型和姿态标签生产者继续保留具体缺口。
此前共享日志缓冲专项被安全检查中止，仍未验收；本轮没有重启或用其他项目替代其完成。

验收结论：本轮列明的正常本地功能链已形成原件→指令/Smali/IL→规则→输出→报告的可追溯证据。不可将此结论改写为“本地所有代码100%逆向完成”或“用户实机已经验证”。
