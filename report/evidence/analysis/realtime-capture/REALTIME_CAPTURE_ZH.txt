2. 设备上传与 App API 不是同一条链
生产者 CBOR -> 本地 JetStream -> 按 topic 拼接 -> CBOR seq/topic/data -> batch -> 持续压缩流 -> TLS。
UPLOADER_PROTOCOL.txt 已恢复默认 raw-api-upload.8slp.net:443；运行时 /persistent/deviceinfo/endpoints.json 的 rawApiUpload 可覆盖。不能只凭默认值判断国行实机实际目标。
未恢复 HTTP POST 路径；不能把此连接当成普通 REST 接口。已追服务端响应为 session/batch ACK，不是可订阅波形的下载接口。
路由器侧被动抓包可保存连接、时序和流量信息；在没有 TLS 会话密钥或端点解密能力时，不能读取其中 CBOR。改 DNS 或设置代理不会自行解决 TLS 信任问题。未做完整证书固定/客户端证书审计。

3. 上传前本地出口
实际发布配置 nats.conf:1 为 listen:127.0.0.1:4222，:5 为 http:127.0.0.1:8222，:15 为 raw.> -> rawmem.> 映射。
因此发布默认配置不是局域网可访问服务。仍缺实机生效配置及本地执行/受控隧道访问。
获得合法本地访问后，优先旁路订阅实际映射主题并保存原始二进制载荷，后续离线解析。勿把生产 uploader 的 consumer/ACK 状态用于旁路采集；优先普通独立订阅，不修改绑定地址或清空生产流。具体主题与是否可独立订阅仍需实机确认。
上传配置 batch_timeout_secs=2、chunk_max_time_secs=2、batch_interval_ms=1024 只是批处理参数，不是传感器采样周期，也不保证端到端延迟。

4. 验证顺序与验收
A：设备恢复后，在官方 App 已有安装检测流程中观察实际 /live 请求和响应；记录状态、原始行、事件类型、timestamp、samples 长度和间隔。若复现404且与App请求一致，停止重复请求，保留服务端可用性缺口。不得因为方法名含Pod5就否定Pod6入口，亦不得推断Pod6一定输出piezo。
B：短时对照静止、翻身、轻触事件，核对哪些 samples 变化；原样保留网络事件，避免把 UI combine/timer 重放计为新样本。此步骤只能验证关联，不能单独证明物理通道映射。
C：若 /live 不提供所需数据，取得设备本地访问，读取生效配置、运行版本和主题，然后旁路保存生产者 CBOR。验收包含侧别、数组长度、时间连续性、增益元信息及缺值；原样保留载荷并以现有解析器验证。
D：仅在必须核对真实出站协议时，再研究 TLS 端点明文观察；目前未实施、不承诺可行，也不以关闭证书验证作为已完成方案。
